# build-order

> **순서를 지킨다.** 1~4단계는 전화 기능이 전혀 필요 없다.
> 가장 어려운 검증(S4)을 가장 단순한 입력(붙여넣기)으로 먼저 끝내도록 짜여 있다.

각 단계는 **"끝났다는 증거"를 눈으로 확인한 뒤에만** 다음으로 넘어간다.
요약만 읽고 넘어가지 않는다 (karpathy-principles 4번).

| 단계 | 하는 일 | 끝났다는 증거 |
|---|---|---|
| 1 | 설정 화면 + `/health` 연결 확인 | 화면에 "연결됨"이 뜬다 |
| 2 | 로그인 → 토큰 보관 | 토큰 앞 10자가 화면에 찍힌다 |
| 3 | 텍스트 입력 + 분석 + 결과 표시 | 보이스피싱 문자를 붙여넣어 **100점** (**S1**) |
| 4 | QR 표시 | ATM에 비춰 **출금이 막힌다** (**S4** — 고비) |
| 5 | 문자 공유 인텐트 | 문자 앱에서 공유해 3~4가 그대로 동작 (**S2**) |
| 6 | 통화 음성 받아쓰기 | 녹음된 대본을 **다른 기기로** 틀어 **70점 이상** (**S3**) |

**4단계까지가 이 앱의 80%다.** 5·6단계는 입력 방법을 늘리는 것뿐이다.

## 각 단계에서 읽을 것

| 단계 | 스킬 |
|---|---|
| 1~3 | `backend-api-client` |
| 4 | `qr-display-for-atm` |
| 5 | `share-intent-receiver` |
| 6 | `continuous-speech-to-text` |

## 단계마다 지키는 것

1. **그 단계의 증거를 먼저 정한다** — 무엇이 보이면 끝인가
2. 만든다 — 그 단계에 필요한 것만. 다음 단계를 위해 미리 구조를 잡지 않는다
3. **실제 기기에서 직접 확인한다** (에뮬레이터로는 4·6단계를 확인할 수 없다)
4. 증거를 확인하면 커밋한다

## 막혔을 때

| 증상 | 먼저 볼 곳 |
|---|---|
| 서버에 못 붙는다 | 설정의 서버 주소 · 백엔드가 `--host 0.0.0.0`인가 · 같은 무선망인가 |
| 401이 난다 | 토큰 만료(12시간) — 다시 로그인 |
| 한글이 깨져서 0점이 나온다 | 요청 헤더의 `charset=utf-8` |
| QR을 ATM이 못 읽는다 | **화면 밝기** → 거리 → QR 크기 순 |
| 받아쓰기가 첫 문장에서 멈춘다 | `onResults`에서 재시작을 부르는가 |
| 받아쓰기가 **아무것도 안 잡는다** | 그 폰에 **통화가 걸려 있지 않은가**(무음이 된다) · 매니페스트에 `<queries>`가 있는가 |
| 오류 메시지가 늘 "서버가 요청을 거부했습니다"뿐이다 | 실패 응답에서 `detail`을 찾고 있다. **`error`**를 읽는다 |
