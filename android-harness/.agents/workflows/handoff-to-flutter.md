# handoff-to-flutter

> **이 앱의 최종 산출물은 APK가 아니라 이 인수인계 문서다.**
> 앱은 확인하면 역할이 끝나지만, 여기서 알아낸 것은 Flutter 앱까지 간다.

## 언제 쓰나

`verify-against-prd`의 체크리스트가 전부 통과한 뒤.

## 넘길 것 다섯 가지

### 1. 검증된 API 계약

`.agents/rules/api-contract-rules.md`에 **실제로 주고받은 요청·응답을 붙여
넣는다.** 문서에 적힌 예시가 아니라 진짜 값이어야 한다.

### 2. QR 인식이 잘 되는 조건 (실측값)

| 항목 | 우리 기기에서 측정한 값 |
|---|---|
| 화면 밝기 | (예: 최대일 때만 안정적) |
| 카메라와의 거리 | (예: 20~30cm) |
| QR 크기 | (예: 화면 폭의 70%) |
| 잘 안 되는 조건 | (예: 형광등 바로 아래에서 반사될 때) |

**이 표가 Flutter 담당 학생의 시간을 가장 많이 아껴 준다.**

### 3. 받아쓰기 재시작 처리

`onResults`/`onError`에서 다시 시작해야 한다는 것, 지연을 줘야 한다는 것,
`listening` 플래그를 먼저 내려야 한다는 것. Flutter의 `speech_to_text`에도
같은 문제가 있으므로 **증상과 해결을 함께** 적는다.

### 4. 전시장에서 걸렸던 것들

실제로 겪은 것만 적는다. 추측은 쓰지 않는다.
- 서버 IP가 바뀐 횟수와 그때 무엇을 했는지
- 무선 지연이 얼마였는지
- 조명 때문에 QR이 안 읽힌 적이 있는지

### 5. 시연 대본과 점수

`verify-against-prd`의 대본에, **실제로 나온 점수를 적어서** 넘긴다.

## Flutter 대응 패키지

| 안드로이드 | Flutter |
|---|---|
| `HttpURLConnection` | `http` |
| ZXing | `qr_flutter` |
| `SpeechRecognizer` | `speech_to_text` |
| 공유 인텐트 | `receive_sharing_intent` |

**구조는 같고 이름만 다르다.** 이 앱에서 확인한 순서(build-order)를 그대로
따라가면 된다.
