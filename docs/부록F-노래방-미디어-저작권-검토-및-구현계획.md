## 1. 왜 다운로드는 안 되는가

내려받기 한 번에 **두 가지 문제**가 동시에 생깁니다.

### 1-1. 유튜브 서비스 약관 위반 (구글과의 계약 문제)

유튜브 서비스 약관의 "허용되지 않는 사항(Permissions and Restrictions)" 조항은
**서비스가 제공하는 기능(예: YouTube Premium 오프라인 저장)이나 유튜브의 사전 서면 허가
없이 콘텐츠를 다운로드하는 행위**를 금지합니다. `yt-dlp`, "유튜브 mp3 변환" 사이트 등
제3자 도구를 쓰는 것이 여기에 해당합니다.

이건 저작권 문제와 **별개**입니다. 설령 저작권법상 예외에 해당하더라도, 구글과 맺은
이용계약 위반은 그대로 남습니다.

### 1-2. 저작권법상 복제권 침해

내려받아 파일로 저장하는 행위 = **복제**(저작권법 제2조 제22호, 제16조 복제권).

노래방 영상 하나에는 권리가 **여러 겹**으로 쌓여 있습니다.

| 권리 | 권리자 | 비고 |
|------|--------|------|
| 음악저작물 (작사·작곡) | 작사가·작곡가 (대개 한국음악저작권협회 등에 신탁) | |
| 노래방 반주 음원 | TJ미디어·금영 등 제작사 | 별도의 저작인접권 |
| 영상저작물 (자막·배경영상) | 영상을 만들어 올린 채널 | 편집저작물 |

**"사적이용을 위한 복제"(제30조)로 되지 않나?** → 안 됩니다.
제30조는 *"개인적으로 이용하거나 가정 및 이에 준하는 한정된 범위 안에서 이용"*하는
경우에만 적용됩니다. 학교 노래방 부스와 전시회는 불특정 다수가 이용하는 공간이라
"가정에 준하는 한정된 범위"로 볼 수 없습니다.

## 2. 학교라서 봐주는 예외는 없나 — 저작권법 제25조

**저작권법 제25조(학교교육 목적 등에의 이용)** 에 따라 고등학교 이하 학교는
수업 목적상 필요한 범위에서 공표된 저작물의 일부분을 보상금 없이 복제·배포·공연·전송할
수 있습니다. 언뜻 우리 상황에 딱 맞아 보이지만, **세 가지 이유로 이번 프로젝트에는
기대기 어렵습니다.**

1. **"수업"의 범위 문제.** 제25조가 말하는 수업은 정규 교육과정의 수업 활동입니다.
   전시회 관람객이 자유롭게 이용하는 상설 노래방 부스는 수업이라고 보기 어렵습니다.
2. **부수 의무가 붙습니다.** 접근제한조치·복제방지조치·저작권 보호 경고문구 표시·
   출처 표시 의무(제25조 및 시행령)가 따라옵니다. 공개 전시 환경에서 이걸 지키기 어렵습니다.
3. **유튜브 약관 위반은 치유되지 않습니다.** 1-1의 문제는 저작권법 예외와 무관하게 남습니다.

> 📌 결론: 제25조는 "수업 시간에 선생님이 자료로 잠깐 트는 것"에는 도움이 되지만,
> **전시회용 상설 부스에 파일을 저장해 두는 근거로는 쓸 수 없습니다.**

## 3. 그럼 노래를 트는 것(공연) 자체는? — 저작권법 제29조

**제29조 제2항**은 *청중·관중으로부터 해당 공연에 대한 반대급부를 받지 않는 경우*,
상업용 음반 또는 상업적 목적으로 공표된 영상저작물을 **재생하여 공중에게 공연**할 수
있도록 하고 있습니다. 다만 시행령 제11조가 열거한 장소(대형마트, 카페, 단란주점,
숙박업소 등 영업 공간)는 제외됩니다.

**학교는 시행령 제11조의 제외 목록에 들어 있지 않습니다.** 따라서 입장료·참가비를
받지 않는 교내 전시회에서 음악을 재생하는 행위 자체는 이 조항의 범위로 볼 여지가 큽니다.

⚠️ 단, 두 가지를 구분해야 합니다.

- 제29조가 허용하는 것은 **"재생(공연)"** 입니다.
- **"복제(다운로드)"** 는 허용하지 않습니다.

즉 *"틀어도 되니까 받아 놔도 되겠지"* 는 성립하지 않습니다.
또한 유튜브 영상은 전형적인 "상업용 음반"이 아닌 온라인 영상저작물이라 제29조 적용에
해석의 여지가 있으므로, 스트리밍으로 정상 재생하는 편이 훨씬 안전합니다.

## 4. ✅ 우리가 채택한 합법 경로 4가지

우선순위대로, 앱이 자동으로 이 순서로 재생 소스를 고릅니다.

### ① 유튜브 공식 임베드 플레이어 (기본값 · 무료 · 권장)

영상을 **우리 서버에 복제하지 않고**, 유튜브가 자기 플레이어로 직접 스트리밍합니다.
광고가 노출되고 조회수가 집계되어 **저작권자에게 수익이 정상적으로 돌아가는** 경로이며,
유튜브가 임베드 기능을 공식 제공하는 이상 약관이 예정한 사용 방식입니다.

- 구현: `frontend/utils/youtubePlayer.ts` (IFrame Player API)
- 임베드를 막아 둔 영상은 재생되지 않으므로, 앱이 자동 감지해 다른 영상으로 다시 등록받습니다.
- 영상 소유자가 임베드를 허용한 영상만 사용합니다 (`videoEmbeddable=true`).

### ② 학교가 정식 구매·구독한 반주 음원 (`school-licensed`)

TJ미디어·금영 등의 공식 노래방 서비스나 유료 MR 판매처에서 구매한 파일.
전시회장 Wi-Fi가 불안정할 때를 대비한 **가장 확실한 방법**이며, 음질도 가장 좋습니다.

- 파일 위치: `frontend/public/media/karaoke/<곡id>.mp3`
- 구매 내역은 `LICENSE-LEDGER.md`에 반드시 기록 (저작권 문의 시 즉시 제시)

### ③ 학생이 직접 만든 반주 (`self-produced`)

밴드부 연주 녹음, DAW/MIDI로 직접 편곡한 MR.
**저작권이 우리 학교에 있으므로 100% 안전**하고, 전시회에서 "이 반주는 저희가 직접
만들었습니다"라고 말할 수 있는 **작품성 가산점 요소**이기도 합니다.

> 다만 남의 곡을 편곡해 연주한 것은 원곡 작곡가의 2차적저작물작성권이 걸립니다.
> 완전히 안전하게 가려면 창작곡이나 저작권 만료곡(교가, 민요 등)을 쓰세요.

### ④ CC 라이선스 / 퍼블릭 도메인 음원 (`cc-or-public-domain`)

CC BY, CC0 음원 및 저작권 보호기간이 끝난 곡. 출처 표시 조건을 지키면 무료로 쓸 수 있습니다.

### ⑤ (폴백) 내장 자동 반주 — `synth-fallback`

위 어느 것도 준비되지 않았을 때 앱이 실시간으로 합성하는 반주입니다.
**원곡의 채보가 아니라** 장르·템포에 맞는 일반적인 코드 진행(I-V-vi-IV 등 대중적으로
널리 쓰이는 진행 템플릿)으로 연주하므로 저작권 문제가 없습니다.
인터넷이 끊겨도 부스가 멈추지 않게 하는 안전장치입니다.

## 5. ❌ 하면 안 되는 것 체크리스트

전시 준비 중 실수하기 쉬운 것들입니다. 팀원 모두 확인하세요.

- [ ] `yt-dlp`, "유튜브 mp3 변환" 사이트로 영상·음원을 내려받지 않았다
- [ ] 노래방 기기 출력을 녹음해서 MR 파일로 만들지 않았다
- [ ] 멜론·지니 등에서 받은 원곡 MP3를 부스에 넣지 않았다
- [ ] 가사 전문을 텍스트로 복사해 코드/DB에 넣지 않았다 *(가사도 저작물입니다)*
- [ ] `public/media/karaoke/`의 음원·영상 파일을 GitHub에 커밋하지 않았다
- [ ] 전시회 입장료·참가비를 받지 않는다 *(받으면 제29조 적용이 어려워집니다)*

> 💡 **가사를 코드에 넣지 않은 이유**
> 이전 버전은 곡마다 가사 6줄을 소스코드에 넣어 두었습니다. 가사는 어문저작물이라
> 저장소에 복제해 공개 배포하면 그 자체가 침해가 될 수 있습니다.
> 이번 구현은 **가사를 노래방 영상이 직접 표시하게** 하고, 코드에는 저작권과 무관한
> `guideCues`(구간 안내: "후렴 시작", "하이라이트 고음 구간" 등)만 남겼습니다.

## 6. 전시회 당일 준비 절차

1. **1주 전** — 곡별 유튜브 노래방 영상을 등록하고 **한 곡씩 실제로 재생 확인**
   (앱 화면의 [등록] 또는 `scripts/resolve-karaoke-videos.mjs`)
2. **3일 전** — 전시회장과 같은 네트워크에서 재생 테스트.
   Wi-Fi가 불안정하면 ②(구매 반주)나 ③(자작 반주)을 `media/` 폴더에 준비
3. **전날** — `LICENSE-LEDGER.md`를 출력해 부스에 비치
4. **당일** — 부스 안내판에 다음 문구 게시

   > 본 부스의 노래방 영상은 파일로 저장하지 않고 유튜브 공식 플레이어로
   > 스트리밍하여 재생합니다. 반주 음원은 학교가 정식으로 확보했거나
   > 학생이 직접 제작한 것만 사용합니다.

   *(앱 화면 하단에도 현재 재생 근거가 항상 한 줄로 표시됩니다.)*

### 7-2. 유튜브 영상 표시 오류 수정

**원인 3가지를 모두 고쳤습니다.**

| 이전 문제 | 원인 | 수정 |
|-----------|------|------|
| "동영상을 재생할 수 없음"만 뜨고 앱은 아무것도 못 함 | `<iframe src>`를 직접 박아서 오류를 감지할 방법이 없었음 | IFrame Player API로 교체 → `onError`로 오류 코드 수신 |
| 임베드가 막힌 영상이면 화면이 그냥 검게 남음 | 폴백 경로 없음 | 오류 감지 시 자동으로 내장 반주 전환 + 다른 영상 등록 안내 |
| 영상 ID가 틀려도 알 수 없음 | 소스코드에 검증 안 된 ID가 하드코딩돼 있었음 | 곡마다 **후보 영상을 2~3개** 두고, 재생에 실패하면 **자동으로 다음 후보**로 넘어감 |
| 등록한 영상이 그 브라우저에서만 보임 | `localStorage`에 저장했음 | **서버에 저장**해 부스 화면·관람객 폰·관리자 노트북이 같은 영상을 봄 (`song_videos` 테이블) |
| 브라우저가 재생을 막음 | 마이크 권한 창이 뜨는 사이 사용자 제스처가 소실됨 | **입장 게이트**에서 권한과 주변 소음 측정을 먼저 끝내고, [반주 시작]은 재생만 함 |
| 곡이 끝나도 점수 화면이 안 뜸 | 유튜브 `ENDED` 이벤트 하나에만 의존 | 재생 위치로도 종료를 판정하는 **이중 감지** (중복 채점은 Guard가 차단) |
| 브라우저가 플레이어 통신을 차단 | `origin` 파라미터 누락 | `origin: window.location.origin` 전달 |

또한 **유튜브 영상과 내장 반주가 동시에 울리던 소리 겹침**도 고쳤습니다
(재생 소스는 항상 하나만 활성화됩니다).

### 7-3. 반주 음질 개선

"음질이 조잡하다"의 원인은 내장 신스 반주였습니다. 네 가지를 고쳤습니다.

| 문제 | 수정 |
|------|------|
| `setInterval`로 박자를 만들어 타이머 지터가 그대로 박자 흔들림이 됨 | **lookahead 스케줄러**로 교체 — 오디오 클럭 기준으로 100ms 앞을 미리 예약 |
| 오실레이터를 필터·엔벨로프 없이 그대로 연결해 "삐-" 하는 전자음 | **ADSR 엔벨로프 + 로우패스 필터 + 디튠 2중 레이어** |
| 공간감이 전혀 없음 | **피드백 딜레이 기반 리버브 센드** 추가 |
| 모든 파트가 같은 세기로 울려 뭉갬 | **파트별 버스 + 킥 사이드체인 덕킹 + 마스터 컴프레서** |

> 다만 **가장 확실한 음질 개선은 ①번(유튜브 임베드)이나 ②번(구매 반주)** 입니다.
> 내장 신스는 어디까지나 인터넷이 끊겼을 때의 안전장치입니다.

### 7-4. 노래 종료 시 점수 자동 표시

- **자동 종료 감지**: 유튜브 영상이 끝나거나(`ENDED`) 반주 파일 재생이 끝나면
  버튼을 누르지 않아도 자동으로 채점 화면이 뜹니다.
- **점수 산정 방식 개선**: 이전에는 성량과 난수만으로 계산해 **노래를 부르지 않아도
  83~99점**이 나왔습니다. 이제 4개 항목으로 나누어 계산하고, 학생에게 항목별 점수를
  함께 보여 줍니다.

  | 항목 | 배점 | 측정 방법 |
  |------|------|-----------|
  | 음정 | 35 | 반음 기준 평균 이탈량(cents) — 자기상관 + 포물선 보간으로 검출 |
  | 박자·지속성 | 30 | 반주가 흐르는 동안 실제로 소리를 낸 시간 비율 |
  | 성량 | 20 | 발성 구간의 평균 RMS 볼륨 |
  | 표현력 | 15 | 사용한 음역 폭 + 비브라토(피치 방향 전환 빈도) |

- 마이크로 아무 소리도 들어오지 않으면 점수를 지어내지 않고
  **"마이크 연결을 확인해 주세요"** 라고 사실대로 안내합니다.
- 화면 하단에 **실시간 음정 정확도 게이지**가 표시됩니다 (가운데에 가까울수록 정확).

## 9. 문제 해결 — "영상이 하나도 재생되지 않아요"

### 9-1. 먼저 원인을 눈으로 확인한다

곡을 눌렀는데 `유튜브 영상을 모두 재생할 수 없어 내장 자동 반주로 전환했습니다`가 뜨면,
**그 화면(영상 등록 화면) 안에 `재생하지 못한 영상 N개` 목록**이 함께 표시된다.

```
재생하지 못한 영상 3개 (직접 열어서 확인해 보세요)
  CP2tLzx79vM   코드 150 · 영상은 있지만 퍼가기(임베드) 금지
  XrTISKbGa2U   코드 150 · 영상은 있지만 퍼가기(임베드) 금지
  FYKuwoJzz1U   코드 100 · 삭제되었거나 비공개
```

같은 내용이 크롬 개발자도구(F12) → Console 탭에도 남는다.

```
[노래방] 재생 실패 — 곡=gomin-jungdok 영상=CP2tLzx79vM 코드=150 (영상 소유자가 …)
```

### 9-2. 코드별 뜻과 대처

| 코드 | 뜻 | 대처 |
|---|---|---|
| **101 / 150** | 영상은 정상이지만 **영상 주인이 외부 사이트 재생(퍼가기)을 막아 둠** | 다른 노래방 영상을 찾아 등록한다. 공식 노래방 채널(TJ·금영)과 대형 기획사 뮤직비디오는 퍼가기를 막아 둔 경우가 많다 |
| **100** | 영상이 삭제되었거나 비공개로 바뀜 | 다른 영상을 찾아 등록한다 |
| **2** | 영상 ID 형식이 잘못됨 | `karaokeSongs.ts`의 후보 ID 오타를 고친다 |
| **5** | 브라우저가 재생할 수 없음 | 크롬 최신 버전에서 다시 시도한다 |

> **101·150이 대부분이면 코드 문제가 아니다.** 우리 쪽 재생 코드는 정상이고,
> 고른 영상이 퍼가기 금지 영상일 뿐이다.

### 9-3. 퍼가기 되는 영상을 고르는 법

1. 유튜브에서 `<곡명> 노래방` 또는 `<곡명> MR 가사`로 검색한다.
2. 영상 아래 **[공유] → [퍼가기]** 버튼이 **보이는지** 확인한다.
   - 버튼이 있으면 → 우리 화면에서 재생된다.
   - 버튼이 없거나 회색이면 → 재생되지 않는다. 다음 영상을 본다.
3. 되는 영상을 찾으면 주소창 링크를 복사해, 노래방 화면의
   **"유튜브 링크를 붙여넣으세요"** 칸에 붙여넣고 [등록]을 누른다.
   (관리자 인증이 필요하며, 등록 결과는 서버에 저장돼 모든 기기에 적용된다)

### 9-4. 전시회를 앞두고 있다면

전시장 Wi-Fi는 끊기기 쉽고, 유튜브가 차단된 망일 수도 있다.
**§4-② / §4-③ 경로로 확보한 반주 파일을 `frontend/public/media/karaoke/`에 넣어 두는 것**이
가장 확실하다. 로컬 파일이 있으면 유튜브보다 먼저 재생된다.

### 9-5. 콘솔의 이 두 줄은 오류가 아니다

```
www-widgetapi.js:163 Failed to execute 'postMessage' on 'DOMWindow':
  The target origin provided ('https://www.youtube.com') does not match
  the recipient window's origin ('http://localhost:3000').
base.js:5430 [Violation] Permissions policy violation: compute-pressure is not allowed in this document.
```

둘 다 **유튜브가 제공하는 스크립트가 스스로 찍는 경고**다.
첫 줄은 유튜브 위젯이 iframe이 다 열리기 전에 말을 걸어서 나는 것이고,
둘째 줄은 유튜브 플레이어가 브라우저 성능 API를 요청했다가 거절당해서 나는 것이다.
우리 코드가 고칠 수 있는 대상이 아니며, 재생 여부와도 관계없다.
**재생이 되는지 안 되는지는 위 §9-1의 `[노래방] 재생 실패` 로그로 판단한다.**
