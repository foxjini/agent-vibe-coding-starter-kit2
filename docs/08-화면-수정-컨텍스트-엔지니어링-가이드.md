# 화면 수정 가이드 — 채팅형 AI와 컨텍스트 엔지니어링 (학생용)

> **대상:** 프론트엔드(화면) 담당 · **준비물:** `npm install`이 끝난 `frontend/`, 학교에서 허용한 채팅형 AI 계정
> **짝 문서:** 무엇을 어떻게 디자인할지는 [06 UI/UX 디자인 교재](06-프론트엔드-UI-UX-디자인-교재.md),
> 기능(시나리오)은 [00 통합 매뉴얼](00-2차개발-통합-매뉴얼.md) 5장.
> **프론트엔드 담당은 이 문서의 "시작하기 전에"부터 읽으세요.** 무엇을 어떤 순서로 하고 어느 문서를 펼치는지가 거기 있습니다.

## 시작하기 전에 — 프론트엔드 담당이 하는 일

### A. 내가 맡은 일과 펼칠 문서

설치와 첫 연동은 끝났습니다. 이제 **우리 팀 주제에 맞는 화면**을 만듭니다. 일은 두 가지입니다.

| 일 | 무엇 | 펼칠 문서 |
|---|---|---|
| **동작** (시나리오) | 버튼을 누르면 무엇이 켜지고, 언제 알림이 뜨고, 미션은 어떻게 판정하나 | [00 매뉴얼](00-2차개발-통합-매뉴얼.md) **5장** + 이 문서 |
| **디자인** (UI/UX) | 색·글꼴·배치·반응형·접근성 | [06 교재](06-프론트엔드-UI-UX-디자인-교재.md) + 이 문서 |
| (둘 다) AI와 코드를 주고받는 방법 | 묶기 → 요청 → 넣기 → 확인 | **이 문서 0~9장** |
| (둘 다) 라즈베리파이 담당과 맞추기 · 파이 없이 시험 · git | 팀 안에서 같이 일하는 방법 | **이 문서 10~12장** |

> **순서가 중요합니다 — 동작 먼저, 디자인은 나중.** 디자인부터 하면 동작을 넣을 때 다시 고치게 됩니다.
> 단, 06의 **6장(스타일 고르기)은 팀이 일찍 한 번** 같이 봅니다.

### B. 혼자 진행하는 순서 — 6단계

한 단계를 끝내고 **성공 기준을 눈으로 확인한 다음** 넘어갑니다.

| 단계 | 할 일 | 볼 곳 | ✓ 성공 기준 |
|---|---|---|---|
| 1 | 지금 화면 셋을 열어 보고 구조 익히기 | 00 매뉴얼 2-6 · 5-0, 이 문서 C | `/` · `/kit` · 본보기(`/wakeup` 등)가 열리고, `/`에 우리 팀 부품 카드가 보인다 |
| 2 | 화면 설계 + **라즈베리파이 담당과 슬롯 약속** | 06 교재 5장, 이 문서 **10장** | 약속표(10-2)를 둘이 같이 채웠다. "누가 · 어디서 · 무엇을 3초 안에 보나"가 한 줄로 적혀 있다 |
| 3 | 팀 이름 바꾸기 + 디자인 스타일 고르기 | 00 매뉴얼 2-6, 06 교재 6장 | `/` 머리말이 우리 팀 이름이다. 팀이 고른 스타일이 06의 6-6 표에 적혀 있다 |
| 4 | **시나리오(동작) 만들기** | 00 매뉴얼 5장, 이 문서 D · 4~6장 · **11장** | 파이가 없어도 **가짜 센서 입력(11장)으로 시나리오가 처음부터 끝까지** 돈다 |
| 5 | 디자인 다듬기 — 한 요청에 하나씩 | 06 교재 7~15장, 이 문서 2~7장 | 요청 하나를 넣을 때마다 이 문서 **6장의 확인표**를 통과한다 |
| 6 | 실제 부품으로 팀 통합 시험, 제출 점검 | 이 문서 10-4, 06 교재 18장 | 실제 버튼·센서로 시나리오가 돌고, 06의 제출 전 체크리스트를 통과한다 |

### C. 기초 개념 — 이것만 알면 코드와 묶음 파일을 읽을 수 있습니다

| 말 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| **폴더 = 주소** | Next.js는 `app/` 아래 폴더 이름이 화면 주소가 됩니다 | `app/page.tsx` → `/`, `app/wakeup/page.tsx` → `/wakeup` |
| **컴포넌트** | 화면 조각 하나를 그리는 함수. 이름이 대문자로 시작하고 `<이름 />`처럼 씁니다 | `<SlotGrid … />`, 우리 팀 것은 `components/team/` 에 새 파일로 |
| **props** | 컴포넌트에 넘기는 값 (함수의 매개변수와 같음) | `<SlotGrid slots={slots} onControl={setActuator} />`에서 `slots`, `onControl` |
| **state** (`useState`) | 바뀌면 화면이 다시 그려지는 값 | 미션 단계, 남은 시간, 열린 팝업 |
| **`useEffect`** | 화면이 뜬 뒤에 할 일 — 구독 등록·타이머. 정리 함수로 해지합니다 | `useEffect(() => onSensor("sensor_01", …), [onSensor])` |
| **`useScenario()`** | 키트가 주는 SDK. 슬롯 상태, 부품 켜기, 센서·카메라 구독, 알림 | 00 매뉴얼 5-2. 한 화면에서 **한 번만** 부릅니다 |
| **`className`** | 모양을 정하는 Tailwind 클래스 목록 | `className="rounded-xl bg-white p-5"` — 둥근 모서리·흰 배경·안쪽 여백 |
| **`"use client"`** | 파일 맨 위에 두면 브라우저에서 도는 화면이 됩니다 | 버튼·state를 쓰는 화면에는 꼭 있습니다 |
| **개발 서버** | `npm run dev` — 파일을 저장하면 브라우저가 **저절로** 바뀝니다 | 바뀌지 않으면 터미널과 F12 콘솔에 오류가 있는 것 |
| **F12 개발자 도구** | Console = 오류, Elements = 지금 화면의 구조, 기기 모양 아이콘 = 폰 크기로 보기 | 오류가 나면 **빨간 줄을 그대로 복사**해 AI에게 |

> 코드를 다 이해하지 못해도 괜찮습니다. 다만 **AI가 준 코드를 넣은 뒤 "어디가 바뀌었는지"는**
> 5-2의 미리 보기로 꼭 읽고, 모르는 줄이 있으면 AI에게 "이 줄이 무슨 뜻이야?"라고 물어보세요.

### D. 어느 도구를 쓰나 — 화면인가, 동작인가

| 하려는 일 | 만드는 파일 | 명령 |
|---|---|---|
| **화면**(배치·색·카드 추가·반응형)을 고친다 | 화면 묶음 `context_packs/ui_home.md` | `python tools/merge_ui.py` (다른 화면이면 `--page wakeup` 처럼) |
| **새 시나리오**(동작)를 만든다 — classroom · subway 팀 | 컨텍스트 팩 `context_packs/context_pack_frontend.md` | `python tools/context_pack.py frontend` (00 매뉴얼 8장) |
| **이미 있는 우리 팀 시나리오**를 고친다 — wakeup · study 팀 | 화면 묶음에 시나리오 파일을 **전문으로 추가** | 아래 예 |

```bash
# wakeup 팀: 기상 화면 + 시나리오 파일 두 개를 전문으로 담기
python tools/merge_ui.py --page wakeup --add scenarios/useWakeup.ts --add scenarios/wakeupEngine.ts
# study 팀
python tools/merge_ui.py --page study --add scenarios/useStudy.ts --add scenarios/studyEngine.ts
```

> ⚠️ **왜 이렇게 나누나요?** 컨텍스트 팩은 wakeup 시나리오를 '다른 팀 본보기'로 보고 **요약만** 담습니다.
> 그래서 wakeup 팀이 자기 시나리오를 고칠 때는 화면 묶음에 `--add`로 넣어야 AI가 전문을 봅니다.
> 화면 묶음 2장에는 "`scenarios/`는 화면 작업에서 고치지 않는다"고 적혀 있으니, 요청의 **[바꿀 곳]에
> "이번에는 scenarios/useWakeup.ts도 고친다"고 분명히** 적으세요. `apply_ui.py`는 `scenarios/` 파일도 적용합니다.
> 이렇게 묶으면 파일이 커집니다(wakeup 약 96KB, study 약 65KB). 붙여넣기보다 **파일 올리기**로 올리세요.
>
> 💡 classroom · subway 팀의 컨텍스트 팩에 **study 팀 파일이 '고치는 파일'로** 들어 있다면, 그것은 우리 것이 아닙니다.
> 요청에 "study 파일은 참고만 해"라고 적거나, 00 매뉴얼 5-0대로 다른 팀 본보기 파일을 지우고 팩을 다시 만드세요.

**동작(시나리오) 요청 틀** — 4-2의 틀과 같고, [완료 기준]을 **11장의 가짜 입력으로 확인할 수 있게** 씁니다.

```text

[바꿀 곳] 새 파일 frontend/scenarios/congestionEngine.ts(판정, React 없이), frontend/scenarios/useCongestion.ts(진행),

[완료 기준] 가짜 입력으로 sensor_01에 {"value": 35}를 보내고 10초 기다리면 LED 명령이 level 3으로 나가고 경고가 뜬다.
           {"value": 5}를 보내면 경고가 사라진다. 판정 함수 테스트 파일도 있다.
[진행] 먼저 계획만 3~5줄로 보여 줘.
```

## 0. 왜 이 방법인가

우리 학생들은 만 18세 미만이라 **AI 에이전트 도구**(AI가 폴더를 직접 읽고 고치는 도구)를 쓰지 않습니다.
채팅창에 묻는 **채팅형 생성형 AI**만 씁니다.

채팅형 AI는 우리 폴더를 볼 수 없습니다. 아무것도 보여 주지 않고 "화면 고쳐 줘"라고 하면
그럴듯하지만 **우리 프로젝트에는 맞지 않는 코드**가 옵니다 —
Tailwind v3 방식이라 색이 안 바뀌고, 없는 파일을 import하고, 4팀 공통 파일을 고칩니다.

그래서 **AI가 볼 자료를 우리가 설계해서** 보여 줍니다. 이것이 **컨텍스트 엔지니어링**입니다.

| | 프롬프트 엔지니어링 | 컨텍스트 엔지니어링 |
|---|---|---|
| 무엇을 다듬나 | 질문 문장 | AI가 보는 **자료 전체** (규칙 · 지금 코드 · 답 형식 + 질문) |
| 우리 도구 | 요청 틀 (4장) | `tools/merge_ui.py`가 만드는 **묶음 파일** |

AI가 좋은 답을 내려면 네 가지가 필요합니다.

| | 무엇 | 누가 넣나 |
|---|---|---|
| ① 규칙 | 고치면 안 되는 파일, Tailwind v4, React 19 규칙 | 묶음 파일에 **자동으로** |
| ② 사실 | 지금 코드 — 고칠 파일은 전문, 쓰는 부품은 사용법 | 묶음 파일에 **자동으로** |
| ③ 목표 | 무엇을 바꾸고, 언제 끝난 것인가 | ✍️ **학생이 씁니다** |
| ④ 답 형식 | 내가 받아서 그대로 넣을 수 있는 모양 | 묶음 파일에 **자동으로** |

**학생은 ③만 잘 쓰면 됩니다.** 나머지는 도구가 빠짐없이 넣어 줍니다.

## 1. 한눈에 보는 순서

```
 ① 정하기      ② 묶기             ③ 요청하기     ④ 넣기              ⑤ 확인하기
 한 번에 하나  merge_ui.py        채팅창에 올림   apply_ui.py         eslint · build · 브라우저
      ↑                                                                    │
      └──────────────── 다음 요청은 반드시 ② 묶기부터 다시 ────────────────┘
```

명령은 모두 **저장소 최상위 폴더**에서 실행합니다 (PowerShell · 터미널 똑같습니다).

| 단계 | 명령 |
|---|---|
| ② 묶기 | `python tools/merge_ui.py` (다른 화면이면 `--page study`) |
| ④ 미리 보기 | `python tools/apply_ui.py` |
| ④ 적용 | `python tools/apply_ui.py --write` |
| ④ 되돌리기 | `python tools/apply_ui.py --undo` |
| ⑤ 확인 | `cd frontend` → `npx eslint .` → `npx next build` → `npm run dev` |

## 3. ② 화면 파일 묶기 — `merge_ui.py`

```bash

python tools/merge_ui.py --list          # 묶지 않고, 무엇이 들어갈지만 보기
```

`context_packs/`는 git에 올라가지 않습니다.

### 묶음 파일 안에 든 것

도구는 고른 화면 파일에서 시작해 그 화면이 **실제로 import하는 파일**을 따라가며 담습니다.

| 장 | 내용 | 어떻게 만들어지나 |
|---|---|---|
| 1 | AI에게 — 역할, "이 파일에 없는 것은 추측하지 마라", 답하는 순서 | 고정 문구 |
| 2 | 지켜야 할 제약 — 고치는 곳 / 고치지 않는 곳 | 고정 문구 |
| 3 | 이 프로젝트의 사실 — Next.js 16 · Tailwind v4 · React 19 린트 규칙 | 고정 문구 |
| 4 | 설치된 패키지 | `package.json`에서 읽음 |
| 5 | 화면 지도 · 이 화면이 가져다 쓰는 것 · 담긴 파일 목록 | 폴더와 import에서 읽음 |
| 6 | 지금 쓸 수 있는 디자인 토큰 → 클래스 이름 | `globals.css`의 `@theme`에서 읽음 |
| 7 | **고치는 파일 — 전문** (화면, `components/team/`, `globals.css`, `layout.tsx`) | 파일 그대로 |
| 8 | **참고 — 쓰는 법만** (키트 카드, `lib/`, 팀 로직): 타입은 전문, 함수는 이름과 props | 구현을 빼고 자동 요약 |
| 9 | 답변 형식 — 바꾸는 파일마다 코드블록 하나, 첫 줄은 `// 파일: frontend/…` | 고정 문구 |

> 🔒 `.env.local`은 **어떤 경우에도 들어가지 않습니다** (`--add`로 넣으려 해도 거부합니다).
> 코드에 키처럼 보이는 문자열이 있으면 지우고 경고합니다. 그래도 올리기 전에 묶음 파일에서
> `KEY` · `PASSWORD`를 한 번 검색(Ctrl+F)해 보세요.

> 📸 **묶음 파일은 만든 순간의 사진입니다.** 코드를 고친 뒤 다음 요청을 할 때는
> **반드시 다시 묶으세요.** 옛 묶음을 올리면 AI가 이미 고친 코드를 모르고 되돌려 놓습니다.

## 4. ③ AI에게 올리고 요청하기

### 4-1. 올리기

1. 채팅형 AI에서 **새 대화**를 엽니다.
2. `context_packs/ui_home.md`를 **파일로 올립니다.**
   파일을 올릴 수 없으면 내용을 전부 복사해 붙여넣습니다.
3. 같은 메시지에 아래 4-2의 틀로 요청을 씁니다.

> 요청 없이 파일만 올리면 AI는 "화면 구성 3줄 요약 + 무엇을 바꿀까요?"로 답하도록
> 묶음 파일에 적혀 있습니다. 요약이 맞는지 보면 **AI가 파일을 제대로 읽었는지** 알 수 있습니다.

### 4-2. 요청 틀 — 이 다섯 칸만 채우세요

```text
[목표] (무엇을 왜 바꾸나 — 한두 문장. 누가 · 어디서 · 몇 m 떨어져서 보는지)
[바꿀 곳] (파일 이름. 새 파일이면 frontend/components/team/○○.tsx)
[바꾸지 말 것] (동작·데이터, 다른 카드 등 — 묶음 2장 말고 더 지킬 것이 있으면)
[완료 기준] (화면에서 무엇이 보이면 끝인가 — 눈으로 확인할 수 있게)
[진행] 먼저 계획만 3~5줄로 보여 줘. 내가 좋다고 하면 코드를 줘.
```

**[완료 기준]이 가장 중요합니다.** "예쁘게"는 확인할 수 없지만
"폰 폭(375px)에서 가로 스크롤이 없다"는 확인할 수 있습니다.

### 4-3. 요청 예시

**① 새 카드 추가** — 이 가이드를 만들 때 실제로 해 본 요청입니다.
```text
[목표] 교실 뒤(3m)에서도 3초 안에 상태가 읽히게, 헤더 아래에 '지금 상태' 줄을 넣고 싶어.
       실시간 연결 여부, 켜져 있는 장치 수, 센서 수.
[바꿀 곳] frontend/app/page.tsx, 새 파일 frontend/components/team/StatusStrip.tsx
[바꾸지 말 것] SlotGrid 줄, 알림 목록
[완료 기준] 숫자가 화면에서 가장 크다. 연결이 끊기면 색이 바뀐다. 폰 폭에서는 한 줄에 하나씩 쌓인다.
[진행] 먼저 계획만 보여 줘.
```

**② 디자인 토큰으로 바꾸기** (06 교재 7장을 고른 다음)
```text
[목표] 우리 팀은 'soft' 스타일로 정했어. 06 교재 7-3의 globals.css 구조로 토큰을 만들고,
       app/page.tsx 헤더와 알림 영역의 slate 색을 토큰(text-ink, text-muted, bg-surface)으로 바꾸고 싶어.
[바꿀 곳] frontend/app/globals.css, frontend/app/layout.tsx, frontend/app/page.tsx
[바꾸지 말 것] 동작 전부. components/kit/은 못 고치니까 그대로.
[완료 기준] <html data-style="soft">일 때 배경이 바뀐다. 빌드 후 CSS에 .bg-surface 규칙이 있다.
[진행] 파일이 3개라 globals.css부터 하나씩 하자. 먼저 계획만.
```

**③ 반응형 다듬기**
```text
[목표] 폰 폭(375px)에서는 헤더의 버튼 줄이 길어서 답답해 보여.
       '하드웨어·규칙 설정' 버튼은 폰에서 아이콘만 보이게 하고 싶어.
[바꿀 곳] frontend/app/page.tsx의 header 부분만
[바꾸지 말 것] 데스크톱 화면 모양, 버튼이 가는 주소
[완료 기준] 375px에서 버튼 글자가 사라지고 아이콘만 남는다 (화면 읽기용 aria-label은 있다).
           1280px에서는 지금과 같다. 어느 폭에서도 가로 스크롤이 없다.
[진행] 바로 코드를 줘도 돼.
```

### 4-4. 계획을 받은 다음

- 계획이 요청과 다르면 **코드를 받기 전에** 고칩니다. ("2번은 하지 마", "파일은 하나만")
- 좋으면 "좋아, 진행해"라고 씁니다.

AI가 추측하지 않고 물어본 것입니다 — 좋은 신호입니다. 그 파일을 넣어 **다시 묶어서** 올립니다.

```bash
python tools/merge_ui.py --add components/team/FocusPanel.tsx
```

## 5. ④ 답을 코드에 넣기 — `apply_ui.py`

### 5-1. 답을 파일로 저장하기

1. VS Code에서 `context_packs` 폴더에 **`answer.md`** 파일을 만듭니다 (이미 있으면 내용을 지웁니다).
2. 채팅 화면에서 **답 전체를 복사**(답 아래의 복사 버튼)해서 붙여넣고 저장합니다.
   - 답 전체가 잘 안 복사되면, **코드블록마다 있는 복사 버튼**으로 블록만 차례로 붙여넣어도 됩니다.
     블록 첫 줄의 `// 파일: …` 표시로 파일을 나눕니다.

### 5-2. 미리 보기 — 아직 아무것도 바뀌지 않습니다

```bash
python tools/apply_ui.py
```

| 표시 | 뜻 |
|---|---|
| `[바꿈]` | 지금 파일을 이 내용으로 바꿉니다 (줄 수와 `+늘어난 줄 -줄어든 줄`) |
| `[새로]` | 새 파일을 만듭니다 |
| `[같음]` | 지금 파일과 똑같아서 건너뜁니다 |
| `[거부]` | 쓰지 않습니다 — 아래 `✖`에 이유가 있습니다 |
| `[건너뜀]` | 경로 표시가 없는 코드블록 (보통 명령어 예시) |
| `⚠` | 쓸 수는 있지만 확인이 필요합니다 (예: 212줄 → 80줄로 크게 줄었음) |

아래에 **바뀌는 곳**(`-` 지금 / `+` AI 답)이 나옵니다. **반드시 읽어 보세요.**
내가 부탁하지 않은 곳이 바뀌었다면 적용하지 말고 AI에게 물어봅니다.

### 5-3. 적용하기

```bash
python tools/apply_ui.py --write
```

바꾸기 전 파일은 `context_packs/backups/<시각>/`에 저장됩니다.

### 5-4. 되돌리기

```bash
python tools/apply_ui.py --undo
```

마지막 적용을 되돌리고, AI 답으로 새로 만든 파일은 지웁니다.
적용한 뒤 **학생이 직접 또 고친 파일은 되돌리지 않습니다** (내가 고친 것이 사라지지 않게).

### 5-5. 거부되었을 때

도구는 아래 경우에 **아무것도 쓰지 않습니다** — 파일 하나라도 문제가 있으면 전부 멈춥니다
(반쪽만 바뀌면 원인을 찾기 더 어렵습니다).

| 거부 이유 | 왜 |
|---|---|
| 4팀 공통 파일 (`lib/`, `components/kit/`, `app/kit/`, 설정 파일) | 고치면 다른 팀이 깨집니다 |
| `.env` 파일 | 비밀값은 내가 직접 관리합니다 |
| 생략 표시 (`...`, `// 기존 코드`, `(생략)`, `// 나머지는 그대로`) | 붙여넣으면 코드가 사라집니다 |
| diff 기호 (줄 앞의 `+` `-`) | 그대로 넣으면 문법 오류입니다 |
| 코드블록이 닫히지 않음 | 답이 중간에 끊겼습니다 |
| `page.tsx`에 `export default`가 없음 · `layout.tsx`에 `"use client"` | 빌드가 실패합니다 |

거부되면 화면에 **"여기부터 복사 ~ 여기까지"** 문장이 나옵니다 (`context_packs/retry.md`에도 저장).
그대로 복사해서 AI에게 보내면 됩니다.

### 5-6. 도구 없이 손으로 넣을 때

- 파일 **전체를 선택해서 바꿉니다** (일부만 골라 바꾸지 않기).
- 첫 줄의 `// 파일: …` 줄은 지워도 되고 남겨도 됩니다 (주석이라 동작에 영향이 없습니다).
- 파일 하나를 넣을 때마다 저장하고 5장의 확인을 합니다.
- 되돌리기는 `git checkout -- <파일>` (새로 만든 파일은 직접 지웁니다).

## 9. 안전 규칙

- **비밀값** — `.env.local`은 묶음에 들어가지 않습니다. 요청에도 키·비밀번호를 적지 않습니다.
- **개인정보** — 친구 이름·얼굴 사진·학번을 요청이나 코드에 넣지 않습니다.
- **서비스와 계정** — 학교에서 허용한 서비스·계정만 씁니다. 서비스마다 이용할 수 있는 나이와
  보호자 동의 조건이 다릅니다 (예: Claude.ai는 만 18세 이상만 가입할 수 있습니다). 모르면 선생님께 묻습니다.
- **AI 답을 그대로 믿지 않기** — 미리 보기에서 바뀌는 곳을 읽고, 6장의 확인을 직접 합니다.
- **공통 파일을 꼭 고쳐야 할 것 같으면** — AI 말만 믿고 고치지 말고 선생님께 먼저 말합니다.
  거의 항상 우리 파일로 해결하는 방법이 있습니다.

## 10. 라즈베리파이 담당과 맞추기 — 슬롯 약속표

### 10-1. 왜 약속이 필요한가

화면 코드는 부품을 **슬롯 이름**(`actuator_01`, `sensor_01`)으로 부릅니다.
라즈베리파이 담당이 배치표(`pi/slot_map.py`)에서 부품을 다른 슬롯으로 옮기면,
화면은 오류 없이 **엉뚱한 부품을 켜거나 버튼을 무시**합니다. 그래서 시나리오를 만들기 **전에** 둘이 약속합니다.

| 바뀌어도 괜찮은 것 | 바뀌면 화면이 깨지는 것 |
|---|---|
| `label`(대시보드 이름), 핀 번호, 배선 | **슬롯 이름**, `control_type`(켜는 값의 모양), 센서가 보내는 값의 모양 |

### 10-2. 약속표 — 둘이 같이 채워 팀 노션에 둡니다

| 슬롯 | 부품 | label | control_type / unit | 화면이 보내거나 받는 값 | 시나리오에서 쓰는 곳 |
|---|---|---|---|---|---|
| `actuator_01` | 피에조 부저 | 알람 부저 | `tonal` | `setActuator("actuator_01", "on", { frequency: 1000, volume: 80 })` | 알람 울리기 |
| `sensor_01` | 푸시 버튼 | 기상 확인 버튼 | — | `e.pressed === true` | 기상 확인 |
| | | | | | |

↑ 위 두 줄은 wakeup 팀 기본 배치표 예시입니다. 값의 모양은 control_type마다 정해져 있습니다:

| control_type | 켜기 상태 | 함께 보내는 값 |
|---|---|---|
| `onoff` | `"on"` / `"off"` | 없음 |
| `pulse` | `"on"` | `{ on_time: 0.25, off_time: 0.15 }` |
| `tonal` | `"on"` | `{ frequency: 1000, volume: 80 }` |
| `pwm` | `"on"` | `{ duty: 0~100 }` |
| `servo` | **`"move"`** (서보만 다름) | `{ angle: 0~180 }` |
| `rgb` | `"on"` | `{ r: 0~255, g: …, b: … }` |
| `level` | `"on"` | `{ level: 0~N }` |

센서는 `onSensor`로 받은 `e`에서 버튼·터치는 **`e.pressed`**, 인체감지는 **`e.detected`**,
숫자 센서(온도·거리·압력)는 **`e.number`** 를 씁니다.

### 10-3. 코드에서는 슬롯 이름을 한 곳에 모읍니다

시나리오 파일 맨 위에 **상수 하나**로 모아 두면, 배치표가 바뀌어도 이 줄만 고치면 됩니다.
wakeup 팀의 `scenarios/useWakeup.ts`가 본보기입니다.

```ts
/** 우리 팀 하드웨어 배치 — pi/slot_map.py, 약속표(10-2)와 같은 슬롯을 가리킵니다. */
export const OUR_SLOTS = {
  buzzer: "actuator_01",
  button: "sensor_01",
} as const;

// 쓰는 곳에서는 이름 대신 상수로
void setActuator(OUR_SLOTS.buzzer, "on", { frequency: 1000, volume: 80 });
```

AI에게 시나리오를 부탁할 때 "**슬롯 이름은 `OUR_SLOTS` 상수 한 곳에 모아 줘**"라고 [바꾸지 말 것]이나 [목표]에 적으세요.

**지금 배치표를 확인하는 법** — `/kit` → **하드웨어 구성** 탭(슬롯 20칸의 이름·종류),
또는 컨텍스트 팩의 "우리 팀 현재 배치표" 표, 또는 저장소의 `pi/slot_map.py`.

### 10-4. 바뀔 때와 통합 시험

| 언제 | 누가 · 무엇을 |
|---|---|
| 부품을 추가·이동·교체하기 **전** | 라즈베리파이 담당이 먼저 말합니다 → 둘이 약속표를 고칩니다 |
| 배치표를 바꾼 **뒤** | 라즈베리파이 담당이 커밋·푸시하고 알립니다 → 프론트엔드 담당은 `git pull` 후 `OUR_SLOTS`를 맞춥니다 |
| 하루 작업을 마칠 때 | 둘이 같이 **통합 시험** — 실제 버튼을 누르고, 화면에서 켜기를 눌러 부품이 실제로 움직이는지 |

통합 시험에서 문제가 나면 **어느 쪽인지 먼저 가립니다**:
화면에서 켜기를 눌렀을 때 카드가 **반영 대기**에 머물면 → 라즈베리파이 쪽(데몬·연결·배선, 07 매뉴얼).
**동작 중**이 되는데 시나리오가 다음 단계로 안 가면 → 화면 쪽(슬롯 이름·시나리오 코드).

## 11. 하드웨어 없이 시험하기

라즈베리파이 담당이 배선하는 동안에도 프론트엔드 담당은 시나리오를 끝까지 시험할 수 있습니다.

### 11-1. 부품을 켜는 쪽 (액추에이터)

화면에서 켜기를 누르면 카드의 **내린 명령**이 바뀝니다. 파이가 꺼져 있으면 배지가 **반영 대기**에 머무는데,
이것은 **화면 쪽은 정상**이라는 뜻입니다 (명령은 나갔고, 받을 파이가 없을 뿐).

### 11-2. 센서 입력 흉내 내기 — 가짜 보고 보내기

버튼을 누른 것처럼, 압력이 35kg인 것처럼 백엔드에 **보고를 대신 보냅니다**.
PC의 PowerShell에서, **저장소 맨 위 폴더**에서 실행합니다.

```powershell
# 키를 화면에 치지 않도록 backend/.env에서 읽어 옵니다 (한 번만)
$key = (Get-Content backend\.env | Select-String '^DEVICE_API_KEY=').Line.Split('=', 2)[1].Trim()
$url = "http://localhost:8000/api/v1/devices/states"

# 버튼 누름 → 뗌
Invoke-RestMethod -Method Post -Uri $url -Headers @{ "X-Device-Api-Key" = $key } -ContentType "application/json" -Body '{"states":[{"slot_id":"sensor_01","value":{"pressed":true}}]}'
Invoke-RestMethod -Method Post -Uri $url -Headers @{ "X-Device-Api-Key" = $key } -ContentType "application/json" -Body '{"states":[{"slot_id":"sensor_01","value":{"pressed":false}}]}'

# 숫자 센서 (온도·거리·압력 등) — 숫자는 꼭 "value"에
Invoke-RestMethod -Method Post -Uri $url -Headers @{ "X-Device-Api-Key" = $key } -ContentType "application/json" -Body '{"states":[{"slot_id":"sensor_02","value":{"value":35}}]}'
```

- 결과에 **`accepted=1`** 이 보이면 성공입니다. 화면의 센서 카드가 바뀌고, 시나리오의 `onSensor`가 불립니다.
- `slot_id`는 약속표의 센서 슬롯으로 바꿉니다.
- **`SLOT_DISABLED`** 가 나오면 그 슬롯이 아직 등록되지 않은 것입니다 → 11-3.
- 이 키는 비밀입니다. 이 명령을 AI 채팅에 붙여넣을 때 `$key` 줄의 결과값을 함께 붙이지 마세요.

### 11-3. 슬롯이 아직 등록되지 않았을 때

파이 데몬이 **한 번이라도** 켜져서 배치표를 등록했다면, 파이를 꺼도 슬롯은 켜진 채로 남습니다
(MySQL이 켜져 있으면 DB에 저장되기 때문입니다).
한 번도 등록된 적이 없다면, **실제 파이가 꺼져 있을 때만** PC에서 데몬을 흉내내기로 잠깐 켭니다.

```powershell
copy pi\.env.example pi\.env     # 처음 한 번 — 열어서 BACKEND_URL=http://localhost:8000, DEVICE_API_KEY=backend와 같게
cd pi
pip install -r requirements.txt  # 처음 한 번
python daemon.py                 # "[배치표 등록] 사용 슬롯 N개"가 나오면 Ctrl+C로 꺼도 됩니다
```

> ⚠️ 실제 파이가 켜져 있는데 PC에서도 데몬을 켜면 둘이 같은 슬롯을 두고 다툽니다. 둘 중 하나만 켜세요.

### 11-4. 카메라 쪽 (`onVision`)

vision이 PC에서 돈다면 웹캠 앞에 사물·손을 보여 주면 됩니다. `/` 화면의 비전 로그 카드에 감지 기록이 쌓이는지 먼저 봅니다.
vision이 파이에서 도는 팀은 영상인식 담당과 시간을 맞춰 함께 시험합니다.

### 11-5. 판정 규칙은 브라우저 없이

판정 규칙을 `scenarios/<우리팀>Engine.ts`에 React 없는 순수 함수로 두면(00 매뉴얼 5-3),
`node --experimental-strip-types scenarios/<우리팀>Engine.test.ts`로 하드웨어·브라우저 없이 바로 시험합니다.

## 12. 팀 브랜치에서 둘이 함께 일하기 (git)

프론트엔드 담당은 `frontend/`, 라즈베리파이 담당은 `pi/slot_map.py`를 고치므로 **같은 파일이 겹치지 않습니다.**
순서만 지키면 충돌은 거의 나지 않습니다.

| 언제 | 명령 (저장소 맨 위 폴더) |
|---|---|
| 작업을 **시작할 때마다** | `git pull` — 상대가 올린 것을 먼저 받기 |
| 한 가지가 잘 됐을 때 | `git add frontend` → `git commit -m "[frontend] 지금 상태 줄 추가"` |
| 하루를 마칠 때 | `git push` |
| `push`가 **rejected** 될 때 | 상대가 먼저 올린 것입니다. `git pull` → 다시 `git push` |
| `pull`이 **충돌(CONFLICT)** 을 알릴 때 | 당황하지 말고 `git merge --abort`로 되돌린 뒤 선생님께. 같은 파일을 둘이 고친 경우입니다 |

- **`.env.local`·`.env`는 커밋되지 않습니다** (`.gitignore`). 각자 PC의 설정이라 서로 덮어쓰지 않습니다.
- `git add -A`보다 **`git add frontend`** 처럼 내 폴더만 담으면, 실수로 남의 파일을 올리지 않습니다.
- 올리기 전에 `git status`로 목록을 한 번 봅니다 — `.env`가 보이면 멈춥니다.
