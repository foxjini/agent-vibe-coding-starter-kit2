# 05. 라즈베리파이 5 실기기 마이그레이션 매뉴얼

> **대상**: 라즈베리파이 담당 학생
> **목표**: PC에서 돌아가던 ATM 데몬을 라즈베리파이 5에서 **실제 서보가 움직이도록** 옮긴다
> **걸리는 시간**: 처음이면 2~3시간 (배선 제외)

이 문서는 **옮기는 순서**만 다룹니다. 하드웨어가 처음이라면
[06 배선과 구성](./06_라즈베리파이-ATM-배선과-구성.html)을 브라우저로 먼저 여세요 —
같은 절차를 그림으로 설명하고, **센서·액추에이터를 바꿔 다는 방법**까지 있습니다.
백엔드와 주고받는 API 규격은
[부록 A](./부록A_라즈베리파이5-연동-인터페이스-가이드.md), 전시 당일 동선은
[04 전시회 시연 매뉴얼](./04_전시회-시연-매뉴얼.md)을 보세요.

---

## 0. 시작하기 전에

### 준비물

| | |
|---|---|
| 라즈베리파이 5 | 전원 어댑터(5V/5A 공식 어댑터 권장), microSD |
| 라즈베리파이 OS | Bookworm 또는 Trixie (데스크톱 이미지 권장 — 7인치 화면을 띄워야 한다) |
| MG996R 서보 2개 | 게이트 + 밀대 |
| **별도 5V 전원** | **서보용. 파이 5V 핀에 직결하지 않는다** (0-2 참고) |
| USB 웹캠 | QR 인식용. **파이 카메라 모듈(CSI)은 쓸 수 없다** (3-3 참고) |
| 7인치 터치 디스플레이 | ATM 화면 |
| 점퍼선, 브레드보드 | |

### 0-1. 전체 순서 한눈에

```
1. PC에서 mock으로 통과 확인      ← 여기서 안 되면 파이에서도 안 된다
2. 파일 옮기기 (git clone)
3. 파이썬 환경 만들기             ← 가장 많이 막히는 곳
4. .env 작성
5. 배선 (전원 끄고, 교사 입회)
6. check_hardware.py 로 점검      ← 여기서 [실패]가 없어야 다음으로
7. --servo 로 서보 확인 (교사 입회)
8. 데몬 실행
9. 7인치 화면 띄우기
10. 전 구간 확인
```

**순서를 지키세요.** 6번을 건너뛰고 8번으로 가면, 무엇이 잘못됐는지 찾는 데
훨씬 오래 걸립니다.

### 0-2. 안전 수칙 (먼저 읽습니다)

1. **서보는 별도 5V 전원으로 돌립니다.** 파이의 5V 핀에 직결하면 서보가 움직이는
   순간 전압이 떨어져 **파이가 재부팅되거나 SD 카드가 손상될 수 있습니다.**
2. **접지(GND)는 파이와 외부 전원이 함께 씁니다.** 이게 연결되지 않으면 서보가
   제멋대로 움직이거나 아예 안 움직입니다.
3. **배선을 바꿀 때는 반드시 전원을 끕니다.**
4. **실기기 첫 연결과 `--servo` 테스트는 교사 입회 하에** 합니다.
5. 서보가 움직일 때 **배출구에 손을 넣지 않습니다.** MG996R은 힘이 셉니다.

## 2단계. 파일 옮기기

**`pi/` 폴더만 복사하면 안 됩니다.** `pi/main.py`는 장치 제어 코드를
`backend/iot/`에서 가져옵니다.

```bash
# 파이에서
git clone <저장소 주소>
cd <저장소 이름>
```

`backend/` 전체가 부담스러우면 **`backend/iot/` 하나만 옮겨도 됩니다.**
`iot/`는 표준 라이브러리만 쓰기 때문입니다. 다만 자리는 정해져 있습니다.

```
<상위폴더>/
├── pi/            ← 여기서 python main.py
└── backend/
    └── iot/       ← 이것만 있으면 된다
```

> 이 구조가 아니면 실행하자마자 `ModuleNotFoundError: No module named 'iot'`가
> 납니다. 요즘은 이 오류가 나면 화면에 위 그림과 고치는 방법이 함께 뜹니다.

## 3단계. 파이썬 환경 만들기 — **가장 많이 막히는 곳**

### 3-1. GPIO 라이브러리는 대개 이미 있습니다

라즈베리파이 OS 데스크톱 이미지에는 `gpiozero`와 `lgpio`가 처음부터 들어 있습니다.
**다시 설치하려 들지 말고, 먼저 확인하세요.**

```bash
/usr/bin/python3 -c "import gpiozero, lgpio; print('있음')"
```

| 결과 | 할 일 |
|---|---|
| `있음` | 설치할 것 없습니다. 3-2로 갑니다 |
| `ModuleNotFoundError` | `sudo apt install -y python3-gpiozero python3-lgpio` |

`pip install lgpio`는 하지 마세요. 최근 라즈베리파이 OS에서 빌드에 실패하는 일이
잦고, apt 쪽이 이 기기에 맞게 이미 준비되어 있습니다.

### 3-2. venv는 반드시 `--system-site-packages`로

여기가 핵심입니다. `gpiozero`와 `lgpio`는 **시스템 파이썬**에 있는데, 그냥 만든
venv 안에서는 **보이지 않습니다.** "분명 설치했는데 `No module named 'gpiozero'`"가
나는 이유가 이것입니다.

```bash
cd pi
rm -rf venv                                    # PC에서 만든 venv가 있으면 지운다
python3 -m venv --system-site-packages venv    # ← 이 옵션이 없으면 못 본다
source venv/bin/activate
pip install -r requirements.txt
```

확인:

```bash
python -c "import gpiozero, lgpio; print('venv에서도 보임')"
```

> **opencv 설치가 오래 걸리면** (몇 분이 지나도 계속 빌드 중이면) 중단하고
> apt 쪽을 쓰는 편이 빠릅니다. `--system-site-packages` venv를 썼다면 이것도
> 바로 보입니다.
> ```bash
> sudo apt install -y python3-opencv
> # requirements.txt 에서 opencv-python 줄을 빼고 나머지만 설치
> ```

## 4단계. `.env` 작성

```bash
cd pi
cp .env.example .env
nano .env
```

바꿔야 하는 값:

| 키 | 값 | 설명 |
|---|---|---|
| `DEVICE_MODE` | `hardware` | `mock`이면 서보가 안 움직입니다 |
| `GPIOZERO_PIN_FACTORY` | `lgpio` | 파이 5는 GPIO 칩이 달라(RP1) 이게 필요합니다 |
| `BACKEND_URL` | `http://<백엔드 PC의 IP>:8000` | **`localhost`는 파이 자신을 뜻합니다** |
| `DEVICE_API_KEY` | 백엔드와 **같은 값** | `backend/.env`와 한 글자도 달라선 안 됩니다 |
| `SERVO_GATE_PIN` | 실제 배선한 핀 번호 | 기본 18 |
| `SERVO_PUSHER_PIN` | 실제 배선한 핀 번호 | 기본 19 |
| `ENABLE_CAMERA` | `true` | 카메라 없이 먼저 볼 때는 `false` |

그대로 둬도 되는 값 (필요할 때만 건드립니다):

| 키 | 기본값 | 언제 바꾸나 |
|---|---|---|
| `SERVO_HOLD` | `false` | 게이트가 제 무게로 흘러내릴 때만 `true` (5-3 참고) |
| `BUZZER_PIN` | (비어 있음) | 부저를 달았을 때 핀 번호 |
| `WARN_BEEP_SECONDS` / `_COUNT` | `0.2` / `2` | 경고음이 너무 짧거나 길 때 |
| `CAMERA_WIDTH` / `_HEIGHT` | `640` / `480` | **키우지 마세요** (3-3, 6단계 참고) |
| `CAMERA_INDEX` | `0` | 파이에 USB 웹캠 하나면 보통 0입니다 (아래 설명) |
| `IDLE_RESET_SECONDS` | `60` | 리허설에서 화면을 오래 띄우려면 `0` |

> **`CAMERA_INDEX`는 추측하지 마세요.** 리눅스에서 USB 웹캠 하나를 꽂으면 장치가
> 둘 생깁니다 — `/dev/video0`(영상)과 `/dev/video1`(메타데이터). **번호가 있다고
> 카메라가 아닙니다.** 메타데이터 쪽을 지정하면 열리기는 하는데 영상이 한 장도
> 오지 않습니다. 6단계의 `check_hardware.py`가 **영상이 실제로 들어오는 번호**를
> 찾아 알려 주니, 그 번호를 넣으면 됩니다.

> **백엔드도 외부 접속이 되게 떠 있어야 합니다.** PC에서
> `uvicorn main:app --host 0.0.0.0 --port 8000` 으로 띄우세요.
> `127.0.0.1`로 띄우면 파이에서 닿지 못합니다.

## 5단계. 배선

### 5-1. 연결

**전원을 끄고** 연결합니다.

```
파이 GPIO18 ──── 게이트 서보 신호선(주황/노랑)
파이 GPIO19 ──── 밀대 서보 신호선
파이 GND   ──┬── 서보 GND(갈색/검정)
             └── 외부 5V 전원 GND      ← 반드시 함께 묶는다
외부 5V(+)  ──── 서보 전원선(빨강)
```

파이는 **신호만** 줍니다. 서보의 힘은 외부 전원에서 나옵니다.

### 5-2. 실제 핀 번호가 다르다면

배선을 먼저 하고 `.env`의 `SERVO_GATE_PIN` / `SERVO_PUSHER_PIN`을 그 번호로
맞추면 됩니다. **코드는 고치지 않습니다.**

### 5-3. `SERVO_HOLD`가 왜 있나

gpiozero는 각도를 준 뒤에도 신호를 계속 내보냅니다. MG996R은 그동안 자세를
유지하느라 전류를 계속 먹고 미세하게 떨립니다("지지직" 소리). 몇 시간짜리 전시
내내 그러면 발열과 전압 강하로 이어집니다.

그래서 기본값은 **자세를 잡은 뒤 신호를 끊는 것**(`SERVO_HOLD=false`)입니다.
게이트가 제 무게로 흘러내린다면 그때만 `true`로 바꿉니다. (전류는 더 먹습니다)

## 6단계. 점검 — 데몬을 켜기 전에

```bash
cd pi
python check_hardware.py
```

파이썬 환경 · 폴더 구조 · `.env` · GPIO · 카메라 · 백엔드 연결을 한 줄씩 확인해
줍니다. **서보는 움직이지 않으니 안전합니다.**

```
[  OK  ] 파이썬 3.13.5 — .../pi/venv/bin/python
[  OK  ] venv가 시스템 패키지를 함께 봄 — --system-site-packages
[  OK  ] iot 모듈 import 가능
[  OK  ] DEVICE_MODE=hardware — 실기기
[  OK  ] gpiozero 버전 확인 불가          ← 버전을 못 읽어도 문제 없습니다
[  OK  ] lgpio 사용 가능
[  OK  ] 핀 팩토리 준비됨 — LGPIOFactory
[  OK  ] 카메라 영상 읽기 성공 (CAMERA_INDEX=0) — 640x480
[  OK  ] QR 검출 속도 넉넉함 — 12ms/장 (여유 100ms)
[  OK  ] 디바이스 키 통과
```

버전 숫자는 기기마다 다릅니다. **`[  OK  ]`인지 아닌지만 보면 됩니다.**

**`[실패]`가 하나라도 있으면 다음 단계로 가지 않습니다.** 실패 줄 바로 아래에
무엇을 어떻게 고치는지가 함께 나옵니다. 위에서부터 차례로 고치세요.

> 점검 하나가 예상치 못하게 터져도 **나머지는 계속 확인합니다.** 도구가 중간에
> 죽어서 뒤쪽(카메라·백엔드)을 못 보는 일이 없게 하려는 것입니다.

> **QR 검출 속도가 `빠듯함`이나 `느림`으로 나오면** 해상도가 크게 열린 것입니다.
> 검출 비용은 화소 수에 거의 비례합니다 (640×480은 약 12ms, 1920×1080은 약 62ms).
> `.env`의 `CAMERA_WIDTH=640`, `CAMERA_HEIGHT=480`을 확인하세요.

## 7단계. 서보 확인 — **교사 입회 하에**

여기서 처음으로 서보가 실제로 움직입니다.

```bash
python check_hardware.py --servo
```

게이트 서보가 90도로 열렸다가 1초 뒤 닫힙니다. **눈으로 확인할 것:**

- [ ] 서보가 실제로 움직였는가
- [ ] 닫힌 뒤 **조용해지는가** (계속 "지지직" 하면 5-3을 확인)
- [ ] 파이가 재부팅되지 않았는가 (재부팅됐다면 전원이 부족한 것 — 0-2 참고)

## 8단계. 데몬 실행

```bash
python main.py
```

기동 로그에서 확인할 것:

```
PWMSoftwareFallback: To reduce servo jitter, use the pigpio pin factory
  ↑ 경고이지 오류가 아닙니다. 파이 5(RP1)에서는 pigpio를 쓸 수 없어
    소프트웨어 PWM으로 돕니다. 서보가 미세하게 떨릴 수 있지만 동작에는 문제 없습니다.
하드웨어 Provider 시작 (gate=GPIO18, pusher=GPIO19, 대기 시 펄스=끊음)
카메라 열림 (index=0, backend=any, 640x480)      ← 번호와 해상도를 확인하세요
QR 스캔 시작 (camera_index=0)
ATM 데몬 시작 — DEVICE_MODE=hardware, port=8100
```

> **"카메라 열림"이 떴는데 QR이 안 읽힌다면** 번호가 잘못된 것입니다. 데몬은 이제
> 프레임을 한 장 받아 보고, 안 오면 **쓸 수 있는 번호를 알려 주며 멈춥니다.**

**`DEVICE_MODE=mock`으로 뜨면 `.env`를 다시 확인하세요.** mock이면 서보는
움직이지 않습니다.

> 장치 준비에 실패하면 데몬은 **아예 뜨지 않습니다.** 일부러 그렇게 만들었습니다 —
> mock으로 되돌아가면 서보는 가만히 있는데 화면과 서버에는 "배출했다"고 기록되는,
> 현금에 대해 거짓말하는 ATM이 되기 때문입니다.

다른 터미널에서 확인:

```bash
curl http://localhost:8100/state
```

## 10단계. 전 구간 확인

백엔드와 데몬이 모두 떠 있는 상태에서:

```bash
python scripts/demo_e2e.py
```

정상 문자 → 출금 가능, 보이스피싱 문자 → 출금 차단 → 콜센터 해제까지 실제 HTTP로
확인합니다. **마지막 줄이 "통합 시연 전 구간 통과"** 여야 합니다.

그다음 **직접 손으로** 확인합니다.

- [ ] 화면에서 5만원 → 서보가 움직이고 "50,000원을 배출했습니다"
- [ ] 위험 QR을 카메라에 → 화면이 빨갛게 + **부저가 "삑삑" 두 번**
- [ ] 그 상태에서 50만원 → **서보가 전혀 움직이지 않는다** ← 이 작품의 전부입니다
- [ ] "상담원 확인 요청하기" → 콜센터 화면에서 해제 → 다시 배출됨

## 11. 실기기가 PC와 다른 점

PC 리허설만 하다가 파이에서 처음 보면 "고장 났나?" 싶은 것들입니다. **전부
정상입니다.**

| 현상 | 이유 |
|---|---|
| 출금 버튼을 눌러도 1~2초 반응이 없다 | 서보가 게이트를 열고·밀고·닫는 실제 시간(약 1.4초)입니다. 그동안 화면은 "잠시만 기다려 주세요"를 띄우고 금액 버튼을 잠급니다 |
| 위험 판정 때 "삑삑" 소리가 난다 | 경고 부저입니다. 두 번 울리고 꺼집니다 |
| 배출 뒤 서보가 조용해진다 | 신호를 끊어 쉬게 하는 것입니다 (5-3) |
| 차단 화면에 카운트다운이 없다 | 막혀 있는 동안에는 자동 초기화가 돌지 않습니다. 시간이 차단을 풀어 주면 안 되니까요 |
| 차단 화면에서 "처음으로"가 안 먹는다 | 한 번 누르면 "직원 확인 후 해제" 버튼이 나옵니다. 제한은 사람이 풉니다 |

## 12. 문제 해결

| 증상 | 해결 |
|---|---|
| `ModuleNotFoundError: No module named 'iot'` | 2단계의 폴더 구조를 확인합니다 |
| `No module named 'gpiozero'` (설치했는데도) | venv가 apt 패키지를 못 봅니다. 3-2로 다시 만듭니다 |
| `BadPinFactory` / `Unable to load any default pin factory` | `lgpio`가 없거나 `.env`에 `GPIOZERO_PIN_FACTORY=lgpio`가 빠졌습니다 |
| GPIO 권한 오류 | `sudo usermod -aG gpio $USER` 후 **다시 로그인** |
| 데몬을 껐다 켰는데 "핀이 사용 중" | 앞서 띄운 데몬이 아직 살아 있습니다. `ps aux \| grep main.py` 로 찾아 종료합니다 |
| `ImportError: libGL.so.1` (cv2) | `sudo apt install -y libgl1 libglib2.0-0` |
| 카메라를 못 연다 | `CAMERA_INDEX`를 1, 2로. 파이 카메라 모듈(CSI)은 `cv2.VideoCapture`로 열리지 않습니다 — USB 웹캠을 씁니다 |
| ATM API가 401 | `DEVICE_API_KEY` 불일치입니다. 양쪽 `.env`를 맞추고 **둘 다 재시작** |
| 백엔드에 못 붙는다 | `BACKEND_URL`이 `localhost`면 파이 자신을 가리킵니다. PC의 실제 IP로 바꾸고, PC 백엔드가 `--host 0.0.0.0`인지 확인합니다 |
| 서보가 떨리기만 하고 안 움직인다 | 전원이 부족하거나 GND가 따로 놀고 있습니다 (0-2) |
| 서보가 움직일 때 파이가 재부팅된다 | 서보를 파이 5V에 직결했습니다. 별도 전원으로 분리합니다 |
| QR 인식이 느리거나 밀린다 | 6단계의 속도 측정과 `CAMERA_WIDTH/HEIGHT`를 확인합니다 |

**여기에 없는 오류가 나면** `python check_hardware.py` 출력과 데몬 터미널의
마지막 `Traceback` 부분을 통째로 팀에 공유하세요.

## 13. 아직 실기기에서 확인되지 않은 것

정직하게 적어 둡니다. 이 문서의 절차와 코드 경로는 **가짜 GPIO로 시뮬레이션해서**
끝까지 검증했지만, 아래는 **진짜 기기에서만 알 수 있습니다.**

- 서보가 실제로 도는지, 각도(0°/90°)와 유지 시간(1.0초)이 배출구에 맞는지
- 전원이 버티는지 (서보 2개 동시 동작 시)
- 부저 소리 크기가 전시장에서 적당한지
- 웹캠이 640×480으로 실제로 열리는지

이 값들은 전부 `.env`나 `backend/iot/hardware_provider.py` 상단 상수로 빼 두었으니,
조립한 뒤 실측해서 맞추면 됩니다. **맞춘 값은 팀에 공유하고 이 문서에 기록하세요.**
