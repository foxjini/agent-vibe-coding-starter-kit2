    팀 전체 4단계 — 파란 칸이 내 일 · 자세한 설명 ②는 17번 · ③은 18번 · 우리 팀 예시 19~20번

    STEP 2 · 파이 담당과 함께

    슬롯 약속표 — classroom 팀 (★ = 모의 작업에서 추가)

    화면은 부품을 슬롯 이름(actuator_01)으로 부릅니다. 파이 담당이 슬롯을 바꾸면 화면이 엉뚱한 부품을 켭니다. 표를 팀 노션에 두고, 바뀔 때마다 같이 고칩니다.

    슬롯부품control_type / 단위화면에서 쓰는 코드
    actuator_01SG90 서보servosetActuator("actuator_01", "move", { angle: 90 })
    actuator_02LEDonoffsetActuator("actuator_02", "on")
    actuator_03네오픽셀 12알rgbsetActuator("actuator_03", "on", { r: 255, g: 200, b: 120 })
    actuator_04피에조 부저tonalsetActuator("actuator_04", "on", { frequency: 1000, volume: 80 })
    actuator_05릴레이 모듈onoffsetActuator("actuator_05", "on")
    actuator_06 ★ 추가LED (점멸)pulsesetActuator("actuator_06", "on", { on_time: 0.25, off_time: 0.25 })
    sensor_01 ★ 추가PIR 인체감지 (HC-SR501)—onSensor("sensor_01", e => { if (e.pressed) … })
     

    켜는 값의 모양 (control_type별)

    control_type상태함께 보내는 값
    onoff"on"/"off"없음
    pulse"on"{ on_time: 0.25, off_time: 0.15 }
    tonal"on"{ frequency, volume }
    pwm"on"{ duty: 0~100 }
    servo"move"{ angle: 0~180 }
    rgb"on"{ r, g, b } (0~255)
    level"on"{ level: 0~N }

    센서 값: 버튼·터치·PIR 인체감지 e.pressed (셋 다 button_in) · 숫자(온도·거리·압력·조도) e.number

    화면에 보여 줄 지금 값은 slotOf("sensor_02")?.current_value에서 읽습니다. onSensor는 값이 바뀌는 순간 할 일(경고음·횟수 세기)에만 씁니다 — 거기서 모은 값은 새로고침하면 비어 보입니다.

    지금 배치표 확인하기

    • http://localhost:3000/kit → 하드웨어 구성 탭
    • 저장소의 pi/slot_map.py (파이 담당이 자기 PC에서 고쳐 팀 PC로 복사·커밋한 것 — 막 고친 최신 상태는 위의 하드웨어 구성 탭이 더 정확)

    코드에서는 한 곳에 모으기

    scenarios/useClassroom.ts 맨 위
    export const OUR_SLOTS = {
  warningLight: "actuator_06",  // ★ 출입 경고등 (점멸)
  motion: "sensor_01",          // ★ 출입문 인체감지 (PIR)
} as const;

    슬롯이 바뀌면 이 상수만 고칩니다. 표에 없는 부품을 달면 빈 줄에 적고 상수에도 한 줄 추가.

    HOW WE CODE

    AI와 일하는 한 바퀴 — 5단계

    채팅형 AI는 우리 폴더를 볼 수 없습니다. 그래서 필요한 파일을 하나로 묶어(컨텍스트 팩) 보여 주고, 받은 답을 도구로 넣습니다.

    1. 정하기바꿀 것 하나
    2. 묶기merge_ui.py / context_pack.py
    3. 요청새 대화 + 파일 올리기 + 프롬프트
    4. 넣기answer.md → apply_ui.py
    5. 확인eslint · build · 브라우저
    단계명령 (저장소 맨 위 폴더)
    ② 묶기 (화면)python tools/merge_ui.py
    ② 묶기 (새 시나리오)python tools/context_pack.py frontend
    ④ 미리 보기python tools/apply_ui.py
    ④ 적용python tools/apply_ui.py --write
    ④ 되돌리기python tools/apply_ui.py --undo
    ⑤ 확인cd frontend → npx eslint . → npx next build
    다음 요청은 반드시 ② 묶기부터

    묶음 파일은 만든 순간의 사진입니다. 코드를 고친 뒤 옛 묶음을 올리면 AI가 고친 것을 되돌려 놓습니다.

    하려는 일명령생기는 파일

    무엇이 들어갈지만 보기python tools/merge_ui.py --list(파일 안 만듦)
    올리는 법

    AI에서 새 대화 → 생긴 .md 파일을 파일로 올리기 → 같은 메시지에 프롬프트(8번 슬라이드).

    시나리오 파일을 --add 했다면

    프롬프트 [바꿀 곳]에 "이번에는 scenarios/○○.ts도 고친다"고 꼭 적습니다. 그리고 화면 묶음에는 배치표가 들어 있지 않으니, 새 부품의 슬롯·control_type·값을 약속표에서 옮겨 [목표]에 적습니다.

    classroom · subway 팀의 컨텍스트 팩

    팩에 study 팀 파일(studyEngine.ts·useStudy.ts)이 "제가 고치는 파일"로 들어 있습니다. 우리 것이 아니니 프롬프트 [바꾸지 말 것]에 "study 파일은 고치지 마"를 적습니다.

    더 알기 · 팀 4단계의 ②

    배치표가 바뀌면 — 저절로 바뀌는 것, 사람이 고칠 것

    화면은 두 부분입니다. 키트가 만드는 부분(부품 카드 · /kit 하드웨어 구성)은 배치표를 따라 저절로 바뀝니다. 팀이 만든 부분(미션·타이머·팝업 코드와 자동화 규칙)은 부품을 자리 이름으로 부르므로 경우에 따라 사람이 고칩니다.

    자리 이름 = 슬롯 이름

    배치표의 부품마다 붙은 이름입니다. 화면 코드는 "actuator_01을 켜라", "sensor_01이 눌리면 알람 끄기"처럼 이 이름으로 명령합니다.

    frontend/scenarios/useWakeup.ts (본보기)
    export const WAKEUP_SLOTS = {
  buzzer: "actuator_01",   // 부저는 1번 자리
  button: "sensor_01",     // 확인 버튼은 1번 센서 자리
};
    저절로 됨 — 프론트 담당은 할 일 없음
    • 부저를 GPIO 18 → 13으로 옮김 (자리 이름은 그대로 actuator_01)
    • 부품 이름을 "알람 부저" → "침대 옆 부저"로 바꿈 → 카드 제목이 바뀜
    • 빈 자리 actuator_02에 LED를 새로 닮 → 카드가 하나 생김
    사람이 고쳐야 함 — 바꾸기 전에 먼저 말하기
    바뀐 것고치지 않으면프론트 담당이 고칠 것
    자리 번호
    actuator_01 → actuator_03    		카드는 03에 생기지만 코드는 빈 01에 명령 → 알람이 울리지 않음buzzer: "actuator_03" 한 줄
    부품 종류
    버튼 → 거리 센서    		버튼은 e.pressed(눌림), 거리 센서는 e.number(예: 35cm) → 손을 대도 반응 없음"눌렸나?" → "30cm보다 가까운가?" 판정 줄
    자동화 규칙에 쓴 자리규칙이 빈 자리를 지켜봄 → 발동 안 함/kit 규칙 화면에서 자리 다시 고르기
    약속

    핀 번호·부품 이름만 바꿀 때 → 말 안 해도 됨.
    자리 번호·종류를 바꿀 때 → 바꾸기 전에 프론트 담당에게 말하고 슬롯 약속표를 함께 고칩니다.

    // scenarios/useClassroom.ts
onSensor(OUR_SLOTS.motion, (e) => {
  // PIR은 button_in 드라이버라 {"pressed": true}로 옵니다
  if (!e.pressed) return;
  const result = registerMotion(entryRef.current, Date.now());
  if (!result.counted) return;               // 3초 안 재감지 = 같은 사람
  entryRef.current = result.state;
  setEntry(result.state);
  notify(`출입 감지 — 오늘 ${result.state.count}번째`, "info");
  void setActuator(OUR_SLOTS.warningLight, "on", { on_time: 0.25, off_time: 0.25 });
  if (offTimer.current !== null) cancel(offTimer.current);
  offTimer.current = after(5, () => {
    void setActuator(OUR_SLOTS.warningLight, "off");
  });
});

    새 파일 scenarios/classroomEngine.ts(registerMotion) · classroomEngine.test.ts · components/team/EntryCard.tsx · app/page.tsx의 안내 카드 → <EntryCard />

    PC · PowerShell · 같은 창에서 한 줄씩
    Invoke-RestMethod -Method Post -Uri $url -Headers $h -ContentType "application/json" -Body '{"states":[{"slot_id":"sensor_01","value":{"pressed":true}}]}'
Invoke-RestMethod -Method Post -Uri $url -Headers $h -ContentType "application/json" -Body '{"states":[{"slot_id":"sensor_01","value":{"pressed":false}}]}'
    이렇게 되면 성공
    • {"pressed":true} → 출입 1명 · 알림 · 경고등 pulse 명령
    • {"pressed":false} → (뗌) — 5초 뒤 경고등 끄기 명령

    3초 안에 true를 한 번 더 보내면 그대로 1명, 3초 뒤에 보내면 2명.

    모의 작업에서 막혔던 곳
    • 모의 작업 처음 실패 원인: 예전 문서대로 e.detected를 썼더니 PIR을 무시했습니다. PIR은 버튼과 같은 e.pressed입니다 (지금 문서는 고쳐짐).
    • 컨텍스트 팩에 study 팀 파일이 "고치는 파일"로 들어 있습니다 → [바꾸지 말 것]에 "study 파일은 고치지 마".
    • 출입 횟수는 화면 안에서 세므로 새로고침하면 0부터 다시 셉니다. 전시 중에는 탭을 닫지 않습니다.
