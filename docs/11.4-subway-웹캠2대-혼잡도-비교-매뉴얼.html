    11.4 subway 팀
    웹캠 2대로 두 칸 혼잡도 비교

    웹캠 2대로 지하철 1번 칸·2번 칸의 사람 수를 세고, 화면에 "2번 칸이 덜 붐벼요"처럼 덜 붐비는 칸을 안내합니다. 처음 하는 사람도 그대로 따라 할 수 있게 순서대로 적었습니다. 한 단계를 끝내고 눈으로 확인한 다음 넘어갑니다.

    팀 subway · 지하철 혼잡도 시스템 어디서 팀 PC (백엔드가 도는 PC) 누가 1~7단계 비전 담당 · 8~11단계 프론트 담당 넘기기 ← → · 목차
    백엔드·비전 공통 코드는 한 줄도 고치지 않습니다

    칸 수를 세는 검출기 파일(vision/detectors/subway_cars.py)은 키트에 이미 들어 있습니다. 우리가 할 일은 ① 웹캠 꽂기 ② vision/.env에 한 줄 ③ 비전 프로그램을 창 2개로 켜기 ④ 화면 만들기입니다.

    이 매뉴얼의 명령·출력·화면은 실제로 실행해 확인한 것입니다(웹캠 대신 사진 2장으로 시험: 1번 칸 3명 · 2번 칸 2명).

    OVERVIEW

    한눈에 보기 — 웹캠 1대 = 비전 창 1개 = 칸 1개

    비전 프로그램(main.py)은 웹캠을 하나만 엽니다. 그래서 웹캠이 2대면 비전 프로그램을 2번 따로 켜고, 창마다 "나는 몇 번 칸"인지 알려 줍니다.

    📷 웹캠 1 → 창 ①

    CAMERA_INDEX=0 · SUBWAY_CAR=car_1
    "car_1: 3명 (혼잡 단계 1)"을 보냄

    📷 웹캠 2 → 창 ②

    CAMERA_INDEX=1 · SUBWAY_CAR=car_2
    "car_2: 2명 (혼잡 단계 1)"을 보냄

    🖥 백엔드 → 화면

    백엔드는 받은 그대로 화면에 전달 → 화면이 두 칸을 비교해 "2번 칸이 덜 붐벼요"

    무엇고치나?설명
    backend/ 전부✕ 안 고침칸 라벨(car_1·car_2)·사람 수·혼잡 단계를 그대로 화면에 넘겨 줍니다
    vision/main.py · camera.py✕ 안 고침4팀 공통 파일입니다
    vision/detectors/subway_cars.py이미 있음 (필요하면 숫자 하나)사람 수를 세어 칸 라벨로 보내는 검출기. SUBWAY_CAR가 없으면(다른 팀) 아무것도 안 함
    vision/.env한 줄 추가SUBWAY_CAR=car_1 (3단계)
    /kit 영상인식 설정체크 하나subway_cars만 켜기 (6단계)
    frontend/새 화면바이브 코딩으로 비교 카드 만들기 (9~11단계)

    STEPS

    전체 순서 — 11단계 (괄호 안은 슬라이드 번호)

    1. 웹캠 꽂고 번호 찾기0번 · 1번 (4)
    2. 검출기 파일 확인subway_cars.py (5)
    3. vision/.env 한 줄SUBWAY_CAR (6)
    4. 창 ① 켜기car_1 (7)
    5. 창 ② 켜기car_2 (8)
    6. subway_cars만 켜기/kit 설정 (9)
    7. 감지 로그 확인car_1 · car_2 (10)
    1. 웹캠 없이 시험가짜 이벤트 (11)
    2. AI에게 요청팩 · 프롬프트 (12)
    3. 넣고 검사apply_ui · 빌드 (13)
    4. 화면 확인 · 커밋완료 기준 (14 · 17)

    규칙 1 · 한 단계씩

    단계마다 "이렇게 되면 성공"을 눈으로 확인하고 넘어갑니다. 안 되면 16번 슬라이드(증상으로 찾기).

    규칙 2 · 비밀값

    .env의 DEVICE_API_KEY는 AI 채팅에 붙여넣지 않고, 커밋하지 않습니다.

    규칙 3 · 공통 파일

    main.py·backend/를 고치라는 AI 답은 거절하고 "우리 파일로 같은 결과를 내 줘"라고 다시 요청합니다.

    STEP 1 · 비전 담당

    웹캠 2대를 꽂고 카메라 번호 찾기

    1. 웹캠 2대를 PC 본체의 서로 다른 USB 포트에USB 허브 하나에 둘 다 꽂으면 대역폭이 모자라 한쪽이 안 열릴 수 있습니다. 가능하면 앞·뒤 포트처럼 떨어진 포트에 꽂습니다.
    2. 카메라 번호 확인
      팀 PC · PowerShell · 저장소 맨 위
      cd vision
.\venv\Scripts\Activate.ps1
python -c "import cv2; print([i for i in range(4) if cv2.VideoCapture(i, cv2.CAP_DSHOW).isOpened()])"
      결과가 [0, 1]이면 0번·1번 두 대가 잡힌 것입니다.
    결과뜻 · 할 일
    [0, 1]정상. 0번 → 1번 칸, 1번 → 2번 칸으로 씁니다
    [0, 1, 2]노트북 내장 카메라가 0번입니다. 웹캠은 1번·2번 → 3·5단계에서 1과 2를 씁니다
    [0]한 대만 잡힘 → 다른 USB 포트로 옮기고 다시 확인
    []하나도 안 잡힘 → 다른 프로그램(줌·카메라 앱)이 쓰고 있는지 확인 후 닫기
    번호와 칸이 맞는지는 7·8단계에서 손으로 확인

    재부팅하면 0번·1번 순서가 바뀔 수 있습니다. 한쪽 웹캠을 손으로 가리고, 그 창의 사람 수가 0이 되는지 봅니다.

    STEP 2 · 비전 담당

    검출기 파일 확인 — vision/detectors/subway_cars.py

    새로 만들 필요 없이 이미 들어 있습니다. 무엇을 보내는지만 알고 넘어갑니다.

    이 검출기가 보내는 것 (창 하나당)

    칸값예
    label몇 번 칸 — car_1 또는 car_2car_1
    count보이는 사람 수3
    extra.people사람 수 (count와 같음)3
    extra.level혼잡 단계 0 여유 · 1 보통 · 2 혼잡 · 3 매우 혼잡1

    "어느 칸이 덜 붐비니 그쪽으로 안내"하는 판단은 검출기가 아니라 프론트엔드 화면이 합니다.

    고칠 수 있는 곳은 숫자 두 개뿐 (선택)

    vision/detectors/subway_cars.py
    # 사람이 2명 이상이면 1단계(보통), 4명 이상 2단계(혼잡), 6명 이상 3단계(매우 혼잡)
LEVELS = (2, 4, 6)

#: 사람으로 인정할 최소 확신도. 사람이 아닌 것을 사람으로 세면 올리세요.
MIN_PERSON_CONFIDENCE = 0.5
    언제 고치나

    칸 모형이 작아 2~3명만 보여도 붐비는 느낌이면 LEVELS = (1, 2, 3)처럼 낮춥니다. 고친 뒤에는 비전 창을 껐다 켭니다(Q → 다시 실행).

    고치지 않는 것

    vision/main.py · camera.py · detectors/base.py · detectors/objects.py (4팀 공통)

    vision/.env에 한 줄 추가 — 창 ①의 설정

    1. VS Code에서 vision/.env 열기없으면 vision/.env.example을 복사해 .env로 만듭니다(설치 때 이미 했다면 그대로).
    2. 아래 네 줄이 맞는지 보고, 마지막 줄을 추가
      vision/.env (확인할 줄 + 추가할 줄)
      BACKEND_URL=http://localhost:8000
DEVICE_API_KEY=(backend/.env와 똑같은 값 — 이미 들어 있음)

      저장(Ctrl+S).

    창 ②(2번 칸)는 5단계에서 그 창에서만 값을 바꿔 실행합니다. .env를 두 개 만들지 않습니다.

    1단계 결과가 [0, 1, 2]였다면

    내장 카메라가 0번이므로 여기를 CAMERA_INDEX=1, 5단계에서 "2"로 씁니다.

    이 파일은 비밀값이 있어 커밋하지 않고, AI 채팅에 붙여넣지 않습니다

    git status 목록에 vision/.env가 보이면 멈춥니다.

    철자를 틀리면(car1, car_3) 창에 SUBWAY_CAR='car_3'는 쓸 수 없습니다. car_1, car_2 중 하나로 적으세요.가 나오고 칸 정보를 보내지 않습니다.

    STEP 4 · 비전 담당

    창 ① 켜기 — 웹캠 0번 = 1번 칸

    백엔드(uvicorn)가 먼저 켜져 있어야 합니다. 비전용 PowerShell 창을 새로 엽니다.

    PowerShell 창 ① · 저장소 맨 위
    cd vision
.\venv\Scripts\Activate.ps1
python main.py

    이렇게 되면 성공 — 창에 찍히는 글

    창 ① 출력 (일부)
     [IoT 플랫폼 키트 - 영상인식 클라이언트]
 * 카메라   : USB 웹캠 #0
 * 백엔드   : http://localhost:8000
 * 검출기:
     [O] objects      사물·사람 감지 (YOLOv8)
     [O] subway_cars  객차별 사람 수·혼잡 단계 (subway 팀)

    [O] subway_cars가 보이는 것이 중요합니다. 다른 팀 검출기 줄(hands_rps·study_…)도 함께 보이는 것은 정상입니다.

    영상 창(IoT Kit Vision)에서 볼 것

    • 맨 위 두 번째 줄(노란색)에 car_1: 3명 (혼잡 단계 1)처럼 칸 이름과 사람 수가 보입니다.
    • 오른쪽 위에 백엔드 OK (초록).
    • 웹캠을 손으로 가리면 → car_1: 0명. 이 창이 1번 칸 웹캠인지 이렇게 확인합니다.
    상태 줄에 car_1이 안 보이면

    ① vision/.env의 SUBWAY_CAR=car_1 저장 확인 → 창을 Q로 끄고 다시 실행. ② 6단계에서 subway_cars 체크가 꺼져 있지 않은지.

    이 창은 끄지 않습니다

    창을 닫으면 1번 칸 소식이 끊깁니다. 다음 단계는 새 PowerShell 창에서 합니다.

    STEP 5 · 비전 담당

    창 ② 켜기 — 웹캠 1번 = 2번 칸 (새 PowerShell 창에서)

    새 PowerShell 창 ② · 저장소 맨 위
    cd vision
.\venv\Scripts\Activate.ps1
$env:CAMERA_INDEX="1"; $env:SUBWAY_CAR="car_2"; python main.py

    셋째 줄은 한 줄로 붙여넣습니다. $env:로 정한 값은 이 창에서만 .env보다 먼저 쓰입니다 — 창 ①은 그대로 car_1입니다.

    이렇게 되면 성공

    • 창 ② 출력: * 카메라 : USB 웹캠 #1
    • 영상 창 상태 줄: car_2: 2명 (혼잡 단계 1)
    • 영상 창이 2개 떠 있고(이름은 둘 다 IoT Kit Vision), 상태 줄이 하나는 car_1, 하나는 car_2
    창 ②를 껐다가 다시 켤 때

    같은 창이면 위쪽 화살표(↑)로 셋째 줄을 다시 실행합니다. PowerShell 창을 새로 열었다면 $env: 값이 사라졌으니 세 줄을 모두 다시 붙여넣습니다. 빠뜨리면 창 ②도 car_1이 되어 두 창이 같은 칸을 보냅니다.

    확인: 손으로 가리기

    2번 칸 웹캠을 가리면 car_2만 0명이 되어야 합니다. car_1이 0이 되면 칸과 번호가 뒤바뀐 것 → 창 ①의 .env CAMERA_INDEX와 창 ②의 "1"을 서로 바꿉니다.

    느려지면

    사람 찾기가 두 번 돌아 CPU를 두 배로 씁니다. 화면이 많이 끊기면 vision/.env에 CAMERA_WIDTH=320, CAMERA_HEIGHT=240을 추가하고 두 창을 다시 켭니다.

    STEP 6 · 비전 담당

    영상인식 설정에서 subway_cars 하나만 켜기

    1. 브라우저 http://localhost:3000/kit → 영상인식 설정 탭
    2. "검출기 (감지 방법)" 칸에서객차별 사람 수·혼잡 단계 (subway 팀) subway_cars만 체크된 상태로 만듭니다. 나머지(사물·사람 감지 objects, 좌석별 점유 study_seats, 가위바위보 hands_rps, 한 사람 집중도 study_focus)는 클릭해서 체크를 뺍니다.
    3. 초록 글씨 확인저장했습니다. 비전 클라이언트가 몇 초 안에 반영합니다. — 두 창 모두 5초 안에 자동 반영됩니다(비전 창을 다시 켤 필요 없음).
    왜 하나만 켜나
    • objects가 켜져 있으면 두 창이 모두 칸 구분 없는 person을 보내 화면이 헷갈립니다.
    • 시험에서 objects를 함께 켰더니 1번 칸 사람 수가 3명 → 2명으로 덜 세어졌습니다.
    • CPU도 아낍니다.

    시험한 PC 화면입니다. 회색으로 사용할 수 없음이 붙은 줄은 그 PC에 MediaPipe가 없어서 그렇고, 팀 PC에서는 보통 체크할 수 있습니다 — 그것도 빼세요.

    STEP 7 · 비전 담당 → 프론트 담당에게 알리기

    감지 로그에 car_1·car_2가 번갈아 오면 비전 쪽 끝

    1. /kit → 대시보드 탭 → 맨 아래 "영상인식 감지 로그"
    2. car_1 개수 3, car_2 개수 2 같은 줄이 약 2.5초마다 쌓이면 성공개수는 그 칸에 보이는 사람 수입니다. 같은 상태가 이어지면 "보고 간격"(기본 2.5초)마다 다시 보냅니다.
    3. 프론트 담당에게 알리기"라벨 car_1·car_2, 사람 수 extra.people, 단계 extra.level (0~3)로 와."
    사람 수가 실제보다 적으면

    웹캠을 칸 전체가 보이게 조금 높이·뒤로. 그래도 적으면 5번 슬라이드의 MIN_PERSON_CONFIDENCE를 0.4로 낮춥니다.

    감지 로그 예 (car_1 개수 7·3, car_2 개수 2)

    STEP 8 · 프론트 담당

    웹캠 없이 시험하기 — 가짜 영상 이벤트 보내기

    비전 창이 켜져 있으면 진짜 값이 2.5초마다 덮어씁니다. 이 시험은 비전 창 2개를 Q로 끈 상태에서 합니다.

    팀 PC · PowerShell · 저장소 맨 위 (한 창에서 차례로)
    # 1) 준비 — 키를 화면에 치지 않도록 backend/.env에서 읽어 옴
$key = (Get-Content backend\.env | Select-String '^DEVICE_API_KEY=').Line.Split('=', 2)[1].Trim()
$v = "http://localhost:8000/api/v1/vision/events"
$h = @{ "X-Device-Api-Key" = $key }

# 2) 1번 칸 7명(매우 혼잡) · 2번 칸 2명(보통)
Invoke-RestMethod -Method Post -Uri $v -Headers $h -ContentType "application/json" -Body '{"event_type":"car_crowd","detected":true,"count":7,"label":"car_1","extra":{"people":7,"level":3}}'
Invoke-RestMethod -Method Post -Uri $v -Headers $h -ContentType "application/json" -Body '{"event_type":"car_crowd","detected":true,"count":2,"label":"car_2","extra":{"people":2,"level":1}}'

# 3) 바꿔 보기 — 1번 칸 1명(여유) · 2번 칸 5명(혼잡)
Invoke-RestMethod -Method Post -Uri $v -Headers $h -ContentType "application/json" -Body '{"event_type":"car_crowd","detected":true,"count":1,"label":"car_1","extra":{"people":1,"level":0}}'
Invoke-RestMethod -Method Post -Uri $v -Headers $h -ContentType "application/json" -Body '{"event_type":"car_crowd","detected":true,"count":5,"label":"car_2","extra":{"people":5,"level":2}}'
    성공

    결과에 recorded=True와 label=car_1(또는 car_2). /kit 감지 로그에도 쌓입니다.

    두 줄을 10초 안에

    화면은 10초 넘게 소식이 없는 칸을 "카메라 소식 없음"으로 봅니다(우리가 정할 규칙). 두 칸 줄을 연달아 보냅니다.

    401 / 인증 실패

    backend\.env의 키를 읽지 못함 → 저장소 맨 위에서 실행했는지 확인.

    scenarios/useSubwayCars.ts — 칸 이벤트 받기
    useEffect(
  () =>
    onVision(CARS, (e) => {                     // CARS = ["car_1", "car_2"]
      const id = String(e.label ?? "") as CarId;
      if (!CARS.includes(id)) return;
      const people = typeof e.extra?.people === "number" ? e.extra.people : (e.count ?? 0);
      const level = typeof e.extra?.level === "number" ? e.extra.level : 0;
      setCars((prev) => ({ ...prev, [id]: { people, level, at: Date.now() } }));
    }),
  [onVision]
);
    scenarios/subwayCarsEngine.ts — 비교 판정 (React 없이)
    export function recommendCar(cars: Cars, now: number): CarId | null {
  const a = cars.car_1;
  const b = cars.car_2;
  if (!isLive(a, now) || !isLive(b, now)) return null;   // 10초 넘게 소식 없음
  if (a.people === b.people) return null;                // 같으면 안내 안 함
  return a.people < b.people ? "car_1" : "car_2";
}
    이러면 고쳐 달라고 하기

    onVision(null, …)처럼 모든 이벤트를 받거나, e.label === "person"을 보면 칸 구분이 안 됩니다 → "car_1·car_2 라벨만 받아 줘".

    이것도

    e.confidence로 사람 수를 읽으면 틀립니다(칸 이벤트는 confidence가 없음) → "사람 수는 extra.people".

    이것도

    "1초마다 시계" 없이 시간을 비교하면 소식이 끊겨도 화면이 그대로입니다 → "10초 소식 없음이 안 바뀌어".
