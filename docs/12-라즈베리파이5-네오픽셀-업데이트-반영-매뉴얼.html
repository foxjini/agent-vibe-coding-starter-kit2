    RASPBERRY PI 5 · NEOPIXEL UPDATE

    12 네오픽셀 업데이트 반영하기
    플랫폼 수정을 우리 파이에 가져오기

    플랫폼(키트)에서 라즈베리파이 5용 네오픽셀 연결 방법을 고쳤습니다. 우리 팀 PC와 파이에 이 수정을 가져와, 네오픽셀이 흉내내기가 아니라 실제로 켜지게 만듭니다. 한 단계를 끝내고 눈으로 확인한 다음 넘어갑니다.

    꼭 할 팀 wakeup · classroom (네오픽셀 · 온습도) 파일만 받을 팀 study · subway 누가 1단계 팀 PC 담당 · 2~6단계 파이 담당 시간 30분 안팎 (파이 업데이트가 필요하면 +20분)
    우리 팀이 만든 것은 그대로입니다

    배치표 pi/slot_map.py, 비밀값 .env, 파이의 venv 폴더는 덮어쓰지 않습니다. 바뀌는 것은 키트가 주는 파일(데몬과 드라이버)뿐입니다.

    이 매뉴얼의 "고쳐야 할 것" 문구는 키트의 점검 코드(pi/drivers/libcheck.py)가 실제로 출력하는 그대로입니다.

    WHAT CHANGED

    무엇이 바뀌었나

    예전 안내는 라즈베리파이 4 방식이었습니다. 라즈베리파이 5는 핀을 다루는 칩(RP1)이 달라서 그 방식으로는 네오픽셀이 켜지지 않습니다.

    라이브러리rpi_ws281xadafruit-blinka-raspberry-pi5-neopixel (파이 5 전용)
    데몬 실행sudo python daemon.pypython daemon.py (sudo 없이)
    필요한 것—파이에 /dev/pio0 장치가 있어야 함 (최신 펌웨어)
    문제를 알려 주는 곳없음 — 데몬은 도는데 LED만 가만히 있음python daemon.py --check의 "고쳐야 할 것"에 원인과 설치 명령이 나옴

    바뀐 키트 파일 (덮어씀)

    pi/daemon.py · pi/drivers/ 폴더(libcheck.py 새로 생김, neopixel_out.py, dht_in.py 등) · pi/requirements.txt

    우리 팀 파일 (그대로)

    pi/slot_map.py · pi/.env · 파이의 venv/ — 1단계 git pull도, 2단계 복사도 이 파일들은 건드리지 않습니다.

    STEPS

    전체 순서 — 6단계 (괄호 안은 슬라이드 번호)

    1. 팀 PC에서 받기git pull (4)
    2. 파이로 보내기WinSCP (5)
    3. 파이 장치 확인/dev/pio0 (6)
    4. venv에 설치pip install (7)
    5. 점검--check (8)
    6. 켜고 LED 보기/kit (9)

    규칙 1 · sudo 쓰지 않기

    pip 설치와 데몬 실행에 sudo를 붙이지 않습니다. sudo가 필요한 곳은 3단계(파이 업데이트)뿐입니다.

    규칙 2 · (venv) 확인

    파이 터미널 줄 앞에 (venv)가 보일 때만 pip을 실행합니다. 없으면 source venv/bin/activate.

    규칙 3 · 막히면 표부터

    출력 첫 줄을 읽고 10번 슬라이드(증상으로 찾기) → 선생님. AI에 물을 때 .env 내용은 붙이지 않습니다.

    1. 팀 PC에서 받기 — git pull

    1. 내 작업부터 저장(커밋)
      팀 PC · PowerShell · 저장소 맨 위

git add -A
git commit -m "[작업] 업데이트 받기 전 저장"

      nothing to commit이 나오면 이미 깨끗한 것이니 넘어갑니다. .env·.env.local·venv는 git이 원래 건드리지 않습니다.

    2. 플랫폼 수정 받기
      팀 PC · PowerShell · 저장소 맨 위
      git pull --no-rebase --no-edit origin platform
    3. 받았는지 확인
      팀 PC · PowerShell
      Test-Path pi\drivers\libcheck.py

      True가 나오면 성공입니다.

    STEP 2 · 파이 담당 PC → 파이

    2. 파이로 보내기 — 세 가지만 덮어쓰기

    3. 내 PC → 파이 (WinSCP): 왼쪽 C:\pi-work\pi → 오른쪽 /home/사용자이름/iot-kit/pi/로 같은 세 가지를 끌어 놓기 → 덮어쓰기 예
    보낼 것 ○보내지 않을 것 ✕
    daemon.pyslot_map.py — 파이에 있는 것이 진짜

    requirements.txtvenv 폴더 — 윈도우용이라 파이 venv가 망가짐
    확인

    WinSCP 오른쪽 drivers 폴더 안에 libcheck.py가 보이면 성공입니다.

    study · subway 팀은 여기까지 하고 5단계(8번 슬라이드)의 --check만 해 봅니다(네오픽셀·온습도가 없으면 3·4단계는 건너뜀).

    STEP 3 · 파이 (한 번만)

    3. 네오픽셀용 장치 /dev/pio0 확인

    파이 5의 네오픽셀 라이브러리는 /dev/pio0라는 장치를 씁니다. 파이 펌웨어가 오래됐으면 이 장치가 없습니다.

    파이 터미널
    ls -l /dev/pio0
groups
    이렇게 나오면 통과 → 4단계로

    crw-rw---- 1 root gpio … /dev/pio0 같은 줄이 보이고, groups 결과에 gpio가 있음

    "No such file or directory"가 나오면 — 파이 업데이트

    파이 터미널 · 인터넷 연결 필요 · 10~20분
    sudo apt update && sudo apt full-upgrade -y
sudo rpi-eeprom-update -a
sudo reboot

    장치는 있는데 root root로 나오면 — 권한 주기

    파이 터미널
    echo 'SUBSYSTEM=="*-pio", GROUP="gpio", MODE="0660"' | sudo tee /etc/udev/rules.d/99-pio.rules
sudo reboot

    다시 켠 뒤 맨 위 두 명령으로 다시 확인합니다.

    STEP 4 · 파이

    4. venv에 라이브러리 설치 (sudo 없이)

    파이 터미널 · 폴더 이름은 우리 팀 것으로
    cd ~/iot-kit/pi
source venv/bin/activate
pip install adafruit-circuitpython-neopixel "gpiod>=2.2.2,<3"
pip install --pre adafruit-blinka-raspberry-pi5-neopixel

    줄 앞에 (venv)가 붙은 것을 확인한 뒤 pip을 실행합니다. 마지막 줄의 --pre는 꼭 붙입니다(아직 정식판이 없는 파이 5 전용 라이브러리).

    이렇게 되면 성공

    마지막에 Successfully installed …. 이미 깔려 있으면 Requirement already satisfied — 그것도 정상입니다.

    온습도(DHT) 센서도 쓰는 팀 (classroom)

    같은 파이 터미널 · (venv)
    pip install adafruit-circuitpython-dht "gpiod>=2.2.2,<3"
    예전 방식으로 설치했었다면

    예전에 sudo pip install … --break-system-packages를 했어도 지우지 않아도 됩니다. 대신 앞으로 데몬을 sudo로 켜지 않습니다. 자동 실행 서비스(iot-daemon)는 원래 내 사용자로 돌기 때문에 그대로 두면 됩니다.

    pip이 Python.h나 gcc 오류로 멈추면 sudo apt install -y python3-dev 뒤 같은 pip 명령을 다시 합니다.

    STEP 5 · 파이

    5. 점검 — "고쳐야 할 것"이 없으면 통과

    파이 터미널 · (venv)
    python daemon.py --check
    통과

    배치표 슬롯 목록이 나오고, 그 아래에 ⚠ 고쳐야 할 것 줄이 없습니다. 네오픽셀 슬롯(예: wakeup actuator_04 조명, classroom actuator_03)이 목록에 있는지도 봅니다.

    PC에서 --check를 하면 라이브러리 점검은 건너뜁니다(PC에는 네오픽셀이 없으니 정상). 라이브러리 점검은 파이에서만 합니다.

    아직 문제가 있으면 — 이렇게 알려 줍니다 (실제 출력)

    --check 출력의 끝부분 예시
     ⚠ 고쳐야 할 것 5개 (이 줄만 빼고 나머지는 동작합니다)
   · actuator_04 네오픽셀: 라이브러리를 쓸 수 없어 실제 부품 대신 흉내내기로 돕니다 — No module named 'neopixel'
   · 네오픽셀: /dev/pio0이 없습니다 (파이 5 펌웨어가 오래됨) → sudo apt update && sudo apt full-upgrade -y && sudo rpi-eeprom-update -a 후 sudo reboot
   · 설치 — (venv)가 켜진 파이 터미널에서: pip install adafruit-circuitpython-neopixel
   · 설치 — 이어서: pip install --pre Adafruit-Blinka-Raspberry-Pi5-Neopixel
   · 설치한 뒤: python daemon.py --check 로 이 줄들이 사라졌는지 확인 → 데몬 다시 켜기

    "설치 —" 줄의 명령을 그대로 복사해 실행하고 --check를 다시 합니다. 줄이 다 사라질 때까지 반복.

    STEP 6 · 파이 + 화면

    6. 데몬 켜고 실제 LED 확인

    파이 터미널 · 자동 실행을 등록한 팀
    sudo systemctl restart iot-daemon
journalctl -u iot-daemon -n 20 --no-pager
    파이 터미널 · 손으로 켜는 팀 (venv)
    python daemon.py
    이 줄이 보이면 아직 흉내내기입니다

    네오픽셀 라이브러리를 쓸 수 없어 실제 LED 대신 색을 로그로만 표시합니다 → 5단계로 돌아가 --check.

    1. 화면에서 켜기: 브라우저로 http://팀PC주소:3000/kit → 네오픽셀 슬롯 카드 → 켜기(색 고르기)
    2. LED 보기: 고른 색으로 켜지면 성공. 데몬 창에도 [actuator_…] … → on RGB(…) 같은 줄이 나옵니다
    3. 팀 시나리오: wakeup은 /wakeup 제어 탭 → 조명 "새벽빛", classroom은 팀 화면의 조명 동작으로 한 번 더
    끝 — 팀 PC 기록

    파이에서 slot_map.py를 고치지 않았다면 팀 PC에서 따로 커밋할 것은 없습니다(1단계에서 이미 받음). 고쳤다면 평소처럼 USB로 가져와 커밋합니다.

    CHECKLIST

    다 했는지 확인

    팀 PC 담당

    • ☐ 업데이트 전에 내 작업을 커밋했다
    • ☐ git pull --no-rebase --no-edit origin platform 성공
    • ☐ Test-Path pi\drivers\libcheck.py → True

    파이 담당

    • ☐ daemon.py · drivers 폴더 · requirements.txt만 파이에 덮어썼다 (slot_map.py · .env · venv는 그대로)
    • ☐ ls -l /dev/pio0에 장치가 보인다
    • ☐ (venv)에서 네오픽셀 라이브러리 두 줄을 설치했다 (classroom은 온습도도)
    • ☐ python daemon.py --check에 "고쳐야 할 것"이 없다
    • ☐ /kit에서 켠 색으로 실제 LED가 켜진다
    왜 이렇게 바뀌었나 (한 문단)

    라즈베리파이 5는 핀을 다루는 칩이 RP1으로 바뀌어, 예전 네오픽셀 라이브러리(rpi_ws281x)가 동작하지 않습니다. 대신 RP1 안의 PIO라는 작은 프로세서를 쓰는 전용 라이브러리를 씁니다. 이 라이브러리는 sudo 없이 동작하므로 venv에 설치하고, 데몬도 sudo 없이 켭니다.
