01내가 맡은 일 — 파이는 시스템에서 무엇을 하나

라즈베리파이는 우리 시스템의 손과 귀입니다. 무엇을 할지는 백엔드와 대시보드가 정하고, 파이는 그 명령대로 부품을 움직이고 센서를 읽어서 알려 줍니다.

대시보드

PC 브라우저 · localhost:3000

  • "켜기" 버튼
  • 카드에 상태 표시
⇄명령 / 상태

백엔드

PC · FastAPI · :8000

  • 내린 명령 보관
  • 하드웨어 보고 기록
  • 자동화 규칙 실행
⇄Wi-Fi

  • ↓

"켜기"를 눌렀을 때 일어나는 일

  1. 대시보드에서 켜기를 누르면 백엔드에 내린 명령(on)이 적힙니다.
  2. 파이의 데몬(daemon.py)이 1초마다 백엔드에 "할 일 있나요?" 하고 물어봅니다.
  3. 데몬이 명령을 받으면 배치표(slot_map.py)를 보고, 그 부품의 드라이버로 GPIO 핀에 신호를 보냅니다 → 부저가 울립니다.
  4. 데몬이 "켰습니다"라고 보고하면 백엔드가 하드웨어 보고(on)를 기록하고, 대시보드 카드가 동작 중으로 바뀝니다.

센서는 방향이 반대입니다. 데몬이 버튼·온도 같은 센서를 읽어 백엔드에 보고하면, 대시보드가 값을 보여 주고 자동화 규칙이 그 값을 씁니다.

비유하면

백엔드는 식당의 주문판, 데몬은 1초마다 주문판을 확인하는 직원입니다. 주문판에 "부저 켜기"가 적히면 직원이 부엌(부품)에 전하고, 주문판 옆에 "켰음"이라고 적어 둡니다. 대시보드는 그 주문판을 보여 주는 화면입니다. 직원이 자리를 비우면(데몬이 꺼지면) 주문은 쌓이기만 합니다.

왜 백엔드가 파이에게 직접 명령하지 않나요

파이는 IP 주소가 자주 바뀌고, 학교 네트워크에서는 밖에서 파이로 접속하기 어렵습니다. 그래서 파이가 먼저 물어보는 방식(폴링)을 씁니다. 파이만 백엔드 주소를 알면 됩니다.

내가 고치는 곳은 한 파일뿐입니다

이 키트는 4개 팀(wakeup · classroom · study · subway)이 같이 씁니다. 공통 파일을 고치면 다른 팀 시스템이 멈춥니다.

✓ 내가 고치는 것

  • pi/slot_map.py — 배치표
  • pi/.env — 백엔드 주소·인증키 (커밋하지 않음)

✕ 고치지 않는 것

  • pi/daemon.py — 공통 루프
  • pi/drivers/ — 부품 드라이버
  • pi/slot_config.py — 검사기
  • backend/ · frontend/ · vision/
왜 이렇게 만들었나

부품을 바꿀 때마다 백엔드와 화면을 같이 고쳐야 한다면, 팀마다 코드가 갈라져서 나중에 합칠 수 없게 됩니다. 그래서 "어디에 무엇을 꽂았는가"만 배치표에 적고, 나머지는 전부 키트가 알아서 하도록 만들었습니다.

배치표를 고치면 자동으로 일어나는 일

내가 한 일자동으로 일어나는 일
배치표에 한 줄 추가대시보드에 카드가 생기고, 종류에 맞는 조작 위젯이 붙습니다
배치표에서 한 줄 삭제대시보드에서 사라집니다 (기록은 남습니다)
label 수정대시보드 이름이 바뀝니다
unit 추가센서값 옆에 단위가 붙고 차트가 그려집니다
driver 교체조작 방법이 바뀝니다 (켜기/끄기 → 세기 조절 등)

단, 데몬을 다시 켜야 반영됩니다. 데몬은 시작할 때 배치표를 한 번 읽습니다.

02꼭 알아야 할 낱말

이 문서와 화면 메시지에 계속 나오는 말입니다. 모르는 말이 나오면 여기로 돌아오세요.

라즈베리파이 5
신용카드만 한 컴퓨터. 리눅스(Raspberry Pi OS)가 돌고, 가장자리의 핀 40개로 부품을 직접 제어합니다.
GPIO General Purpose I/O
프로그램으로 켜고 끄거나(출력) 상태를 읽을 수 있는(입력) 핀. 전압은 3.3V입니다.
BCM 번호 · 물리 번호
같은 핀을 부르는 두 가지 이름. 배치표에는 BCM(GPIO) 번호, 손으로 꽂을 때는 물리 번호(1~40번 자리)를 봅니다 → 08
액추에이터 actuator
움직이거나 소리·빛을 내는 부품 — 부저, LED, 모터, 서보, 릴레이.
센서 sensor
무언가를 재서 알려 주는 부품 — 버튼, 터치, 온도, 거리, 압력.
슬롯
부품이 들어갈 고정 자리. actuator_01~10, sensor_01~10 모두 20칸. 이름은 바꿀 수 없습니다.
배치표 slot_map.py
"어느 슬롯에, 어떤 부품을, 몇 번 핀에 꽂았나"를 적은 표. 내가 고치는 유일한 코드입니다.
드라이버
부품 종류별로 "어떻게 다루는지"를 담은 파일(pi/drivers/). 11종이 들어 있어 이름만 고르면 됩니다.
데몬 daemon.py
켜 두면 끝없이 돌면서 백엔드와 주고받는 프로그램. 끄려면 Ctrl+C. 고치지 않습니다.
내린 명령 · 하드웨어 보고
대시보드 카드의 두 칸. 명령(desired)은 대시보드·규칙이 정하고, 보고(current)는 파이가 실제로 반영한 뒤에만 바뀝니다.
폴링 polling
정해진 간격(1초)마다 "할 일 있나요?" 하고 물어보는 방식.
흉내내기 모드 Mock
GPIO가 없는 PC에서 부품 대신 로그만 찍으며 도는 상태. PC에서는 정상, 파이에서 뜨면 문제입니다.
.env 파일
백엔드 주소·인증키처럼 컴퓨터마다 다른 값을 적는 파일. 깃허브에 올라가지 않습니다(올리면 안 됩니다).
가상환경 venv
이 프로젝트용 파이썬 패키지를 따로 담아 두는 폴더. 파이에서 터미널을 열 때마다 켜야 합니다 → 05
SSH
내 PC에서 파이의 터미널을 원격으로 쓰는 방법. 모니터·키보드 없이 작업할 수 있습니다.
IP 주소
같은 Wi-Fi 안에서 컴퓨터를 찾는 번지수(예: 192.168.0.25). 공유기가 정해 주므로 장소가 바뀌면 바뀔 수 있습니다.
PWM
아주 빠르게 켰다 껐다 해서 '세기'를 만드는 방법. LED 밝기, 모터 세기, 부저 음높이에 씁니다.
풀업 pull_up
버튼을 안 눌렀을 때 핀을 3.3V 쪽으로 붙잡아 두는 것. 버튼 종류마다 True/False가 다릅니다.
능동 · 수동 부저
능동(active)은 전기만 주면 정해진 소리, 수동(passive)은 파이가 주파수를 만들어 줘야 소리가 납니다. 피에조 부저는 보통 수동입니다.
ADC
아날로그 전압을 숫자로 바꾸는 칩. 파이에는 없어서 압력·조도 센서는 MCP3008 같은 칩을 거칩니다.

03혼자 진행하는 순서 — 6단계

한 번에 다 연결하면 안 될 때 어디서 틀렸는지 찾을 수 없습니다. 한 단계씩 끝내고, 성공 기준을 눈으로 확인한 다음 넘어가세요. 단계마다 바뀌는 것이 하나뿐이라, 문제가 생기면 방금 바꾼 그것이 원인입니다.

  1. PC에서 흉내내기로 돌려 보기 — 파이·배선 없음 · 04

    ✓ 성공 기준

    대시보드에서 켜기를 누르면 PC의 데몬 창에 알람 부저 → on이 찍힌다.

  2. 파이 준비하고 접속하기 — 05

    ✓ 성공 기준

    파이에서 python daemon.py --check를 돌리면 하드웨어 : 실기기 GPIO가 나온다.

  3. 파이와 PC 연결하기 — 아직 배선 없음 · 06

    ✓ 성공 기준

    대시보드에서 켜기 → 카드 배지가 동작 중, 파이 터미널에 알람 부저 → on.

  4. 부품 하나 배선하기 — 07 · 08 · 09

    ✓ 성공 기준

    대시보드 켜기/끄기로 실제 소리가 나고 멈춘다. 버튼을 누르면 카드에 눌림.

  5. 부품을 하나씩 늘리기 — 10~14

    ✓ 성공 기준

    부품을 하나 추가할 때마다 20의 "부품을 바꿀 때마다" 체크리스트를 모두 통과한다.

  6. 팀과 합치고 전시 준비 — 19

    ✓ 성공 기준

    파이 전원만 꽂으면 데몬이 저절로 켜지고, 팀 화면의 시나리오(알람·미션)대로 부품이 움직인다.

하드웨어 규칙 — 꼭 지킵니다
  • 실기기에 연결하기 전에 흉내내기(Mock)에서 먼저 확인합니다 — 그래서 1단계가 PC입니다.
  • 배선은 전원을 끈 상태에서만 바꿉니다.
  • 실기기 첫 연결(4단계에서 처음 전원을 넣을 때)은 선생님 입회 하에 합니다.

041단계 — PC에서 먼저 해 보기 (흉내내기)

파이도 배선도 없이, 내 윈도우 PC에서 데몬을 돌려 봅니다. 여기서 되면 배치표와 키 설정은 맞다는 뜻이고, 나중에 문제가 생겨도 원인을 배선·네트워크로 좁힐 수 있습니다.

  1. 준비 (팀에서 한 번)

    저장소 받기와 .env 복사는 00 통합 매뉴얼 2장대로 합니다. 그다음 pi 폴더의 패키지를 설치합니다.

    pi/.env를 열어 두 줄을 확인합니다. PC에서 돌릴 때만 주소가 localhost입니다.

  2. 백엔드와 대시보드 켜기

    백엔드 담당이 이미 켜 둔 PC라면 건너뜁니다. 직접 켤 때는 창 두 개를 엽니다.

  3. 데몬 켜기

    PC에는 GPIO가 없으니 흉내내기 모드가 정상입니다. 창은 닫지 말고 그대로 둡니다 — 데몬은 계속 돌아야 합니다.

  4. 대시보드에서 눌러 보기

    브라우저에서 http://localhost:3000/kit → 대시보드 탭 → 알람 부저 카드의 켜기를 누릅니다. 데몬 창에 이런 줄이 생기면 성공입니다.

  5. 끄기

    데몬 창에서 Ctrl+C. 종료 신호를 받았습니다. 부품을 끄고 정리합니다...가 나오고 끝납니다.

✓ 1단계 성공 기준
  • 데몬 창에 백엔드에 연결되었습니다와 [배치표 등록] 사용 슬롯 2개가 나왔다
  • 켜기·끄기를 누를 때마다 → on / → off 줄이 생겼다

안 되면 → 15 오류 사전에서 창에 나온 문장을 찾으세요. 인증 실패!가 보이면 두 .env의 키가 다른 것입니다.

07배선 기초와 안전

처음 배선하는 학생이 알아야 할 것만 모았습니다. 부품별 연결 방법은 12의 카드마다 배선 줄에 있습니다.

안전 수칙 — 파이를 지키는 7가지
  1. 꽂거나 뺄 때는 전원을 끕니다 (sudo poweroff → 불 꺼짐 → 전원선 뽑기).
  2. GPIO는 3.3V입니다. 5V를 GPIO 핀에 직접 넣으면 핀이 상합니다.
  3. 5V 핀과 GND를 바로 잇지 않습니다 (합선 — 파이가 꺼지거나 고장 납니다). 3V3과 GND도 마찬가지입니다.
  4. LED에는 반드시 저항(220~330Ω)을 거칩니다.
  5. 모터·여러 개의 서보·긴 LED 스트립처럼 전류를 많이 쓰는 부품은 파이 핀에서 직접 전원을 뽑지 않고 별도 전원을 씁니다 (GND는 파이와 이어 줍니다).
  6. 릴레이로 220V 가정용 전기를 켜고 끄지 않습니다. 전시용은 건전지·USB 전원 부품으로 충분합니다.
  7. 처음 전원을 넣을 때는 선생님이 배선을 확인한 뒤 켭니다. 타는 냄새·뜨거움이 느껴지면 즉시 전원선을 뽑습니다.

브레드보드 — 구멍끼리 어떻게 이어져 있나

  • 가운데 홈을 사이에 두고, 한 줄(구멍 5개)이 안에서 이어져 있습니다. 같은 줄에 꽂은 다리끼리는 전선 없이 연결됩니다.
  • 가장자리의 빨강(+)·파랑(−) 긴 줄은 전원용입니다. 3.3V와 GND를 한 번씩 끌어다 놓고 여러 부품이 나눠 씁니다. (가운데가 끊긴 제품도 있으니 확인하세요)
  • 부품 다리 두 개를 같은 줄에 꽂으면 그 부품은 양쪽이 이어져 동작하지 않습니다. 버튼·LED는 가운데 홈을 가로질러 꽂습니다.

    PC 브라우저 /kit → 알람 부저 → 켜기. 소리가 나고, 끄기를 누르면 멈추면 성공입니다.

    소리가 안 날 때 — 이 순서로
    1. 파이 터미널에 알람 부저 → on이 찍혔나요? 안 찍혔으면 배선이 아니라 연결 문제입니다 → 06
    2. 찍혔는데 조용하거나 "틱"만 나면: Ctrl+C → nano slot_map.py → "buzzer_type": "active"로 바꾸고 저장 → python daemon.py → 다시 켜기
    3. 그래도 안 나면 전원을 끄고 물리 12번에 꽂았는지, +와 −가 바뀌지 않았는지 봅니다

    파이에서 slot_map.py를 고쳤다면 나중에 PC의 파일에도 똑같이 반영하세요 → 11

11부품 추가하기 — 고치는 흐름

배치표는 PC에서 고치고 깃허브로 파이에 보냅니다. 고치는 곳을 한 군데로 정해 두면, 파이와 PC의 파일이 서로 달라지는 일이 없습니다.

  1. 배선하고 GPIO 번호를 적어 둡니다

    전원을 끄고 연결하세요. 어느 GPIO에 꽂았는지 종이에 적어 둡니다 — 08의 배치도에서 BCM 번호를 확인하세요.

  2. PC에서 slot_map.py에 한 줄 추가합니다

    빈 슬롯 번호를 하나 골라 적습니다. 12에서 부품에 맞는 코드를 복사해 오세요. 파일 아래쪽에 #로 막아 둔 예시가 있다면 #만 지워서 써도 됩니다.

  3. PC에서 먼저 확인합니다 (파이 없이)

    고쳐야 할 것이 없고, 새 부품이 목록에 나오면 다음으로 갑니다.

  4. 커밋·푸시합니다

    평소 쓰는 방법(소스 제어 화면 또는 명령)으로 우리 팀 브랜치에 올립니다.

    올리기 전에 .env가 목록에 없는지 확인합니다 (git status). git push가 rejected되면 프론트엔드 담당이 먼저 올린 것이니 git pull 후 다시 git push합니다. 슬롯 이름이나 control_type을 바꿨다면 프론트엔드 담당에게 알립니다 (18).

  5. 파이에서 받고, 확인하고, 데몬을 다시 켭니다

    대시보드(localhost:3000)를 새로고침하면 카드가 나타납니다. 켜기를 눌러 실제 부품이 움직이는지 봅니다.

파이에서 nano로 바로 고쳤다면

배선하면서 급히 고치는 것은 괜찮습니다. 다만 동작을 확인한 뒤 같은 내용을 PC 파일에도 옮겨 커밋하세요. 그다음 파이에서 git pull이 Your local changes ... would be overwritten로 거부되면, 파이 쪽 수정이 PC에 반영된 것을 확인하고 git checkout -- pi/slot_map.py로 되돌린 뒤 다시 git pull합니다.

파이가 없어도 됩니다

PC에서 실행하면 GPIO가 없으므로 흉내내기 모드로 돕니다. 배치표가 맞는지, 대시보드에 카드가 제대로 나오는지는 파이 없이도 전부 확인할 수 있습니다. --check에 "흉내내기 모드"라고 나오면 PC에서는 정상입니다.

19전시 준비 — 전원만 꽂으면 켜지게

지금까지는 SSH 창에서 데몬을 켰기 때문에 창을 닫으면 데몬도 꺼집니다. 전시 때는 파이 전원만 꽂으면 데몬이 저절로 켜지도록 자동 실행 서비스로 등록합니다. 모든 기능이 손으로 켠 데몬에서 잘 동작한 다음에 하세요.

① 자동 실행 등록 (한 번만)

② 잘 도는지 확인

그다음 sudo reboot로 파이를 다시 켜고, SSH로 아무것도 하지 않은 채 대시보드에서 켜기가 되는지 봅니다.

③ 등록한 뒤에 달라지는 것

하고 싶은 것명령
배치표·.env를 고친 뒤 반영sudo systemctl restart iot-daemon
손으로 python daemon.py를 켜서 시험먼저 sudo systemctl stop iot-daemon — 두 개가 동시에 돌면 GPIO busy
자동 실행 그만두기sudo systemctl disable --now iot-daemon

네오픽셀은 sudo 권한이 필요해 이 설정으로는 색이 나오지 않을 수 있습니다. 네오픽셀을 쓰는 팀은 선생님과 상의하세요.

④ 전시장에서

  • 네트워크가 바뀌면 IP도 바뀝니다. 전시장 Wi-Fi(또는 가져간 공유기)에 PC와 파이를 연결하고, ipconfig → pi/.env의 BACKEND_URL 수정 → sudo systemctl restart iot-daemon. 파이가 새 Wi-Fi를 모르면 모니터를 연결해 데스크톱에서 Wi-Fi를 추가하거나, 미리 같은 이름·비밀번호의 휴대폰 핫스팟을 등록해 두면 편합니다.
  • 백엔드를 클라우드(Render)에 배포했다면 BACKEND_URL에 그 주소(https://…onrender.com)를 적습니다 → 00 매뉴얼 12장.
  • 전원은 공식 어댑터로, 멀티탭은 발에 걸리지 않는 곳에. 끌 때는 sudo poweroff.
  • 예비 점퍼선·저항, 그리고 배선표 사진을 챙겨 갑니다. 이동 중에 빠진 선을 사진대로 다시 꽂으면 됩니다.
