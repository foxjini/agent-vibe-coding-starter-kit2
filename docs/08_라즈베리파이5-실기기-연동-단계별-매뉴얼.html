스마트 금융 보안 ATM · 라즈베리파이 담당

Mock에서 실제 라즈베리파이 5로 — 단계별 연동 매뉴얼

PC의 시뮬레이션(mock)에서 잘 되던 ATM을, 라즈베리파이 5 + SG-90 서보 1개 + USB 웹캠 + 7인치 화면으로 옮겨 PC 백엔드·휴대폰과 실제로 연동하는 과정을 14단계로 나눴습니다. 한 단계가 끝날 때마다 "성공하면 이렇게 보인다"를 확인하고 다음으로 넘어가세요.

먼저 이해하기

무엇이 바뀌고, 무엇이 그대로인가

코드는 거의 그대로입니다. 바뀌는 것은 "어느 기계에서 무엇이 도는가"와 "서로를 어떤 주소로 부르는가" 두 가지뿐입니다.

백엔드 (FastAPI, 8000번)PCPC 그대로 — 단, 다른 기계가 들어올 수 있게 띄운다

'localhost'는 "지금 이 기계 자신"이라는 뜻입니다

PC에서 한 대로 돌릴 때는 모든 주소가 localhost여서 상관없었습니다. 기계가 셋으로 나뉘면 파이에서 쓴 localhost는 파이, 휴대폰에서 쓴 localhost는 휴대폰을 가리킵니다. 연동이 안 되는 원인의 대부분이 이것입니다.

시작 전에

준비물과 안전 수칙

준비물메모
라즈베리파이 5 + 공식 27W(5V 5A) 어댑터 + microSD라즈베리파이 OS(Bookworm 또는 Trixie) 데스크톱 이미지
SG-90 서보 1개현금 배출구 덮개. 어느 금액(5만·10만·30만·50만 원)이든 같은 덮개가 열렸다 닫힙니다
서보용 별도 5V 전원 (1A 이상)파이의 5V 핀에서 서보 전원을 따지 않습니다
USB 웹캠파이 카메라 모듈(CSI 리본)은 이 코드로 열리지 않습니다
7인치 디스플레이, 키보드·마우스처음 설정할 때만 키보드·마우스가 필요합니다
브레드보드, 점퍼선(암-수, 수-수)서보의 빨강·갈색선을 외부 전원과 파이 GND에 잇습니다
개발 PC, 휴대폰, 공유기 또는 휴대폰 핫스팟세 기계가 같은 네트워크에 있어야 합니다 (3단계)

안전 수칙 5가지 — 먼저 읽습니다

  1. 서보는 별도 5V 전원으로. 파이 5V 핀에 직결하면 서보가 움직이는 순간 전압이 떨어져 파이가 재부팅되거나 SD 카드가 상할 수 있습니다.
  2. GND는 파이와 외부 전원이 함께 씁니다. 빠지면 서보가 제멋대로 움직이거나 아예 안 움직입니다.
  3. 배선은 전원을 끄고 바꿉니다.
  4. 첫 연결과 서보 시험(7·10단계)은 교사 입회 하에.
  5. 서보가 움직일 때 배출구에 손을 넣지 않습니다.

A부 · 개발 PC에서 (1~3단계)

PC를 "다른 기계가 찾아올 수 있는 서버"로 만든다

파이를 켜기 전에 PC 쪽부터 끝냅니다. 여기서 안 되는 것은 파이에서도 안 됩니다.

  1. mock으로 한 번 더 통과시킨다

    왜? 파이에서 문제가 나면 "코드 문제인지 기계 문제인지"를 가려야 합니다. 출발점이 깨끗해야 가릴 수 있습니다.

    $ pytest
$ python scripts/demo_e2e.py      # 백엔드와 ATM 데몬(mock)을 띄운 상태에서
    성공하면 112 passed, 그리고 마지막 줄 통합 시연 전 구간 통과

    막히면 파이로 넘어가지 말고 팀(백엔드 담당)과 먼저 고칩니다.

  2. PC의 IP 주소를 알아내고, 백엔드를 "밖에서도 들어오게" 띄운다

    왜? 파이와 휴대폰은 PC를 localhost로 부를 수 없습니다. PC의 진짜 주소(IP)가 필요하고, 백엔드가 그 주소로 오는 손님도 받아 주어야 합니다.

    ① IP 확인 (Windows PowerShell)

    > ipconfig
무선 LAN 어댑터 Wi-Fi:
   IPv4 주소 . . . . . . . . . : 192.168.0.25     ← 이 숫자를 적어 둔다 (기계마다 다르다)

    ② 키 맞추기 — backend/.env의 DEVICE_API_KEY 값을 확인해 둡니다. 5단계에서 파이에도 똑같이 넣습니다. (키 값은 채팅·문서에 붙여 넣지 말고 USB나 직접 입력으로 옮깁니다.)

    ③ 백엔드 실행 — --host 0.0.0.0이 "모든 손님을 받는다"는 뜻입니다.

    > cd backend
> uvicorn main:app --host 0.0.0.0 --port 8000

    처음 실행하면 Windows 방화벽 창이 뜹니다. "개인 네트워크"에 체크하고 액세스 허용을 누릅니다.

    성공하면 휴대폰 브라우저에서 http://192.168.0.25:8000/health를 열었을 때 응답(JSON)이 보입니다.

    막히면 휴대폰에서 안 열리면 → 같은 Wi-Fi인지, 방화벽을 허용했는지. 둘 다 맞는데 안 되면 학교 Wi-Fi가 기기끼리의 통신을 막는 것일 수 있습니다(AP 격리). 휴대폰 핫스팟이나 별도 공유기에 세 기계를 모두 붙이세요.

  3. 프론트엔드를 띄우고, 휴대폰이 PC를 찾게 한다

    왜? 파이의 7인치 화면과 휴대폰은 PC의 프론트엔드(3000번)에서 화면 파일을 받아 갑니다.

    > cd frontend
> npm run dev
  - Local:   http://localhost:3000
  - Network: http://192.168.0.25:3000     ← Network 줄의 주소가 다른 기계용

    휴대폰 쪽 설정 — 둘 중 쓰는 쪽 하나만 하면 됩니다.

    휴대폰에서 쓰는 것할 일
    안드로이드 사전 테스트 앱앱 설정의 서버 주소를 http://192.168.0.25:8000(PC의 IP)으로 바꾼다
    휴대폰 브라우저의 /messages frontend/.env.local에 NEXT_PUBLIC_API_BASE_URL=http://192.168.0.25:8000, backend/.env의 CORS_ORIGINS에 http://192.168.0.25:3000을 쉼표로 덧붙이고 백엔드와 프론트엔드를 둘 다 다시 켠다

    NEXT_PUBLIC_ATM_DAEMON_URL은 http://localhost:8100 그대로 둡니다. /atm 화면은 파이에서 열리고, 거기서 localhost는 바로 데몬이 도는 파이이기 때문입니다.

    성공하면 휴대폰에서 로그인 → 보이스피싱 문자 검사 → QR이 화면에 뜬다. (이 QR을 10단계까지 아껴 둡니다)

B부 · 라즈베리파이에서 (4~6단계)

파이에 코드와 파이썬 환경을 갖춘다

아직 서보는 꽂지 않습니다. 소프트웨어부터 끝내야 문제가 나도 원인을 좁힐 수 있습니다.

  1. 같은 네트워크에 붙이고 PC가 보이는지 확인한다

    왜? 파이에서 PC가 안 보이면 뒤의 모든 단계가 "백엔드 연결 실패"로 끝납니다. 가장 먼저 확인합니다.

    $ hostname -I                                  # 파이 자신의 IP (적어 둔다)
$ curl http://192.168.0.25:8000/health           # PC의 IP로 백엔드 찾기
    성공하면 curl 결과로 JSON 한 줄이 나온다.

    막히면 Connection refused → PC에서 2단계의 --host 0.0.0.0 확인. timed out → 같은 Wi-Fi인지, 방화벽, AP 격리(2단계 '막히면').

  2. 저장소를 받는다 — pi/만 복사하지 않는다

    왜? pi/main.py는 서보를 움직이는 코드를 backend/iot/에서 가져옵니다. pi/만 있으면 No module named 'iot'로 멈춥니다.

    $ git clone <저장소 주소>
$ cd <저장소 이름>
$ git checkout atm
$ ls                       # pi  backend  frontend ... 가 함께 보여야 한다
    성공하면 pi/와 backend/iot/가 같은 상위 폴더 아래에 있다.

  3. 파이썬 가상환경을 --system-site-packages로 만든다 가장 많이 막히는 곳

    왜? 서보 제어에 필요한 gpiozero와 lgpio는 파이 OS에 이미 깔려 있습니다. 그런데 보통 방식으로 만든 venv는 그것을 못 봅니다. 이 옵션이 "시스템에 깔린 것도 같이 봐라"는 뜻입니다. 파이 5는 GPIO 칩(RP1)이 바뀌어서 예전 RPi.GPIO·pigpio로는 동작하지 않고, lgpio가 필요합니다.

    $ /usr/bin/python3 -c "import gpiozero, lgpio; print('있음')"   # 먼저 확인
있음
$ cd pi
$ rm -rf venv                                        # PC에서 가져온 venv가 있으면 지운다
$ python3 -m venv --system-site-packages venv
$ source venv/bin/activate
(venv) $ pip install -r requirements.txt
(venv) $ python -c "import gpiozero, lgpio; print('venv에서도 보임')"
    성공하면 마지막 줄에 venv에서도 보임

    막히면 처음 확인에서 있음이 안 나오면 그때만 sudo apt install -y python3-gpiozero python3-lgpio. pip install lgpio는 하지 않습니다(빌드 실패가 잦음). opencv 설치가 몇 분째 안 끝나면 sudo apt install -y python3-opencv로 대신하고 requirements.txt의 opencv-python 줄을 빼고 설치합니다. GPIO 권한 오류가 나면 sudo usermod -aG gpio $USER 후 다시 로그인.

C부 · 하드웨어 (7~10단계)

.env를 쓰고, 배선하고, 움직이기 전에 점검한다

  1. pi/.env를 작성한다 — mock에서 바뀌는 줄은 4개

    왜? 같은 코드가 PC에서는 가짜 장치, 파이에서는 진짜 서보를 쓰는 것은 이 파일의 DEVICE_MODE 한 줄 덕분입니다. 주소와 핀도 코드가 아니라 여기서 바꿉니다.

    $ cp .env.example .env
$ nano .env              # 저장: Ctrl+O, Enter / 나가기: Ctrl+X
    키mock(PC)실기기(파이)설명
    DEVICE_MODEmockhardware진짜 서보를 쓴다
    BACKEND_URLhttp://127.0.0.1:8000http://192.168.0.25:8000PC의 IP (2단계에서 적은 값)
    DEVICE_API_KEY—백엔드와 같은 값한 글자만 달라도 거절(401)
    SERVO_PIN—18배출구 덮개 서보를 꽂은 GPIO (물리 핀 12)
    GPIOZERO_PIN_FACTORYlgpio (그대로)파이 5에 필요
    ENABLE_CAMERAtrue (그대로)카메라 없이 먼저 보려면 false
    SERVO_MIN_PULSE_US / _MAX_500 / 2400SG-90 0~180도. 11단계에서 실측으로 조정
    SERVO_HOLDfalse움직인 뒤 신호를 끊어 떨림·발열 방지
    CAMERA_WIDTH / _HEIGHT640 / 480키우지 않는다 — QR 인식이 느려진다
    .env를 고치면 데몬을 껐다 켭니다

    데몬은 시작할 때 한 번만 읽습니다. 고쳤는데 그대로라면 재시작을 안 한 것입니다.

  2. 배선한다 — 전원을 끄고

    왜 이 핀? GPIO18은 파이 5에서 하드웨어 PWM이 되는 핀입니다. 지금은 소프트웨어 PWM으로 돌지만, 나중에 바꾸더라도 배선을 다시 할 필요가 없습니다. SG-90은 3.3V 신호로 동작하니 레벨 변환기는 필요 없습니다.

    SG-90 선어디로
    주황 (신호)GPIO18 (물리 핀 12)
    빨강 (전원)외부 5V(+)
    갈색 (GND)외부 전원 GND 그리고 파이 GND(물리 핀 6 등) — 브레드보드에서 한 줄로 묶는다

    핀이 다르게 꽂혔다면 다시 꽂지 말고 .env의 SERVO_PIN을 실제 번호로 바꿉니다. 코드는 고치지 않습니다.

  3. 점검 도구를 돌린다 — 서보는 아직 움직이지 않는다

    왜? 데몬을 바로 켜면 오류가 트레이스백 한 덩어리로 나와 원인을 찾기 어렵습니다. 이 도구는 파이썬 환경 · 폴더 · .env · GPIO · 카메라 · 백엔드 연결을 한 줄씩 확인하고, 실패하면 고치는 방법을 바로 아래에 적어 줍니다.

    (venv) $ python check_hardware.py
[  OK  ] venv가 시스템 패키지를 함께 봄 — --system-site-packages
[  OK  ] DEVICE_MODE=hardware — 실기기
[  OK  ] 배출구 서보 핀 — GPIO18
[  OK  ] 핀 팩토리 준비됨 — LGPIOFactory
[  OK  ] 카메라 영상 읽기 성공 (CAMERA_INDEX=0) — 640x480
[  OK  ] 디바이스 키 통과
… (실제로는 줄이 더 많습니다)
    성공하면 마지막에 전부 통과 — python main.py 로 ATM 데몬을 켜도 됩니다.

    막히면 실패 줄 바로 아래 안내를 위에서부터 차례로 고칩니다. 주의는 읽어 보고 넘어가도 됩니다. 예전 설정(SERVO_GATE_PIN, OUTLET_SERVO_PINS)이 남았다는 주의가 뜨면 그 줄을 지우세요. 카메라 번호(CAMERA_INDEX)는 추측하지 말고 이 도구가 알려 주는 번호를 넣습니다.

  4. 배출구 덮개를 한 번 움직여 본다 교사 입회

    왜? 처음으로 서보가 실제로 돕니다. 데몬을 켜기 전에 서보 하나만 따로 확인해 두면, 나중에 안 움직일 때 원인을 좁히기 쉽습니다.

    (venv) $ python check_hardware.py --servo
         GPIO18 배출구 덮개를 90도로 엽니다...
[  OK  ] 배출구 덮개 동작 명령 보냄 (GPIO18) — 실제로 열렸다 닫혔는지 눈으로 확인하세요

    눈과 귀로 확인할 것

    • 덮개가 실제로 열렸다 닫혔는가
    • 닫힌 뒤 조용해지는가 — 계속 "지지직" 하면 SERVO_HOLD=false 확인
    • 파이가 재부팅되지 않았는가 — 재부팅되면 서보 전원이 파이에서 나가고 있거나 부족한 것

    OK인데 안 움직이면 "OK"는 명령을 보냈다는 뜻이지 움직였다는 뜻이 아닙니다. 외부 5V 전원이 켜져 있는지, GND가 공통인지 확인합니다.

  5. 각도와 펄스 폭을 실측해 맞춘다

    왜? SG-90은 제품마다 끝 위치가 조금씩 다르고, 배출구 덮개 모양도 팀마다 다릅니다. 숫자는 조립한 뒤에야 정해집니다.

    증상고칠 곳
    덮개가 끝에 닿아 "드르륵" 소리.env — SERVO_MIN_PULSE_US=600, SERVO_MAX_PULSE_US=2300처럼 범위를 좁힌다
    덮개가 덜 열려 지폐를 못 꺼낸다backend/iot/hardware_provider.py 맨 위 SERVO_OPEN_ANGLE (기본 90)
    닫힌 자세가 비뚤다같은 파일 SERVO_CLOSED_ANGLE (기본 0) — 또는 서보 혼(팔)을 빼서 다시 끼운다
    너무 빨리 닫힌다같은 파일 DISPENSE_HOLD_SECONDS (기본 1.0)
    덮개가 제 무게로 스르륵 열린다.env — SERVO_HOLD=true (전류를 더 먹는다)

    고친 뒤 python check_hardware.py --servo로 다시 확인합니다. 맞춘 값은 아래 실측 기록표에 적어 팀과 공유하세요.

D부 · 연동 (12~14단계)

데몬을 켜고, 화면을 띄우고, 휴대폰 QR로 끝까지 확인한다

  1. ATM 데몬을 켠다

    (venv) $ python main.py
PWMSoftwareFallback: To reduce servo jitter, use the pigpio pin factory
  ↑ 경고일 뿐 오류가 아닙니다. 파이 5는 pigpio를 쓸 수 없어 소프트웨어 PWM으로 돕니다.
하드웨어 Provider 시작 (배출구 서보=GPIO18, 대기 시 펄스=끊음)
카메라 열림 (index=0, ..., 640x480)
QR 스캔 시작 (camera_index=0)
ATM 데몬 시작 — DEVICE_MODE=hardware, port=8100

    켜질 때 덮개가 한 번 닫힌 자세로 맞춰집니다. 정상입니다.

    성공하면 로그에 DEVICE_MODE=hardware. 새 터미널에서 curl http://localhost:8100/state 하면 상태 JSON이 나온다.

    막히면 DEVICE_MODE=mock으로 떴다면 .env를 저장 안 했거나 다른 폴더에서 실행한 것. 장치 준비에 실패하면 데몬은 일부러 아예 뜨지 않습니다 — 서보는 가만히 있는데 "배출했다"고 기록하는 ATM이 되면 안 되기 때문입니다. 화면에 나온 안내를 따라 고칩니다. "핀이 사용 중"이면 앞서 띄운 데몬이 살아 있는 것(ps aux | grep main.py).

  2. 7인치 화면에 ATM 화면을 띄운다

    왜 PC 주소? 화면 파일은 PC의 프론트엔드(3000번)에서 받아 오고, 그 화면이 부르는 데몬은 파이 자신(localhost:8100)입니다.

    $ chromium --kiosk http://192.168.0.25:3000/atm
# 'command not found'면: chromium-browser --kiosk ...
# 리허설 때는 --kiosk를 빼면 주소창이 있어 새로고침이 쉽다. 키오스크 종료: Alt+F4
    성공하면 "출금하실 금액을 선택해 주세요"와 금액 버튼 4개가 보인다.

    막히면 화면이 아예 안 열리면 → PC의 npm run dev와 방화벽(3단계). 화면은 뜨는데 "ATM 제어 장치에 연결할 수 없습니다"가 나오면 → 파이의 데몬(12단계)이 꺼져 있거나, NEXT_PUBLIC_ATM_DAEMON_URL을 localhost가 아닌 값으로 바꿔 둔 것.

  3. 끝까지 연동을 확인한다 — 자동 검사, 그다음 손으로

    ① 자동 검사 (PC에서, 데몬 주소만 파이로 바꿔서)

    > set ATM_DAEMON_URL=http://192.168.0.30:8100     # 파이의 IP (4단계 hostname -I)
> python scripts\demo_e2e.py
통합 시연 전 구간 통과 — 정상 문자와 보이스피싱 문자 모두 확인했습니다.

    PowerShell이면 $env:ATM_DAEMON_URL="http://192.168.0.30:8100". 이 검사는 실제 서보를 움직입니다 — 교사 입회, 배출구에서 손을 뗍니다.

    ② 손으로 확인 — 이것이 전시회에서 보여 줄 장면입니다.

    1. 7인치 화면에서 5만원 → 덮개가 열렸다 닫히고 "50,000원을 배출했습니다"
    2. 10만·30만·50만원 → 같은 덮개가 열렸다 닫힌다
    3. 휴대폰에서 보이스피싱 문자 검사 → QR을 파이 웹캠에 (20cm쯤, 화면 밝기 최대) → 화면이 빨갛게 바뀐다
    4. 그 상태에서 50만원 → 덮개가 전혀 움직이지 않는다 ← 이 작품의 핵심
    5. "상담원 확인 요청하기" → PC의 /callcenter에서 해제 → 몇 초 안에 ATM 화면이 출금 화면으로 → 다시 배출된다
    성공하면 다섯 가지가 모두 된다. 축하합니다 — mock이 아니라 실제 기계로 연동된 것입니다.

PC 리허설과 다르게 보이는 것 (전부 정상)

현상이유
출금을 누르면 1~2초 "잠시만 기다려 주세요"덮개를 열고·기다리고·닫는 실제 시간(약 1.4초). 그동안 버튼이 잠긴다

위험 화면에 카운트다운이 없다막혀 있는 동안은 자동 초기화가 돌지 않는다. 시간이 차단을 풀면 안 되니까
차단 화면에서 "처음으로"가 안 먹는다제한은 사람이 푼다 — 상담원 해제 또는 "직원 확인 후 해제"
