노래방 카운터 관리 컴퓨터(백엔드)와 노래방 룸 도우미(라즈베리파이)가 처음으로 인사하는 날! 하드웨어 핀이나 납땜 없이, 키보드와 화면 출력만으로 통신 성공을 만듭니다.

Zero Hardware
전선 연결? 납땜? 지금은 단 하나도 필요 없습니다. 오직 파이썬 print() 글자로만 시뮬레이션합니다.
ELI5 쉬운 설명
5살 아이에게 설명하듯 어려운 기술 용어를 코인 노래방의 일상 언어로 1:1 완벽 번역해 드립니다.
단 3가지만 맞추기
카운터 IP 주소, 출입증(API Key), 부품 이름표(ID) 딱 3개만 맞추면 무조건 연결에 성공합니다.
🎯 대상: 하드웨어 담당 (학생A 조장, 학생B) ⏱️ 소요 시간: 15분 💻 준비물: 파이썬이 설치된 PC 또는 라즈베리파이 5
우리가 만들 전체 시스템 구조

우리가 만드는 큰 그림:
노래방 카운터와 룸 현장 도우미

시스템이 복잡해 보이지만, 사실은 '예약 손님', '카운터 컴퓨터(백엔드)', '룸 도우미(라즈베리파이)' 3명이 유기적으로 대화하는 구조입니다.

본부 카운터 관리 컴퓨터 (백엔드 + DB)
역할: 노래방 총괄 지휘 본부
• 학생들의 웹 예약(시간, 학번, 4자리 비밀번호)을 장부(DB)에 저장합니다.
• 예약 시간이 되면 "1번 룸 도어락 열어라!", "노래방 반주기 전원 켜라!" 하고 지시서를 작성해 둡니다.
현장 룸 관리 도우미 (라즈베리파이 5)
역할: 부스 룸 현장의 믿음직한 행동대장
• 3초마다 카운터에 가서 "저 지금 할 일 있나요?" 하고 지시서를 확인합니다.
• 지시가 떨어지면 문을 열고(print), 전원을 켜고(print), "다 했습니다!" 하고 보고합니다.
라즈베리파이 담당 학생이 기억할 핵심 원칙
백엔드의 데이터베이스나 프론트엔드 React 코드를 내가 직접 수정할 필요가 전혀 없습니다!
오직 "카운터가 내려준 메모지를 읽고, 그대로 화면에 출력(print)한 뒤, 완료 보고서 보내기"만 완성하면 내 몫의 개발은 끝납니다.
대화의 수단과 규칙

대화 수단: 표준 쪽지(JSON)와
무전 규칙(REST API) 익히기

서로 다른 컴퓨터가 대화할 때는 아무렇게나 말할 수 없습니다. 딱 정해진 '메모지 양식'과 '대화 방법'을 사용합니다.

전문 기술 용어 ELI5 일상 비유 우리 노래방 프로젝트에서의 실제 의미
REST API 📋 공식 심부름 창구 카운터 컴퓨터와 룸 도우미가 통신하기로 약속한 정규 주소 (URL)
JSON 📝 [항목 : 내용] 쪽지 컴퓨터들이 좋아하는 표준 쪽지 서식 (예: {"state": "unlocked"})
Desired-State 📢 카운터의 '지시서' 카운터가 바라는 상태 (예: 도어락 열어둬! 릴레이 켜!)
Current-State 🫡 도우미의 '완료 보고' 현장에서 실제 실행한 결과 보고 (예: 도어락 열었음!)
GET 요청 👀 "지시서 볼래요" 카운터에 적힌 목표 상태를 읽어올 때 쓰는 명령어
POST 요청 ✍️ "보고서 낼게요" 카운터에 내 완료 상태를 기록해달라고 보낼 때 쓰는 명령어
동작 메커니즘

핵심 원리: 폴링(Polling)의 마법
"도우미는 왜 3초마다 카운터에 갈까?"

카운터가 룸 도우미에게 일일이 전화를 걸면 방화벽이나 학교 Wi-Fi 때문에 막힙니다. 대신 도우미가 3초마다 카운터를 찾아가는 '폴링' 방식을 씁니다.

① 지시서 확인 (GET)
3초마다 GET .../desired-state 호출
"카운터님, 지금 도어락 열어야 하나요? 릴레이 켜야 하나요?"
② 모의 동작 (print)
받은 지시가 'unlocked'라면?
터미널에 외치기:
print("🚪 철컥! 도어락 해제!")
③ 완료 보고 (POST)
POST .../state 전송
"카운터님, 지시대로 도어락 열어두었습니다!" (웹 화면에 즉시 반영)
🎮 가상 폴링 인터랙티브 체험
[라즈베리파이 5 도우미 대기 중...] 3초마다 백엔드 카운터에 물어보는 폴링 루프가 실행되고 있습니다. 위 파란색 버튼을 눌러 카운터에서 '도어락 해제' 지시를 내려보세요!

[1단계 실습] 5줄짜리 파이썬 코드로
카운터에 첫 인사 건네기 (Ping)

라즈베리파이에서 백엔드 컴퓨터로 통신선이 제대로 뚫려 있는지 1초 만에 테스트하는 초간단 스크립트입니다.

pi/01_ping_backend.py 
import os, requests
from dotenv import load_dotenv

load_dotenv()  # 1. pi/.env 파일에서 주소 가져오기
BACKEND_URL = os.getenv("BACKEND_URL", "http://127.0.0.1:8000")

# 2. 카운터에 "지금 등록된 부품 목록 보여주세요" 하고 물어보기
print(f"🍓 [라즈베리파이 5] 카운터로 인사를 건넵니다: {BACKEND_URL}/api/devices")
response = requests.get(f"{BACKEND_URL}/api/devices", timeout=3)

if response.status_code == 200:
    print("🎉 [성공 200 OK] 카운터와 정상적으로 연결되었습니다!")
    print("📦 등록된 부품:", [d['id'] for d in response.json().get('data', [])])
else:
    print(f"⚠️ 연결은 됐지만 응답 코드가 다릅니다: {response.status_code}")

실제 모터를 달지 않아도, 카운터의 '도어락 열기' 지시를 받아 화면에 출력하고 카운터에 보고하는 실전 데몬입니다.

pi/02_karaoke_daemon_mock.py (핵심 로직 발췌) 
import time, requests

HEADERS = {"X-Device-Api-Key": "KARAOKE_2026_09_05_v1_0_0"}

def poll_and_act(device_id):
    # 1. 카운터에 "이 부품의 목표 상태는 무엇인가요?" 묻기
    url = f"http://192.168.0.25:8000/api/v1/devices/{device_id}/desired-state"
    res = requests.get(url, headers=HEADERS)
    desired = res.json()["data"].get("desired_state")

    # 2. 지시가 변경되었으면 실제 하드웨어 대신 print()로 동작 시뮬레이션
    if desired == "unlocked":
        print(f"🚪 [동작 시뮬레이션] {device_id} 철컥! 도어락이 해제되었습니다!")
        
        # 3. 카운터에 "도어락 열었습니다!" 보고하기
        report_url = f"http://192.168.0.25:8000/api/v1/devices/{device_id}/state"
        requests.post(report_url, headers=HEADERS, json={"state": "unlocked"})
        print(f"📤 [보고 완료] 카운터에 unlocked 상태 보고 완료!")

# 3초마다 반복 실행 (무한 루프)
while True:
    poll_and_act("door_lock_1")
    poll_and_act("relay_1")
    time.sleep(3)

3. 웹 대시보드의 도어락 아이콘이 초록색 '열림'으로 실시간 변경됩니다. (연동 성공!)

초보자를 위한 3초 해결 처방전

에러는 내가 코딩을 못해서가 아닙니다. 컴퓨터가 서로를 찾아가는 과정에서 보내는 친절한 신호일 뿐입니다.

🚨 401 Unauthorized
뜻: "출입증(API 키)이 틀렸어요!"
원인: 백엔드의 키와 파이의 키가 서로 다름
처방: pi/.env 파일의 DEVICE_API_KEY가 백엔드와 똑같이 KARAOKE_2026_09_05_v1_0_0인지 확인!
🔍 404 Not Found
뜻: "장부(DB)에 그런 부품 이름이 없어요!"
원인: door_lock_1 대신 doorlock처럼 오타가 남
처방: 부품 이름표(ID) 스펠링을 door_lock_1, relay_1로 정확히 확인!
🚫 Connection Refused
뜻: "카운터 문이 닫혀 있어요!"
원인: 백엔드 서버(FastAPI)가 아직 실행 중이지 않음
처방: 백엔드 담당 친구에게 "서버(uvicorn) 켜져 있어?" 하고 물어보기!
⏳ Connection Timeout
뜻: "카운터 주소(IP)로 찾아가는 길이 끊겼어요!"
원인: 두 컴퓨터가 서로 다른 Wi-Fi에 연결되어 있음
처방: 백엔드 PC와 라즈베리파이가 동일한 공유기(Wi-Fi)에 접속했는지 확인!
