라즈베리파이 ATM 배선과 구성

PC에서 흉내만 내던 프로그램(Mock)을 라즈베리파이 5로 옮겨 진짜 서보가 움직이게 만들고, 그 뒤에 센서와 액추에이터를 바꿔 다는 방법까지 다룹니다. 하드웨어를 처음 만져 본다는 전제로 썼습니다.

먼저 읽습니다 — 안전 수칙 5가지

  1. 서보는 별도 5V 전원으로 돌립니다. 파이의 5V 핀에 직접 연결하면 서보가 움직이는 순간 전압이 떨어져 파이가 재부팅되거나 SD 카드가 상할 수 있습니다.
  2. 접지(GND)는 파이와 외부 전원이 함께 씁니다. 이게 빠지면 서보가 제멋대로 움직이거나 아예 안 움직입니다. 초보자가 가장 많이 빠뜨리는 선입니다.
  3. 배선을 바꿀 때는 반드시 전원을 끕니다. 켠 채로 꽂았다 뺐다 하지 않습니다.
  4. 실기기 첫 연결과 서보 테스트는 교사 입회 하에 합니다.
  5. 서보가 움직일 때 배출구에 손을 넣지 않습니다. MG996R은 힘이 셉니다.

1부 · 먼저 이해하기

지금 무엇을 하는 건가

프로그램 전체를 고치는 게 아닙니다. 딱 한 부품만 갈아 끼웁니다.

이 프로젝트는 처음부터 "장치를 다루는 부분"을 따로 떼어 놓았습니다. 그 부분을 Provider라고 부릅니다. PC에서 쓰던 것은 MockDeviceProvider, 파이에서 쓸 것은 HardwareDeviceProvider입니다. 둘은 똑같은 모양 (같은 함수 이름, 같은 인자)을 하고 있어서, 나머지 코드는 어느 쪽이 끼워졌는지 모릅니다.

1부 · 절차

Mock을 실기기로 옮기는 10단계

  1. PC에서 먼저 통과시킵니다

    pi/ 폴더만 복사하면 안 됩니다. pi/main.py는 장치 제어 코드를 backend/iot/에서 가져옵니다.

    gpiozero와 lgpio는 라즈베리파이 OS에 이미 들어 있습니다. 다시 설치하려 들지 말고 먼저 확인하세요. 

    $ /usr/bin/python3 -c "import gpiozero, lgpio; print('있음')"
있음

    $ cd pi
$ rm -rf venv                                 # PC에서 만든 게 있으면 지운다

$ source venv/bin/activate
$ pip install -r requirements.txt

    cp .env.example .env 로 만든 뒤 아래 값을 채웁니다.

    SERVO_PUSHER_PIN실제 배선한 번호기본 19
    CAMERA_INDEX보통 0추측하지 말고 6단계가 알려 주는 번호를 넣으세요
    백엔드 PC도 준비가 필요합니다

    PC에서 uvicorn main:app --host 0.0.0.0 --port 8000 으로 띄워야 합니다. 127.0.0.1로 띄우면 파이에서 닿지 못합니다.

1부 · 5단계 상세

배선

파이는 신호만 줍니다. 서보를 움직이는 힘은 외부 전원에서 나옵니다.

핀 번호가 다르면 코드가 아니라 .env를 고칩니다

배선을 먼저 하고, .env의 SERVO_GATE_PIN과 SERVO_PUSHER_PIN을 실제로 꽂은 번호로 맞추면 됩니다. 코드는 건드리지 않습니다.

SERVO_HOLD가 왜 있나

gpiozero는 각도를 준 뒤에도 신호를 계속 내보냅니다. MG996R은 그동안 자세를 유지하느라 전류를 계속 먹고 미세하게 떨립니다("지지직" 소리). 몇 시간짜리 전시 내내 그러면 발열과 전압 강하로 이어지고, 5V를 나눠 쓰는 배선에서는 파이가 리부팅되기도 합니다.

값동작언제
false (기본)자세를 잡은 뒤 신호를 끊는다대부분의 경우. 조용하고 전류를 덜 먹습니다
true신호를 계속 보내 자세를 붙잡는다게이트가 제 무게로 흘러내릴 때만

2부 · 구성 바꾸기

센서와 액추에이터를 바꿔 달기

바꾸는 범위에 따라 고칠 곳이 달라집니다. 아래로 갈수록 손대는 곳이 많아집니다. 위에서부터 확인해서, 더 내려갈 필요가 없으면 거기서 멈추세요.

레벨 1

핀 번호만 바뀐다

pi/.env

서보를 다른 핀에 꽂았거나 부저를 새로 달았을 때입니다. 코드는 한 줄도 고치지 않습니다. 

SERVO_GATE_PIN=23
SERVO_PUSHER_PIN=24
BUZZER_PIN=20      # 비워 두면 부저를 안 쓴다

고친 뒤에는 데몬을 껐다 다시 켜야 합니다. .env는 시작할 때 한 번만 읽습니다.

레벨 2

움직임을 조정한다

backend/iot/hardware_provider.py 맨 위

각도가 부족해서 지폐가 안 나오거나, 너무 빨리 닫혀 걸릴 때입니다. 파일 맨 위의 상수 네 개만 고치면 됩니다.

상수기본값뜻
SERVO_CLOSED_ANGLE0닫힌 자세
SERVO_OPEN_ANGLE90열린 자세 — 지폐가 안 나오면 여기를 키웁니다
DISPENSE_HOLD_SECONDS1.0열어 두는 시간 — 지폐가 걸리면 늘립니다
SERVO_SETTLE_SECONDS0.4닫힌 뒤 신호를 끊기까지 기다리는 시간
실측해서 맞추고, 맞춘 값은 기록하세요

이 숫자들은 조립 전에 정한 임시값입니다. 배출구를 만든 뒤 실제로 돌려 보며 맞춰야 하고, 맞춘 값은 팀에 공유해 매뉴얼에 남겨야 합니다.

레벨 3

액추에이터를 새로 추가한다

네 곳을 고친다

경고등(LED), 잠금 장치, 회전 표시등 같은 것을 새로 다는 경우입니다. 고칠 곳은 정확히 네 곳이고, 순서대로 하면 됩니다.

① 장치를 DB에 등록한다 — backend/db/seed.py

devices 표가 장치 이름의 유일한 진실입니다. 제어 기록(control_log)이 이 표를 참조하므로, 등록하지 않은 장치를 제어하면 기록을 남길 때 오류가 납니다. 

DEMO_DEVICES = [
    ("cash_dispenser_1", "현금 배출 시연 장치 (MG996R x2)", "cash_dispenser"),
    ("qr_scanner_1", "QR 인식 카메라", "qr_scanner"),
    ("buzzer_1", "경고 부저 (선택)", "buzzer"),
    ("warning_lamp_1", "경고등", "lamp"),          # ← 추가
]

추가한 뒤 python -m db.seed를 다시 실행합니다.

② 실기기 쪽에 장치를 만든다 — backend/iot/hardware_provider.py

# __init__ 안, 다른 장치를 만드는 곳 옆에
from gpiozero import LED
lamp_pin = os.getenv("LAMP_PIN", "").strip()
self._lamp = LED(int(lamp_pin)) if lamp_pin else None

# set_actuator_state 안에, buzzer_1 분기 아래에
if device_id == "warning_lamp_1":
    if self._lamp is not None:
        self._lamp.on() if desired_state == "ON" else self._lamp.off()
    self._lamp_state = desired_state
    return {"device_id": device_id, "state": self._lamp_state}

핀 번호는 코드에 박지 말고 .env에서 읽습니다 (LAMP_PIN=). 위 예시처럼 비어 있으면 장치가 없는 것으로 보고 조용히 넘어가게 하면, 부저처럼 "달아도 되고 안 달아도 되는" 부품이 됩니다.

③ Mock 쪽에도 같은 이름으로 넣는다 — backend/iot/mock_provider.py

_states 사전에 같은 device_id로 한 칸 추가합니다. 이걸 빠뜨리면 PC에서 테스트할 때만 터집니다 — 정작 실기기가 없을 때 확인이 안 되니 가장 곤란한 실수입니다. 

"warning_lamp_1": {
    "device_id": "warning_lamp_1",
    "name": "경고등",
    "kind": "lamp",
    "state": "OFF",
    "last_operator": None,
},

④ 언제 켤지 정한다 — pi/atm_controller.py

부저를 켜는 _warn()이 좋은 본보기입니다. 그 옆에 같은 방식으로 부르면 됩니다. 

await self._provider.set_actuator_state(
    "warning_lamp_1", "ON", operator="device"
)
켰으면 반드시 끄세요

실제로 겪은 일입니다. 부저를 켜는 코드만 있고 끄는 코드가 없어서, 실기기에서는 위험 QR을 한 번 읽는 순간부터 데몬을 끌 때까지 계속 울렸습니다. Mock에서는 글자만 바뀌니 아무도 몰랐습니다. 켜는 코드를 쓸 때 끄는 코드를 같이 쓰세요.

레벨 4

센서를 새로 추가한다

지금은 자리만 비어 있다

이 프로젝트에는 아직 센서가 하나도 없습니다. read_sensor_value()라는 함수는 있지만 속이 비어 있어서 항상 None을 돌려줍니다. 

# backend/iot/hardware_provider.py — 지금 상태
async def read_sensor_value(self, device_id):
    return {"device_id": device_id, "value": None, "unit": None}

센서를 붙인다면 레벨 3과 같은 순서에, 읽는 코드를 채워 넣습니다.

async def read_sensor_value(self, device_id):
    if device_id == "bill_sensor_1" and self._bill_sensor is not None:
        return {
            "device_id": device_id,
            "value": int(self._bill_sensor.is_active),
            "unit": "detected",
        }
    return {"device_id": device_id, "value": None, "unit": None}
센서를 붙인다면 여기가 가장 값어치 있는 자리입니다

지금 ATM은 서보가 실제로 돌았는지 확인하지 않습니다. 서보가 걸리거나 전압이 떨어져 움직이지 않아도 화면에는 "배출했습니다"라고 뜹니다. 배출구에 적외선 센서를 달아 지폐가 실제로 나왔는지 확인하면, 그 거짓말이 사라집니다. 전시 설명거리로도 좋습니다.

여기만은 건드리지 마세요

현금을 내줄지 말지 판단하는 곳은 pi/atm_controller.py의 request_withdraw() 한 곳뿐입니다. 액추에이터를 호출하는 코드를 다른 곳에 새로 만들면, 위험 판정을 거치지 않고 돈이 나가는 길이 생깁니다.

새 장치가 현금 배출과 관련이 있다면, 반드시 이 함수를 통과한 뒤에 호출되도록 붙이세요. 경고등·부저처럼 배출과 무관한 장치는 상관없습니다.

그리고 이 테스트가 빨개지면 무슨 일이 있어도 커밋하지 않습니다. 

$ pytest pi/tests/test_atm_controller.py::test_danger_qr_blocks_withdrawal_and_never_moves_servo

문제 해결

막히면 먼저 python check_hardware.py를 돌리세요. 대부분 원인과 고치는 방법을 함께 알려 줍니다.

증상원인과 해결
No module named 'iot'pi/와 backend/iot/가 같은 상위 폴더에 있어야 합니다 (2단계)
No module named 'gpiozero'
(설치했는데도)		venv가 시스템 패키지를 못 봅니다. --system-site-packages로 다시 만듭니다 (3단계)
BadPinFactory.env에 GPIOZERO_PIN_FACTORY=lgpio가 있는지 확인합니다
GPIO 권한 오류sudo usermod -aG gpio $USER 후 다시 로그인
데몬 재시작 시 “핀이 사용 중”앞서 띄운 데몬이 살아 있습니다. ps aux | grep main.py로 찾아 종료합니다
Not a video capture device번호가 있다고 카메라가 아닙니다. 웹캠 하나가 /dev/video0(영상)과 /dev/video1(메타데이터)을 함께 만듭니다. 점검 도구가 쓸 수 있는 번호를 알려 줍니다
PWMSoftwareFallback 경고오류가 아닙니다. 파이 5에서는 pigpio를 쓸 수 없어 소프트웨어 PWM으로 돕니다. 경고가 권하는 pigpio로 바꾸려 하지 마세요
서보가 떨리기만 하고 안 움직인다전원이 부족하거나 접지가 따로 놀고 있습니다 (안전 수칙 1·2)
서보가 움직일 때 파이가 재부팅서보를 파이 5V에 직결했습니다. 별도 전원으로 분리하세요
출금 버튼을 눌러도 1~2초 반응 없음정상입니다. 서보가 열고·밀고·닫는 실제 시간(약 1.4초)입니다. 그동안 화면은 “잠시만 기다려 주세요”를 띄웁니다
ATM API가 401DEVICE_API_KEY가 다릅니다. 양쪽 .env를 맞추고 둘 다 재시작

여기에 없는 오류라면 check_hardware.py 출력과 데몬 터미널의 마지막 Traceback 부분을 통째로 팀에 공유하세요. 일부만 보내면 원인을 못 찾습니다.

마지막으로. 이 모든 배선과 설정은 단 한 장면을 위한 것입니다 — 위험 문자로 만든 QR을 ATM에 보여준 뒤 50만 원 버튼을 눌러도, 서보가 움직이지 않고 현금이 나오지 않는 것. 다른 게 다 되어도 이게 안 되면 작품이 성립하지 않고, 이것만 되면 나머지는 거들 뿐입니다.
