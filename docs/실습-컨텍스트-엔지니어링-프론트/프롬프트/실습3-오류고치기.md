# 프로젝트 카드 — 학교 노래방 부스 (프론트엔드)

> 이 카드는 대화창 AI에게 우리 프로젝트를 알려 주는 고정 정보입니다. AI는 우리 파일을 직접 볼 수 없으므로
> 여기 적힌 내용과 함께 붙여 넣은 파일만 사실로 여겨야 합니다. (구조가 바뀌면 프론트 담당이 이 카드를 고칩니다)

## 무엇을 만드는가
웹 예약과 일회성 4자리 비밀번호로 부스 문(도어락)·전원(릴레이)·조명(LED)·안내 방송을 자동 제어하는 학교 노래방 부스.
- 백엔드: FastAPI (Python) — 프론트 담당은 백엔드 코드를 고치지 않는다. 필요한 API가 없으면 백엔드 담당에게 부탁한다
- 하드웨어: 라즈베리파이가 백엔드의 '목표 상태(desired_state)'를 폴링해 실제 기기를 움직이고 '실제 상태(current_state)'를 보고한다

## 프론트엔드 기술
- Next.js 16.3.4 (App Router) · React 19.2.8 · TypeScript 5 (`strict: true`) · Tailwind CSS 4 · 아이콘 `lucide-react`
- 경로 별칭 `@/` = `frontend/` 폴더 (예: `import { apiUrl } from "@/utils/apiConfig"`)
- 모든 페이지는 `"use client"` 컴포넌트다. `next.config.ts`의 `reactStrictMode: false`
- 명령: `npm run dev`(개발 서버, http://localhost:3000) · `npm run build` · `npm run lint` · `npx tsc --noEmit`

## 데이터 흐름
- 백엔드 응답은 성공 `{ "data": … }`, 실패 `{ "error": { "code", "message" } }`. 코드는 `json.data`, `json.error.message`를 읽는다
- 일반 요청: `fetch(apiUrl("/api/…"))`. 관리자 전용 요청: `adminFetch("/api/…", { method, headers, body })` — `X-Admin-Token`을 붙여 준다.
  401이면 토큰을 지우고 다시 로그인하게 한다
- 실패해도 화면이 멈추지 않게 `try/catch`로 조용히 넘긴다 (백엔드가 꺼져 있어도 화면은 떠야 한다)
- 기기 제어는 `/admin`의 `handleDeviceControl(id, state, value)` → `POST /api/devices/{id}/control {desired_state, value}` 하나로 한다
- 기기 id: `door_lock_1`(도어락), `relay_1`(전원), `led_1`(조명), `speaker_1`(스피커), `keypad_1`, `pir_1`(입장 감지)
- 기기 객체: `{ id, name, kind, desired_state, current_state, desired_value, current_value, updated_at }`
  - desired = 백엔드가 시킨 목표, current = 파이가 보고한 실제. 둘이 다르면 "아직 반영 안 됨"
  - 센서는 값이 오면 `current_state`가 `"reported"`가 되고 값은 `current_value`에 들어온다

### 프론트가 부르는 API
- GET `/api/devices` · `/api/reservations`(adminFetch면 PIN 포함) · `/api/songs` · `/api/scores/top?period=today|all&limit=..`
  · `/api/experience/queue` · `/api/booth/session` · `/api/scheduler/status` · `/api/song-videos`
- POST(누구나) `/api/reservations` · `/api/songs` · `/api/scores` · `/api/booth/verify-keypad {pin}` · `/api/experience/tickets {nickname}` · `/api/admin/login {pin}`
- adminFetch(관리자) POST `/api/devices/{id}/control` · `/api/booth/simulate-entry` · `/api/booth/simulate-10min-warning` · `/api/booth/simulate-end`
  · `/api/scheduler/run` · `/api/experience/advance` · `/api/experience/tickets/{id}/cancel` · GET `/api/scores/export` · PUT/DELETE `/api/song-videos/{id}`
- 여기 없는 API를 지어내지 않는다. 필요하면 "백엔드에 이런 API가 필요하다"고 따로 적는다

### WebSocket (`useBoothData.ts`의 handleWsMessage)
`device_state`(기기 상태 바뀜) · `booth_auth`(키패드 인증 결과) · `booth_event`(입장·10분 전·종료) · `reservation_created` · `song_recorded`
· `score_recorded` · `queue_called` · `queue_updated`. 백엔드는 센서 값이 오면 `sensor_reading`도 보낸다 (현재 프론트는 처리하지 않음)

## 디자인 규칙 (이 프로젝트에서 실제로 쓰는 것)
- 색은 **토큰 이름만** 쓴다: `canvas`, `surface`, `raised`, `line`, `line-strong`, `ink`, `ink-2`, `ink-3`, `brass`(유일한 강조색), `brass-soft`,
  `on-accent`, `live`(빨강: 이용 중·위험), `live-soft`, `free`(초록: 정상·가능), `free-soft`. 예: `bg-surface border-line text-ink-2`
  - `slate-800`, `blue-500` 같은 Tailwind 기본 색은 쓰지 않는다. 파랑 토큰은 없다 → 중립 수치는 `ink`/`raised`로
- 테마: 페이지 맨 바깥 div에 `theme-day`(밝음) 또는 `theme-stage`(어두움). 숫자는 `tnum`, PIN·점수는 `font-mono`
- 아이콘은 `lucide-react`(`aria-hidden`), 이모지를 아이콘 대신 쓰지 않는다. 색만으로 뜻을 전하지 않고 글자·아이콘도 함께 바꾼다
- 클릭 요소에 `cursor-pointer`, 키보드 포커스가 보이게, 375px 폭에서도 깨지지 않게
- Tailwind 클래스 이름을 문자열 조합으로 만들지 않는다 (`bg-${color}` 금지 — 빌드 때 사라진다). 완성된 클래스 이름을 조건으로 고른다
- 화면 문구는 한국어 존댓말("체험권 받기", "서버와 통신할 수 없습니다"). 주석은 한국어로 '왜'를 적는다

## 알려진 함정
- ESLint 규칙 `react-hooks/set-state-in-effect` 때문에 useEffect 안의 첫 fetch는 `setTimeout(fn, 0)`으로 감싼다 (기존 코드 참고)
- 환경 변수는 `process.env.NEXT_PUBLIC_API_BASE_URL`처럼 **그대로** 적어야 빌드 때 바뀐다 (변수 이름을 조합하면 안 됨)
- 새로 받은 저장소에서 `tsc`가 `LayoutProps`를 못 찾으면 `npx next typegen`을 한 번 실행한다
- `KaraokeRoomSection.tsx`(1,401줄)·`ReservationSection.tsx`(511줄)는 크다. 새 기능은 새 작은 컴포넌트 파일로 만들고 큰 파일에는 연결만 한다

## karpathy-principles

> AI 에이전트가 코드를 작성하기 전에 항상 지키는 4가지 원칙. Andrej Karpathy의 LLM 코딩
> 실수 패턴 관찰(가정하고 그냥 진행함, 과하게 부풀림, 무관한 부분을 건드림, 모호한 목표로
> 대충 마무리함)에서 가져왔다. 이 rule은 다른 모든 rules/skills와 함께 항상 적용된다.

### 1. 생각 먼저 (Think Before Coding)
- 요청이 애매하면 추측해서 진행하지 말고, 가능한 해석을 제시하거나 질문한다
- 더 간단한 방법이 있으면 먼저 제안한다
- 확신이 없는 부분은 "이 부분이 불확실하다"고 명시적으로 말한다

### 2. 단순함 우선 (Simplicity First)
- 요청받은 것 이상으로 기능을 추가하지 않는다
- 나중에 필요할 것 같다는 이유로 미리 확장 가능하게 만들지 않는다 (YAGNI)
- 200줄로 짤 수 있는 걸 50줄로 될 것 같으면 다시 줄인다

### 3. 외과적 변경 (Surgical Changes)
- 요청과 무관한 코드/주석/포맷은 손대지 않는다 — 마음에 안 들어도 그대로 둔다
- 자신의 변경으로 안 쓰게 된 import/변수만 정리한다. 원래 있던 죽은 코드는 지우지 않고
  발견 사실만 언급한다
- 바뀐 모든 줄은 요청과 직접 연결되어야 한다

### 4. 목표 기반 실행 (Goal-Driven Execution)
- "~해줘" 대신 "성공 기준"으로 바꿔서 요청한다 (예: "검증 추가해줘" → "잘못된 입력에 대한
  테스트를 먼저 쓰고, 통과하게 만들어줘")
- 여러 단계가 필요한 작업은 시작 전에 간단한 계획을 제시한다: 1) 단계 → 확인 방법,
  2) 단계 → 확인 방법
- "됐다"고 말하기 전에 실제로 실행해서 확인한다 — 요약만 믿지 않는다

### 다른 rules와의 연결
- 3번(외과적 변경)은 git-rules.md의 PR 체크리스트("관련 없는 파일 변경이 섞이지
  않았는가")와 같은 원칙이다
- 4번(목표 기반 실행)은 workflows/feature-development.md의 "성공 기준 먼저 정의 →
  검증" 절차로 구체화되어 있다

## UI/UX 규칙 (taste-skill · ui-ux-pro-max 참고)

> 학생 팀 프론트엔드는 대부분 "동작은 하는데 밋밋한" 상태로 끝나는 경우가 많다. 이 규칙은
> frontend-agent가 별도 요청 없이도 매번 최소한의 완성도를 보장하도록 만든 것이다.
> taste-skill(anti-slop 원칙)과 ui-ux-pro-max(체계적 디자인 시스템·배포 전 체크리스트)의
> 핵심만 이 프로젝트(IoT 대시보드) 규모에 맞게 정리했다 — 두 원본의 CLI 설치나 외부 검색
> 엔진(Python 스크립트, 192개 산업별 추천)은 설정 부담이 커서 의도적으로 가져오지 않았다.

### 이 프로젝트의 디자인 시스템 (고정)
- 스타일: 대시보드형 — Linear/Notion 톤의 절제된 미니멀
- 위계: 카드마다 "디바이스 이름(작게) → 값/상태(크게) → 보조 정보(작게)" 순서로 크기
  차등을 준다. 경보성 디바이스(예: 침입감지)는 다른 카드보다 시각적으로 더 크게/눈에
  띄게 배치한다
- 색상 의미 (임의로 바꾸지 않는다)

  | 색 | 의미 |
  |---|---|
  | 초록 | 정상 / ON / 연결됨 |
  | 빨강 | 경고 / 감지됨 / 오류 |
  | 회색 | OFF / 비활성 / 연결 끊김 |
  | 파랑 | 중립 수치 정보(온도·조도 등) |

- 아이콘: 이모지를 아이콘 대용으로 쓰지 않는다 — `lucide-react` 등 실제 SVG 아이콘
  라이브러리를 사용한다
- 폰트: 시스템 기본 산세리프 사용. 한글 폰트가 필요하면 `next/font`로 로컬 서빙한다
  (외부 폰트 API 호출을 늘리지 않는다)

### Anti-Slop 체크 (taste-skill 원칙)
- "AI가 만든 티가 나는" 기본값을 피한다: 보라/핑크 그라디언트 배경, 전부 같은 크기
  카드만 나열한 밋밋한 그리드, 그림자 없는 flat 카드
- 레이아웃에 최소한의 의도적 변주를 준다 — 모든 카드를 똑같은 크기로 나열하지 않는다
- 상태가 바뀔 때(ON/OFF, 값 갱신) 200ms 내외의 짧은 트랜지션을 준다 — 과한 애니메이션은
  피한다
- 여백을 충분히 준다 — 요소를 다닥다닥 붙이지 않는다

### 배포 전 체크리스트 (ui-ux-pro-max 참고, 이 프로젝트 규모로 축소)
- [ ] 이모지를 아이콘 대용으로 쓰지 않았는가
- [ ] 클릭 가능한 요소에 `cursor-pointer`가 적용되어 있는가
- [ ] 텍스트 대비가 충분한가 (옅은 회색 글씨 on 밝은 배경 같은 저대비 조합 금지)
- [ ] 키보드로 포커스 이동 시 포커스 표시가 보이는가
- [ ] 디바이스 이름이 길어져도 카드 레이아웃이 깨지지 않는가 (줄바꿈/말줄임 처리)
- [ ] 모바일 폭(375px)에서도 레이아웃이 깨지지 않는가
- [ ] WebSocket 연결이 끊긴 상태가 화면에 명확히 표시되는가 (끊긴 채로 마지막 값만
      계속 보여주면 사용자가 실시간이라고 착각한다)

## 코딩 표준

### TypeScript (frontend/)
- `strict: true` 유지, `any` 사용 금지 (부득이하면 이유를 주석으로 남기고 `unknown` + 타입가드 사용)
- 컴포넌트 파일명/이름은 PascalCase (`DashboardPanel.tsx`)
- 커스텀 훅은 `use`로 시작 (`useSmartDeviceSocket.ts`)
- API 응답 타입은 `types/` 폴더에 별도 선언, 컴포넌트 안에서 인라인으로 만들지 않는다

### Python (backend/, vision/, pi/)
- 함수/변수는 snake_case, 클래스는 PascalCase
- 모든 함수에 타입힌트를 작성한다 (`def get_sensor_history(device_id: str, limit: int) -> list[dict]:`)
- 예외를 조용히 삼키지 않는다 — 최소한 로그로 남긴다

### 공통
- 매직 넘버/문자열은 상수로 분리한다
- 한 함수는 한 가지 일만 한다 — 길어지면 분리한다

- `.env` 파일은 절대 커밋하지 않는다. `.gitignore`에 `.env`, `.env.local`을 포함한다 (필수)

- 커밋 전 `git diff --cached`로 시크릿이 포함되지 않았는지 직접 확인한다

# 작업 카드 — 오류 고치기

너는 이 프로젝트의 **프론트엔드 개발 도우미**다. 나는 고등학생 프론트엔드 담당이고 초보자다.
위의 프로젝트 카드와 규칙, 아래에 붙인 파일만 사실로 여기고, 모르는 것은 지어내지 말고 물어봐 줘.

## 무엇이 잘못됐나 (증상)
관리자 화면(/admin) 기기 관제에서 문을 열면 '경고 부저'는 바로 바뀌는데, '문 열림 센서'는 새로고침해야 바뀝니다.

## 고쳐졌다고 볼 기준
- 문을 열면 새로고침 없이 1초 안에 '문 열림 센서'가 '열림'으로 바뀐다
- 문을 닫으면 새로고침 없이 '닫힘'으로 돌아온다
- 다른 기기(도어락·전원·조명·부저) 표시는 지금처럼 동작한다

```ts
"use client";

import { useState, useEffect, useCallback, useSyncExternalStore } from "react";
import { apiUrl } from "@/utils/apiConfig";
import {
  adminFetch,
  subscribeAdminSession,
  getAdminSnapshot,
  getAdminServerSnapshot,
} from "@/utils/adminSession";
import { useKaraokeSocket } from "@/hooks/useKaraokeSocket";
import { SCHOOL_ANTHEM_TITLE } from "@/data/karaokeSongs";
import {
  Device,
  QueueSnapshot,
  Reservation,
  ScoreRecord,
  Song,
  WebSocketMessage,
} from "@/types";

/** 부스 화면이 소리 내어 읽을 안내 한 건. seq 가 바뀔 때마다 새 안내다. */
export interface BoothAnnouncement {
  seq: number;
  /** auth · entry_detected · 10min_warning · session_ended · queue_called */
  event: string;
  text: string;
}

/**
 * 키패드 인증 결과 방송.
 * 부스 앞 실물 키패드(라즈베리파이)로 누른 결과는 부스 화면이 HTTP 응답을 받지
 * 못한다. 이 방송으로 받아서 "비밀번호가 틀렸습니다" 같은 안내를 화면에 띄운다.
 */
export interface BoothAuthNotice {
  seq: number;
  success: boolean;
  mode?: string;
  /** invalid(틀림) · not_now(예약 시간 아님) */
  reason?: string;
  message: string;
}

/**
 * 부스 공용 데이터 훅 (부록G §3 화면 분리 / 부록J 작업 1)
 *
 * 세 화면(`/`·`/booth`·`/admin`)이 똑같이 필요로 하는 것을 한곳에 모았다.
 *   - 기기 상태 / 예약 목록 / 노래 기록을 백엔드에서 가져온다
 *   - WebSocket으로 실시간 변경을 받아 위 목록을 갱신한다
 *
 * 예전에는 이 코드가 app/page.tsx 안에 화면과 뒤섞여 있었다. 그대로 두고
 * 라우트를 셋으로 나누면 같은 로직이 세 벌로 복제되고, 한 곳만 고치는 실수가
 * 반드시 생긴다. 그래서 라우트를 나누기 **전에** 먼저 뽑아냈다.
 *
 * 백엔드가 꺼져 있어도 화면은 떠야 하므로, 모든 조회는 실패 시 조용히 넘어가고
 * 빈 목록을 유지한다.
 */
export function useBoothData() {
  const [devices, setDevices] = useState<Device[]>([]);
  const [reservations, setReservations] = useState<Reservation[]>([]);
  const [allSongs, setAllSongs] = useState<Song[]>([]);
  const [favoriteSongs, setFavoriteSongs] = useState<Song[]>([]);
  const [lastEventMsg, setLastEventMsg] = useState<string>("부스 시스템이 정상 대기 중입니다.");
  // 순위 (부록G §2-④) — 오늘 기록과 명예의 전당을 따로 본다
  const [topToday, setTopToday] = useState<ScoreRecord[]>([]);
  const [topAll, setTopAll] = useState<ScoreRecord[]>([]);
  // 축제 교가 부르기 대회 — 오늘 교가 점수, 이름당 최고 기록 하나 (상품 배부 기준)
  const [anthemTop, setAnthemTop] = useState<ScoreRecord[]>([]);
  // 전시 체험 대기열 (부록G §2-③)
  const [queue, setQueue] = useState<QueueSnapshot | null>(null);
  // 부스 화면(/booth)이 읽어 줄 안내와 키패드 인증 결과.
  // 소리는 부스에서 나야 한다 — 예전에는 선생님 노트북(/admin)에서 났다.
  const [announcement, setAnnouncement] = useState<BoothAnnouncement | null>(null);
  const [authNotice, setAuthNotice] = useState<BoothAuthNotice | null>(null);

  const announce = useCallback((event: string, text?: string) => {
    // 이용 종료는 읽을 문장이 없어도 퇴실곡을 틀어야 하므로 그대로 넘긴다
    if (!text && event !== "session_ended") return;
    setAnnouncement((prev) => ({ seq: (prev?.seq ?? 0) + 1, event, text: text ?? "" }));
  }, []);

  const fetchDevices = useCallback(async () => {
    try {
      const res = await fetch(apiUrl("/api/devices"));
      if (res.ok) {
        const json = await res.json();
        setDevices(json.data || []);
      }
    } catch {
      // 백엔드가 아직 안 떴을 수 있다 — 화면은 그대로 둔다
    }
  }, []);

  // 예약 PIN은 서버가 관리자에게만 내려준다. adminFetch 는 관리자 토큰이 있을 때만
  // 헤더에 붙이므로, 학생·부스 화면에서는 PIN 없이 목록만 받는다.
  const fetchReservations = useCallback(async () => {
    try {
      const res = await adminFetch("/api/reservations");
      if (res.ok) {
        const json = await res.json();
        setReservations(json.data || []);
      }
    } catch {
      // 위와 같다
    }
  }, []);

  const fetchSongs = useCallback(async () => {
    try {
      const res = await fetch(apiUrl("/api/songs"));
      if (res.ok) {
        const json = await res.json();
        setAllSongs(json.data?.all || []);
        setFavoriteSongs(json.data?.favorites || []);
      }
    } catch {
      // 위와 같다
    }
  }, []);

  const fetchScores = useCallback(async () => {
    try {
      const anthemQuery = `period=today&limit=10&best=true&title=${encodeURIComponent(SCHOOL_ANTHEM_TITLE)}`;
      const [todayRes, allRes, anthemRes] = await Promise.all([
        fetch(apiUrl("/api/scores/top?period=today&limit=5")),
        fetch(apiUrl("/api/scores/top?period=all&limit=5")),
        fetch(apiUrl(`/api/scores/top?${anthemQuery}`)),
      ]);
      if (todayRes.ok) setTopToday((await todayRes.json()).data || []);
      if (allRes.ok) setTopAll((await allRes.json()).data || []);
      if (anthemRes.ok) setAnthemTop((await anthemRes.json()).data || []);
    } catch {
      // 순위를 못 받아도 노래방은 돌아가야 한다
    }
  }, []);

  const fetchQueue = useCallback(async () => {
    try {
      const res = await fetch(apiUrl("/api/experience/queue"));
      if (res.ok) setQueue((await res.json()).data ?? null);
    } catch {
      // 대기열을 못 받아도 노래방은 돌아가야 한다
    }
  }, []);

  // 관리자로 로그인·로그아웃하면 예약 목록을 다시 받는다 (PIN이 보였다 사라졌다 한다)
  const adminAuthed = useSyncExternalStore(
    subscribeAdminSession,
    getAdminSnapshot,
    getAdminServerSnapshot
  );

  useEffect(() => {
    // effect 본문에서 곧바로 상태를 바꾸지 않도록 첫 조회를 한 틱 미룬다
    // (React 19 규칙 react-hooks/set-state-in-effect)
    const id = setTimeout(() => {
      fetchDevices();
      fetchSongs();
      fetchScores();
      fetchQueue();
    }, 0);
    return () => clearTimeout(id);
  }, [fetchDevices, fetchSongs, fetchScores, fetchQueue]);

  useEffect(() => {
    const id = setTimeout(fetchReservations, 0);
    return () => clearTimeout(id);
  }, [fetchReservations, adminAuthed]);

  const handleWsMessage = useCallback(
    (msg: WebSocketMessage) => {
      if (msg.type === "device_state" && msg.device_id) {
        // 관리자 화면의 [스피커 테스트] — 부스 스피커는 부스 화면이 울린다.
        // (actor "user" = 관리자 제어. 파이가 보고한 상태(actor "device")는 읽지 않는다)
        const spoken = (msg.value as { message?: unknown } | null)?.message;
        if (
          msg.device_id === "speaker_1" &&
          msg.actor === "user" &&
          msg.state === "playing" &&
          typeof spoken === "string"
        ) {
          announce("speaker_test", spoken);
        }
        setDevices((prev) =>
          prev.map((d) =>
            d.id === msg.device_id
              ? {
                  ...d,
                  current_state: msg.state ?? d.current_state,
                  current_value: msg.value ?? d.current_value,
                }
              : d
          )
        );
      } else if (msg.type === "booth_auth") {
        const text = msg.message || (msg.success ? "인증 성공!" : "인증 실패!");
        setLastEventMsg(text);
        setAuthNotice((prev) => ({
          seq: (prev?.seq ?? 0) + 1,
          success: Boolean(msg.success),
          mode: msg.mode,
          reason: msg.reason,
          message: text,
        }));
        announce("auth", msg.speech);
        fetchDevices();
      } else if (msg.type === "booth_event") {
        setLastEventMsg(msg.message || "부스 이벤트 감지됨");
        announce(msg.event ?? "booth_event", msg.speech);
        fetchDevices();
      } else if (msg.type === "reservation_created") {
        fetchReservations();
      } else if (msg.type === "song_recorded") {
        fetchSongs();
      } else if (msg.type === "score_recorded") {
        // 누군가 점수를 받으면 부스 화면의 순위가 즉시 바뀐다
        setLastEventMsg(
          `${msg.nickname ?? "익명"}님이 ${msg.title ?? "노래"}로 ${msg.score ?? 0}점을 받았습니다!`
        );
        fetchScores();
      } else if (msg.type === "queue_called") {
        const text = msg.message || `${msg.ticket_no ?? ""}번 입장해 주세요!`;
        setLastEventMsg(text);
        announce("queue_called", msg.speech ?? text);
        fetchQueue();
      } else if (msg.type === "queue_updated") {
        fetchQueue();
      }
    },
    [fetchDevices, fetchReservations, fetchSongs, fetchScores, fetchQueue, announce]
  );

  const { isConnected } = useKaraokeSocket(handleWsMessage);

  return {
    devices,
    reservations,
    allSongs,
    favoriteSongs,
    lastEventMsg,
    topToday,
    topAll,
    anthemTop,
    queue,
    announcement,
    authNotice,
    isConnected,
    fetchDevices,
    fetchReservations,
    fetchSongs,
    fetchScores,
    fetchQueue,
  };
}

/** 헤더 시계 — 서버에서 렌더링하면 시간이 어긋나므로 브라우저에서만 돈다 */
export function useClock(): string {
  const [timeStr, setTimeStr] = useState<string>("");

  useEffect(() => {
    // ko-KR 기본 형식은 "1시 16분 39초"라 자리수가 들쭉날쭉하고 제품 화면에 어울리지 않는다.
    // 두 자리로 고정해 숫자가 흔들리지 않게 한다 (.tnum 과 함께 쓴다).
    const pad = (n: number) => String(n).padStart(2, "0");
    const tick = () => {
      const d = new Date();
      setTimeStr(`${pad(d.getHours())}:${pad(d.getMinutes())}:${pad(d.getSeconds())}`);
    };
    tick();
    const id = setInterval(tick, 1000);
    return () => clearInterval(id);
  }, []);

  return timeStr;
}
```

# 답변 형식 (반드시 지켜 줘)

나는 네가 준 코드를 VS Code에서 **파일 전체를 지우고 그대로 붙여 넣는** 방식으로 반영한다. 그래서:

1. **먼저 계획만** 말해 줘. 코드는 아직 쓰지 말 것.
   - 바꿀 파일과 새로 만들 파일 목록, 파일마다 무엇을 왜 바꾸는지 한두 줄
   - 마지막 줄에 "진행할까요?"라고 묻고 멈출 것. 내가 "진행"이라고 하면 코드를 준다
2. 코드는 **한 번에 파일 하나씩**, 이 모양으로 준다. 파일이 더 있으면 내가 "다음"이라고 할 때 다음 파일을 준다.
   ### 파일: frontend/경로/파일이름.tsx (수정 또는 새 파일)
   ```tsx
   (파일의 첫 줄부터 마지막 줄까지 전부)
   ```
3. **절대 생략하지 말 것.** `...`, `// 기존 코드 동일`, `// 나머지는 그대로`, `/* 생략 */` 같은 줄을 쓰면 안 된다.
   바꾸지 않은 줄도 한 글자도 빠짐없이 그대로 다시 써 줘. 바꾸는 곳 밖의 코드와 주석은 고치지 말 것.
4. **400줄이 넘는 큰 파일**은 되도록 고치지 말고, 새 기능을 작은 새 컴포넌트 파일로 만들어 큰 파일에는 연결만 하도록 설계해 줘.
   그래도 큰 파일을 고쳐야 하면 파일 전체를 `(1/3)`, `(2/3)`, `(3/3)`처럼 나눠서 주고, 나눈 조각마다 끝에
   `// ===== 여기까지 (1/3) — 다음 조각에 이어짐 =====`, 마지막 조각 끝에는 `// ===== 파일 끝 (3/3) =====`을 붙여 줘.
   조각은 함수나 컴포넌트가 끝난 자리(JSX 안이 아닌 곳)에서만 나눌 것. 나는 조각을 순서대로 이어 붙인다.
5. 붙여 준 파일에 없는 함수·컴포넌트·API·npm 패키지를 지어내지 말 것. 필요한 정보가 없으면 코드를 쓰기 전에 물어볼 것.
6. 마지막 파일을 준 뒤에는 **확인 방법**을 적어 줘: 실행할 명령(`npm run ai:check`, `npm run dev` 등)과 화면에서 무엇을 보면 되는지.
