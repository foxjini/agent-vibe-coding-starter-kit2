# 2차 개발 통합 매뉴얼 — 학생용

> 📂 **2차 작업은 이 문서 하나로 시작해서 이 문서 하나로 끝냅니다.**
> 4개 팀(wakeup · classroom · study · subway) 공통입니다.
> 설치부터 배치표·화면·영상인식·자가 점검·배포까지 전부 여기 있습니다.

## 0. 먼저 읽어 주세요 — 문서는 이것 하나입니다

docs 폴더에 파일이 많지만, **2차 작업 중에 펼칠 문서는 둘뿐입니다.**
**기능은 이 문서(00), 화면 디자인은 [06 교재](06-프론트엔드-UI-UX-디자인-교재.md)** 입니다.

| 문서 | 2차 작업에 필요한가 |

| 02 수작업 로드맵 · 04 전시회 아이디어 | 1차 때 쓰던 진행표와 전시회 기획안. 참고용 |

> 🙋 **막혔을 때 순서**: ① 9장 자가 점검 돌리기 → ② 10장 증상표 찾기 → ③ 8장 방법으로 AI에게 묻기 → ④ 선생님.

> 🤖 **우리는 채팅형 AI로 개발합니다.** Claude.ai · ChatGPT · Gemini에 **컨텍스트 팩 파일 하나**를
> 올리고 요청하면, 받은 코드를 **직접 파일에 붙여넣습니다.** AI가 우리 폴더를 읽거나
> 고치는 에이전트 도구(Claude Code · Codex · Antigravity)는 쓰지 않습니다. 방법은 **8장**에 있습니다.

### 이 시스템은 무엇으로 되어 있나

```
[웹 대시보드]  Next.js      ← 우리 팀 화면 + 시나리오(게임·미션)의 "두뇌"
      │ REST + WebSocket
[백엔드]       FastAPI      ← 슬롯 20개만 안다. 팀 부품 이름을 모른다
      │              └ [DB] MariaDB — 기록 보관 (꺼져 있어도 시스템은 동작)
      ├─ REST 폴링 ─ [라즈베리파이]  daemon.py + slot_map.py ← 실제 부품
      └─ REST 이벤트 ─ [영상인식]    main.py + detectors/    ← 웹캠
```

핵심 한 문장: **부품을 바꿔도 백엔드와 DB는 고치지 않습니다.**

## 1. 약속 — 우리가 고치는 곳은 정해져 있습니다

| 하고 싶은 것 | 고치는 곳 | 담당 |
|---|---|---|
| 부품 추가·제거·핀 변경 | `pi/slot_map.py` **한 줄** | 라즈베리파이 |
| 화면 디자인·시나리오(게임·미션) | `frontend/app/page.tsx` · `scenarios/` · `components/team/` | 프론트엔드 |
| 반복 자동화(임계값·정해진 시각) | **코드 아님** — 대시보드 `/kit` 규칙 편집기 | 누구나 |
| 카메라 감지 **대상** (사람·컵·책…) | **코드 아님** — 대시보드 `/kit` 영상인식 설정 | 누구나 |
| 카메라 감지 **방법** (손동작·자세…) | `vision/detectors/<우리팀>.py` **파일 하나** | 영상인식 |

### 고치지 않는 곳 (4팀 공통 코드)

```
backend/          전부            ← 슬롯 20개와 API만 안다
backend/db/       전부            ← 스키마 확정. 바꾸면 4팀이 전부 영향
vision/main.py                    ← 공통 루프
vision/camera.py                  ← 카메라 열기
vision/detectors/base.py          ← 검출기 계약
vision/detectors/__init__.py      ← 검출기 로더
vision/detectors/objects.py       ← 사물 탐지(YOLO) — 4팀이 같이 씀
frontend/lib/ · frontend/components/kit/   ← 키트 제공 (고쳐도 되지만 합칠 때 충돌)
```

> ⚠️ 위 목록을 고쳐야 할 것 같으면 **멈추고 선생님께 물어보세요.**
> 대부분은 위 표의 다섯 가지 중 하나로 해결됩니다. 한 팀이 혼자 고치면 합칠 때 충돌합니다.
>
> 💡 감지 **방법**을 추가할 때조차 백엔드와 대시보드는 고치지 않습니다. 검출기가 부팅할 때
> 자기 라벨을 서버에 신고하고, 설정 화면과 규칙 편집기가 그 신고를 보고 자동으로 채워집니다.

## 2. 첫날 ① 내 PC 준비

### 2-2. 환경변수 파일 만들기

```powershell
copy backend\.env.example  backend\.env
copy frontend\.env.example frontend\.env.local
copy vision\.env.example   vision\.env
copy pi\.env.example       pi\.env
```

> 🔐 **`DEVICE_API_KEY`는 backend · vision · pi 세 곳이 똑같아야 합니다.**

1. **XAMPP Control Panel**에서 MySQL(MariaDB) **Start**

## 4. 라즈베리파이 담당 — 고치는 파일은 `slot_map.py` 하나

### 4-1. 우리 팀 배치표 만들기

```bash
cd pi
cp examples/slot_map_classroom.py slot_map.py   # 자기 팀 예시를 복사
python daemon.py --check                        # 핀 충돌·오타를 실행 전에 확인
python daemon.py                                # 실행
```

예시는 `pi/examples/`에 팀별로 4개 있습니다. **핀 번호만** 실제 배선에 맞게 고치세요.
배치표를 고치고 데몬을 다시 실행하면 **대시보드 카드가 자동으로 생기고 사라집니다.**

`slot_map.py`는 이렇게 생겼습니다 — 한 줄이 부품 하나입니다:

```python
SLOTS = {
    "actuator_01": {"label": "자동문", "kind": "servo", "driver": "servo",
                    "pin": 12, "control_type": "servo"},
    "actuator_02": {"label": "교실 조명", "kind": "relay", "driver": "digital_out",
                    "pin": 25, "control_type": "onoff"},
    "sensor_01":   {"label": "실내 온도", "kind": "temperature", "driver": "dht_in",
                    "pin": 4, "unit": "°C", "interval": 5},
}
```

| 한 줄에 적는 것 | 뜻 |
|---|---|
| `label` | 대시보드에 보일 이름 (한글로) |
| `kind` | 부품 종류 (아이콘·표시 방식 결정) |
| `driver` | `drivers/` 폴더의 파일 이름 (4-2 표) |
| `pin` | GPIO 번호 (BCM 기준 — 보드의 물리 핀 번호가 아닙니다) |
| `pins` | 핀을 **여러 개** 쓰는 부품만: `[5, 6, 13]` 또는 `{"r":17,"g":27,"b":22}` |
| `control_type` | 대시보드 위젯 모양 (액추에이터만, 4-3 표) |
| `unit` | 단위 (센서만): `°C` `kg` `cm` |
| `interval` | 센서를 몇 초마다 읽을지 (기본 1초, 온습도는 5초 이상) |

> 슬롯 이름은 `sensor_01~sensor_10`, `actuator_01~actuator_10`으로 **정해져 있습니다.**
> 안 쓰는 슬롯은 그냥 적지 않으면 됩니다.

### 4-2. 쓸 수 있는 드라이버 (키트 제공 11종)

| 드라이버 | 무엇에 | 핀 |
|---|---|---|
| `digital_out` | LED · 릴레이 · 액티브 부저 (on/off) | `pin` |
| `pwm_out` | 진동모터 세기 · LED 밝기 · 모터 속도 | `pin` |
| `tonal_buzzer` | 주파수 지정 부저 (`buzzer_type`: `passive`/`active`) | `pin` |
| `servo` | 서보모터 각도 | `pin` |
| `neopixel_out` | RGB 스트립 (데이터선 1개로 여러 알) | `pin` |
| `rgb_out` | 3핀 RGB LED | `pins: {"r":…,"g":…,"b":…}` |
| `level_out` | 단계 표시 (LED 여러 개) | `pins: [5, 6, 13]` |
| `button_in` | 버튼 · 터치센서 · PIR (`pull_up`: 극성) | `pin` |
| `analog_in` | 압력 · 조도 (ADC 경유) | `pin` |
| `dht_in` | 온습도 | `pin` |
| `distance_in` | 초음파 거리 | `trigger_pin`, `echo_pin` |

확인: `python -c "import drivers; print(drivers.available_drivers())"`

### 4-3. `control_type` — 이 값이 대시보드 위젯을 결정합니다

| control_type | 상태 값 | 세부 값 | 대시보드 위젯 |
|---|---|---|---|
| `onoff` | `"on"` / `"off"` | 없음 | 토글 스위치 |
| `pulse` | `"on"` / `"off"` | `{"on_time":0.25,"off_time":0.15}` | 토글 + 점멸 주기 |
| `tonal` | `"on"` / `"off"` | `{"frequency":1000,"volume":80}` | 토글 + 주파수·볼륨 |
| `pwm` | `"on"` / `"off"` | `{"duty":0~100}` | 슬라이더 |
| `servo` | `"move"` / `"off"` | `{"angle":0~180}` | 각도 다이얼 |
| `rgb` | `"on"` / `"off"` | `{"r":0-255,"g":…,"b":…}` | 컬러 피커 |
| `level` | `"on"` / `"off"` | `{"level":0~N}` | 단계 버튼 |

### 4-4. 센서 보고 형식 — 숫자는 반드시 `value`

| kind | 보고 형식 |
|---|---|
| `button`, `touch` | `{"pressed": true}` |
| `presence`, `motion` | `{"detected": true}` |
| `temperature`, `humidity`, `distance`, `pressure`, `light` | `{"value": 24.5}` |

> ⚠️ **숫자 센서는 반드시 `{"value": 숫자}`입니다.** 이것만 지키면 **차트가 코드 수정 없이 자동으로** 그려집니다.
> 온습도처럼 값이 둘이면 슬롯 2개로 나누세요. (드라이버를 쓰면 이 형식은 자동입니다.)

### 4-5. 부품을 바꿀 때

| 상황 | 할 일 |
|---|---|
| 부품 추가 | `SLOTS`에 한 줄 추가 |
| 부품 제거 | 그 줄 삭제 (대시보드에서도 사라집니다) |
| 핀 변경 | `pin` 값만 수정 |
| 소리가 안 나거나 '틱'만 남 | `buzzer_type`을 `passive` ↔ `active` |
| 버튼이 안 눌림 | `pull_up`을 반대로 |
| 키트에 없는 부품 | `drivers/`에 파일 하나 추가 (`apply`/`read` 2개 메서드) |

### 4-6. 실기기 연동 (Mock → 라즈베리파이 5)

**① 파이 환경** — `gpiozero`/`lgpio`는 pip로 설치하면 빌드 오류가 나므로 OS 패키지를 씁니다:

```bash
sudo apt update && sudo apt install -y python3-gpiozero python3-lgpio
cd pi
python3 -m venv --system-site-packages venv     # ← 옵션이 중요합니다
source venv/bin/activate
pip install -r requirements.txt
```

**② PC IP 확인** (`ipconfig`) 후 `pi/.env` 수정:

```env
BACKEND_URL=http://192.168.0.25:8000    # localhost 아님 — PC의 실제 IP
DEVICE_API_KEY=우리팀이_만든_키            # backend/.env와 똑같이
DEVICE_MODE=hardware
```

**③ PC 백엔드**도 `backend/.env`에 `DEVICE_MODE=hardware`.
Windows 방화벽 경고가 뜨면 **"개인 네트워크" 허용**. 계속 거부되면 관리자 PowerShell에서:

```powershell
New-NetFirewallRule -DisplayName "FastAPI 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```

**④ 배선 → 점검 → 실행**. 전원을 끈 상태에서 배선하고, 교사 입회 하에 켠 뒤:

```bash
python daemon.py --check       # GPIO를 건드리기 전에 배치표·주소·핀 충돌 확인
python test_slot_daemon.py     # GPIO·백엔드 없이 39개 항목 자가 점검
python daemon.py               # 실행
```

> PC에서는 부품이 없어도 **자동으로 흉내내기(Mock)로 대체**되어 그대로 돌아갑니다.
> 파이에서 "흉내내기 모드"라고 나오면 배선·권한을 확인하세요.

### 5-0. 화면 셋 — 어디를 고치나

>
> 💡 **study 팀은** `app/study/page.tsx`를 `app/page.tsx`로 복사하면 `/`가 집중도 화면이 됩니다.
>
> 💡 **다른 팀은** 자기 것이 아닌 팀 파일(`scenarios/useWakeup.ts` · `wakeupEngine.ts` ·
> `scenarios/study*` · `app/wakeup/` · `app/study/` · `components/team/`)을 지워도 됩니다.

>
> ⚠️ 어느 화면이든 **`useScenario()`는 한 번만** 부르세요. 부를 때마다 WebSocket·구독·알림이
> 따로 생겨서, 한쪽에서 띄운 알림이 화면에 안 나타납니다. 시나리오 훅이 돌려주는
> `scenario`를 꺼내 쓰면 됩니다 (`useWakeup` · `useStudy` 둘 다 그렇게 돼 있습니다).

> 색·글꼴·아이콘·애니메이션은 **기능이 동작한 다음에** 손대세요. 순서를 바꾸면 두 번 일합니다.
> 다만 06의 **6장(디자인 스타일 고르기)은 팀 전체가 일찍 한 번** 보는 편이 좋습니다.

### 5-1. 슬롯 카드는 자동으로 그려집니다

`frontend/app/page.tsx`가 우리 팀 화면입니다. 슬롯 카드는 한 줄이면 됩니다:

```tsx
const { slots, setActuator } = useScenario();

<SlotGrid slots={slots} onControl={setActuator} />   {/* 부품이 바뀌어도 이 줄은 그대로 */}
```

위젯 모양은 `control_type`이 결정하므로 **부품을 바꿔도 화면 코드를 고치지 않습니다.**
부저를 서보로 바꿔도 이 한 줄이 각도 다이얼로 알아서 바뀝니다.

### 5-2. 시나리오 SDK — 프론트엔드가 "두뇌"입니다

라운드·승수·재시도가 있는 게임 로직은 **백엔드에 만들지 않습니다.** `useScenario()`로 씁니다.

```tsx
const {
  slots,          // 현재 슬롯 상태 (실시간 갱신)
  slotOf,         // slotOf("actuator_01")
  connected,      // WebSocket 연결 여부
  setActuator,    // setActuator("actuator_01", "on", { frequency: 1000 })
  onSensor,       // onSensor("sensor_01", e => { if (e.pressed) … })
  onVision,       // onVision(["person","cup"], e => { … })  · null이면 전부
  onSlotChange,   // onSlotChange("actuator_01", s => { … })
  after, cancel,  // after(60, cb) — 지연 실행 (취소 가능)
  notify, notices,// 화면 알림
  serverTimer,    // 브라우저를 닫아도 살아있는 타이머
  refresh,
} = useScenario();
```

구독 함수는 **해지 함수를 돌려줍니다.** `useEffect`에서 등록했으면 정리 함수로 해지하세요:

```tsx
// 압력센서 값에 따라 혼잡도 LED 단계를 바꾼다
useEffect(() => onSensor("sensor_01", (e) => {
  const level = e.number! > 60 ? 3 : e.number! > 30 ? 2 : 1;
  void setActuator("actuator_01", "on", { level });
}), [onSensor, setActuator]);
```

### 5-3. 판정 규칙은 화면과 분리해서 쓰세요

React 없이 **순수 함수**로 만들면 브라우저 없이 바로 테스트할 수 있습니다.
wakeup 팀의 기상 미션이 그대로 본보기입니다:

| 파일 | 역할 |

| `frontend/scenarios/wakeupEngine.test.ts` | 그 규칙 자가 점검 30항목 |
| `frontend/scenarios/useWakeup.ts` | 진행(알람 → 미션 → 2차 수면 방지) |
| `frontend/app/wakeup/page.tsx` | 그것을 화면에 그린 곳 (`/wakeup`에서 직접 볼 수 있습니다) |

```bash
cd frontend && node --experimental-strip-types scenarios/wakeupEngine.test.ts
```

### 5-4. 브라우저 탭을 닫으면 시나리오가 멈춥니다

| 상황 | 어디에 맡기나 |
|---|---|
| 화면이 열려 있는 동안의 게임·미션 | 시나리오 SDK (`onVision`, `after`) |

## 6. 영상인식 담당 — 대상은 설정, 방법은 파일 하나

vision은 **공통 루프 + 검출기 플러그인**으로 나뉩니다. 팀이 건드리는 건 `detectors/` 안뿐입니다.

```
vision/
  main.py                  공통 — 카메라를 열고, 검출기를 돌리고, 보내고, 보여 줌
  camera.py                공통 — USB 웹캠 / Pi Camera 자동 선택
  detectors/
    base.py                공통 — 검출기 계약 (고치지 않습니다)
    __init__.py            공통 — 폴더를 훑어 자동으로 찾는 로더
    objects.py             공통 — 사물 탐지(YOLO). 4팀이 같이 씁니다
    hands_rps.py           ★ wakeup 팀 — 가위바위보 손동작
    _hands_rps_engine.py     `_`로 시작하면 검출기가 아닌 보조 모듈
    <우리팀>.py              ★ 여기에 파일 하나 추가하면 끝
```

### 6-1. 감지 **대상** 바꾸기 — 코드 아님

대시보드 `/kit` → **영상인식 설정**에서 고릅니다. 비전 클라이언트가 **5초 안에** 반영합니다
(프로그램을 다시 켜지 않아도 됩니다). 자동화 규칙에 쓴 라벨은 적지 않아도 자동 포함됩니다.

### 6-2. 감지 **방법** 추가하기 — 파일 하나

`detectors/`에 파일을 넣으면 **자동으로 인식됩니다.** 등록할 곳이 없습니다.

```python
# vision/detectors/stretch.py
from typing import Any, Dict, List
from .base import DetectionEvent, FrameDetector

class Detector(FrameDetector):
    name = "stretch"                    # 설정에서 이 이름으로 켭니다
    labels = ("banzai",)                # 내가 내보낼 라벨 (서버에 신고됩니다)
    description = "만세 스트레칭 자세"

    def __init__(self) -> None:
        super().__init__()
        try:
            import mediapipe            # 없으면 이 검출기만 꺼집니다
        except Exception as exc:
            self.disable(f"MediaPipe를 쓸 수 없습니다: {exc}")

    def detect(self, frame_bgr, config: Dict[str, Any]) -> List[DetectionEvent]:
        if not self.available:
            return []
        # … 자세를 판정해서 …
        return [DetectionEvent(label="banzai", detected=True, confidence=0.9)]
```

규칙 두 가지만 지키면 됩니다.

1. `FrameDetector`를 상속한 **`Detector` 클래스**를 둡니다.
2. 검출기가 아닌 보조 모듈은 파일 이름을 **`_`로 시작**하세요 (로더가 건너뜁니다).

> ⚠️ **검출기는 판정하지 않습니다.** "무엇이 보이는가"만 말하고, 이겼는지·혼잡한지는
> 프론트엔드 시나리오가 판정합니다. 라이브러리가 없으면 `self.disable("이유")` —
> 그 검출기만 빠지고 사물 감지는 그대로 돌아갑니다.

#### 좌석·구역처럼 **여러 곳을 따로** 봐야 한다면

라벨은 **'어디'**, `extra`는 **'어떤 상태'**로 나눕니다 (study 팀 좌석 6개가 이 경우입니다).

```python
labels = ("seat_1", "seat_2", "seat_3", "seat_4", "seat_5", "seat_6")   # 어디
DetectionEvent(label="seat_3", detected=True, confidence=0.92,
               extra={"state": "drowsy", "focus_score": 0.21})          # 어떤
```

화면에서는 이렇게 받습니다.

```tsx
onVision(["seat_1", "seat_2", "seat_3"], (e) => {
  const seat  = e.label;                 // "seat_3"
  const state = e.extra?.state;          // "drowsy"
  const focus = e.extra?.focus_score;    // 0.21
});
```

| 담을 것 | 어디에 |
|---|---|
| 무엇을/어디를 봤나 | `label` |
| **얼마나 확신**하나 | `confidence` |
| 같은 것이 몇 개인가 | `count` |
| 그 밖의 값 (상태·점수) | `extra` |

> ⚠️ **`confidence`에 집중도 같은 측정 점수를 넣지 마세요.** 이 값은 "얼마나 확신하는가"라서,
> 자동화 규칙의 `min_confidence`가 낮은 값을 걸러내 **조용히 무시됩니다.** 점수는 `extra`로.
>
> ⚠️ **`extra`는 화면까지 실시간으로만 갑니다 — 기록(DB)에는 저장되지 않습니다.**
> 나중에 다시 볼 이력은 `label`로 남기세요. 크기는 JSON 2KB·키 20개까지이고,
> 넘으면 **오류로 분명히 알려 줍니다**(조용히 사라지지 않습니다).

**백엔드는 우리 라벨 이름을 모릅니다.** 비전 클라이언트가 부팅할 때 자기 검출기와 라벨을
신고하고, 그때 설정 화면과 규칙 편집기에 자동으로 나타납니다. 그래서 검출기를 추가해도
**백엔드 0줄 · 대시보드 0줄**입니다.

### 6-3. study 팀 예시 — 한 사람의 집중도 (눈·고개·시선)

책상 앞 **한 사람**의 얼굴을 보고, 눈이 감겼는지·고개를 숙였는지·시선이 벗어났는지를
재서 집중도로 바꿉니다. **FHD 웹캠 한 대**면 됩니다.

#### 왜 한 사람인가 — 여러 자리를 한 번에 보면 눈을 못 잽니다

MediaPipe는 얼굴을 잘라 **192×192로 맞춰** 눈을 찾습니다. 얼굴이 그보다 작게 잡히면
억지로 늘려서 눈꺼풀·눈동자가 뭉갭니다. 화면에 잡히는 얼굴 폭을 계산하면 이렇습니다.

| 배치 | 얼굴 폭(추정) | 눈을 잴 수 있나 |
|---|---|---|
| **FHD · 0.5m** | 440~530px | ✅ 눈동자·시선까지 |
| **FHD · 0.8m** | 270~330px | ✅ 눈동자·시선까지 |
| **FHD · 1.0m** | 220~270px | ✅ 눈동자·시선까지 |
| 640×480 · 3m (6자리를 한 화면에) | 24~30px | ❌ 아무것도 안 됨 |

그래서 study 팀은 **자리 하나를 제대로** 봅니다.
`pi/examples/slot_map_study.py`의 부품(등받이·방석 진동 모터, 스탠드)도 원래 한 자리용입니다.

#### ① 카메라 준비

1. FHD 웹캠을 **얼굴에서 0.5~1.0m 앞**에 둡니다 (정면, 눈높이 근처)
2. `vision/.env`에 해상도를 적습니다

```ini
CAMERA_WIDTH=1920
CAMERA_HEIGHT=1080
```

3. MediaPipe를 설치합니다 (`requirements.txt`에 이미 있습니다)

```bash
cd vision && pip install mediapipe
```

> 없어도 됩니다 — 그 경우 이 검출기만 쉬고 사물 감지는 그대로 돌아갑니다.

#### ② 켜기

`/kit` → 영상인식 설정에서 **`study_focus`**를 켭니다. 코드는 건드리지 않습니다.

```bash
cd vision && python main.py
```

웹캠 창에 얼굴 상자와 함께 `face 268px OK`가 뜨면 잘 잡힌 것입니다.
`TOO SMALL - move closer`가 뜨면 카메라를 더 가까이 옮기세요.

#### ③ 내보내는 라벨 네 개

자동화 규칙(`/kit`)은 **켜질 때만** 동작합니다. 그래서 "얼굴이 없다"도 켜지는 라벨로 둡니다.

| 라벨 | 언제 켜지나 | 어디에 쓰나 |
|---|---|---|
| `face_visible` | 얼굴이 보임 | 측정값 전부가 `extra`에 실려 화면으로 |
| `eyes_closed` | 눈을 1.2초 이상 이어서 감음 | 규칙 → 방석 진동 |
| `look_away` | 시선·고개가 오래 벗어남 | 규칙 → 알림 |
| `no_face` | 얼굴이 안 보임 (자리 비움) | 규칙 → 스탠드 끄기 |

`face_visible`의 `extra`는 이렇게 옵니다.

```json
{"samples": 20, "face": true, "eyes_open": 0.86, "closed_ratio": 0.08,
 "closed_run": 0.3, "head_down": 0.12, "look_away": 0.20,
 "no_face": 0.0, "face_px": 268, "calibrated": true}
```

> **한 프레임 값이 아니라 2초 동안 모은 요약입니다.** 전송은 2.5초에 한 번이라,
> 그 순간이 하필 눈을 깜빡인 프레임이면 "졸고 있음"이 되기 때문입니다.
> `closed_run`(가장 길게 이어서 감고 있던 시간)이 **깜빡임과 졸음을 가르는 값**입니다.

#### ④ 화면에서 받기

```tsx
import { useStudy } from "@/scenarios/useStudy";

const study = useStudy();
study.state;        // "focused" | "distracted" | "drowsy" | "away" | "unknown"
study.score;        // 0~100 (판정할 수 없으면 null)
study.summary;      // 집중 시간·비율·졸음 횟수
study.cameraTooFar; // 얼굴이 작게 잡히고 있는가
```

완성된 화면이 **`/study`** 주소에 있습니다 (`frontend/app/study/page.tsx`).

## 7. 코드가 아닌 것 — 대시보드 `/kit`

`/kit` 화면에는 탭이 네 개 있고, **뒤의 세 개가 "코드 대신 쓰는" 곳**입니다.

| 탭 | 무엇을 하나 |
|---|---|
| 대시보드 | 켜져 있는 슬롯 카드를 보고 직접 제어 (동작 확인용) |
| 하드웨어 구성 | 슬롯 20칸의 라벨·종류·단위·사용 여부 |
| 자동화 규칙 | "온도가 28도를 넘으면 선풍기 켜기" 같은 반복 자동화 |
| 영상인식 설정 | 감지 대상 · 최소 신뢰도 · 돌릴 검출기 |

규칙은 **브라우저를 닫아도 백엔드가 실행합니다.** 알람 예약도 규칙입니다.

### 규칙으로 쓸 수 있는 것

| 트리거 (셋 중 하나) | 적는 값 | 예시 |
|---|---|---|
| `schedule` | `at: "07:30"` 또는 `in_seconds: 5` | 알람 시각 |
| `sensor_threshold` | `slot_id`, `op`(`>` `>=` `<` `<=` `==` `!=`), `value`, `for_seconds` | 온도·압력·거리 |
| `vision_label` | `label`, `min_confidence`, `count_at_least` | 사람 감지 시 조명 on |

| 액션 (둘 중 하나) | 적는 값 |
|---|---|
| `set_actuator` | `slot_id`, `state`, `value`(선택), `after_seconds`(선택 — N초 후) |
| `notify` | `level`(`info`/`warn`/`alert`), `message` |

> 라운드·승수가 있는 **게임 로직은 규칙으로 만들지 마세요.** 5장의 시나리오 SDK로 씁니다.

## 8. AI와 함께 작업하기 (채팅형 AI · 프롬프트 바이브 코딩)

우리는 **Claude.ai · ChatGPT · Gemini 같은 채팅형 AI**로 개발합니다.
AI 에이전트 도구(Claude Code · Codex · Antigravity)는 쓰지 않습니다 —
AI가 우리 폴더를 직접 읽거나 고칠 수 없다는 뜻입니다.

그래서 순서가 이렇습니다.

```
① 컨텍스트 팩 만들기  →  ② 채팅창에 올리고 요청  →  ③ 받은 코드를 직접 붙여넣기  →  ④ 자가 점검
   python tools/…         파일 1개 + 한 문단            내 손으로 파일 저장            9장 명령
```

### 8-1. 컨텍스트 팩 만들기 — 파일 하나로 묶어 줍니다

채팅창에는 **폴더 구조를 유지한 채 수십 개 파일을 올릴 수 없습니다.**
그렇다고 아무것도 안 주면 AI가 우리 규약을 모르고 엉뚱한 코드를 줍니다.

그래서 **내 담당 일에 꼭 필요한 것만** 마크다운 파일 하나로 묶는 도구를 준비했습니다.

```bash
python tools/context_pack.py pi          # 라즈베리파이 담당
python tools/context_pack.py frontend    # 프론트엔드 담당
python tools/context_pack.py vision      # 영상인식 담당
python tools/context_pack.py all         # 셋 다
```

`context_packs/` 폴더에 파일이 생깁니다 (각 20~60KB — 채팅창에 그대로 올라갑니다).
다른 팀 본보기 파일(`scenarios/study*`, `app/wakeup/` 등)을 지우면 팩도 함께 작아집니다.

팩 안에 들어 있는 것:

| 무엇 | 어떻게 |
|---|---|
| 지켜야 할 제약 | 고정 슬롯 20개 · 고치지 않는 파일 · 계약 (AI가 어기면 4팀이 깨집니다) |
| **우리 팀 현재 배치표** | 지금 내 `slot_map.py`를 읽어서 표로 (고칠 때마다 최신) |
| 내가 고치는 파일 | **전문** |
| 내가 호출만 하는 키트 | 타입은 전문, 함수는 이름만 (구현 수백 줄은 생략) |
| 답변 형식 요구 | "제가 손으로 붙여넣으니 파일 전체를 주세요" |

> ⚠️ **코드를 고친 뒤에는 팩을 다시 만드세요.** 팩은 만든 순간의 사진입니다.
> 옛 팩을 올리면 AI가 이미 고친 코드를 기준으로 답해서 작업이 되돌아갑니다.

### 8-2. 채팅창에 올리고 요청하기

1. 새 대화를 시작합니다.
2. `context_packs/context_pack_<내역할>.md`를 **파일로 올립니다.**
   (파일 업로드가 안 되면 내용을 전부 복사해서 붙여넣어도 됩니다.)
3. 그 아래에 **하고 싶은 일을 한 문단으로** 적습니다.

요청은 이렇게 씁니다. 팩에 규약이 이미 들어 있으니 **무엇을 하고 싶은지만** 적으면 됩니다.

**부품 추가 (라즈베리파이 담당)**
```text
올린 컨텍스트 팩을 읽었지?
actuator_06에 경보등 LED를 추가하려고 해. 점멸로 쓸 거야 (0.25초 켜고 0.15초 꺼짐).

```

**새 감지 방법 (영상인식 담당)**
```text

**시나리오 만들기 (프론트엔드 담당)**

```

### 8-3. 받은 코드를 붙여넣기 — 여기서 사고가 납니다

AI가 준 코드를 **내 손으로** 파일에 넣어야 합니다. 조심할 것들:

| 하지 말 것 | 대신 |
|---|---|
| `+` `-` 가 붙은 diff를 그대로 붙여넣기 | 기호를 뺀 **완성된 코드**를 달라고 다시 요청 |
| `...` 나 `(이하 생략)` 이 든 코드를 붙여넣기 | **전체를 빠짐없이** 달라고 다시 요청 |
| 한 번에 파일 5개 고치기 | **3개 이하**씩 나눠서 (붙여넣다가 틀립니다) |
| 고치기 전 파일을 안 저장하고 덮어쓰기 | `git diff`로 확인 · 틀리면 `git checkout <파일>`로 되돌리기 |

> 💡 **되돌리는 법을 먼저 익히세요.** 붙여넣기가 꼬였을 때
> `git checkout pi/slot_map.py` 한 줄이면 고치기 전으로 돌아갑니다.
> 잘 된 지점마다 `git add -A && git commit -m "경보등 추가"`로 묶어 두면 더 안전합니다.

### 8-4. 바로 자가 점검 (9장)

붙여넣었으면 **그 자리에서** 점검합니다. 나중에 하면 어느 변경이 깨뜨렸는지 알 수 없습니다.

```bash
cd pi       && python daemon.py --check          # 배치표를 고쳤다면
cd pi       && python test_slot_daemon.py        # 드라이버를 고쳤다면

```

실패하면 **그 출력을 그대로 복사해서** 같은 대화에 붙여넣고 고쳐 달라고 하세요.
에러 메시지는 AI에게 가장 좋은 정보입니다.

### 8-5. 대화를 나누는 요령

- **작업 하나 = 대화 하나.** 배치표 일을 끝내고 화면 일을 할 때는 새 대화를 엽니다
  (팩도 그 역할 것으로 새로 올립니다).
- 같은 대화에서는 팩을 **다시 올리지 않아도** 됩니다. AI가 기억하고 있습니다.
- 대화가 길어져 AI가 헷갈리기 시작하면 **새 대화 + 새 팩**으로 옮기세요.
- 파일을 많이 고친 뒤에는 팩을 다시 만들어 올립니다 (8-1의 경고).

### 8-6. AI가 이렇게 말하면 멈추세요

| AI가 하는 말 | 왜 멈춰야 하나 |
|---|---|

## 10. 막혔을 때 — 증상으로 찾기

### 연결·실행

| 증상 | 해결 |
|---|---|
| 대시보드에 **부품이 하나도 없음** | 파이에서 `python daemon.py`를 실행해야 슬롯이 등록됩니다. `--check`로 먼저 확인 |
| 카드는 보이는데 **"하드웨어 반영 대기"** 에서 안 바뀜 | 파이 데몬이 켜져 있는지, `BACKEND_URL`(PC 실제 IP)과 `DEVICE_API_KEY`가 맞는지 |
| 파이에서 백엔드 **연결 실패** | ① 백엔드에 `--host 0.0.0.0` 줬는지 ② 방화벽 8000 허용 ③ `BACKEND_URL`이 `localhost`가 아닌 PC의 실제 IP인지 |
| `401 Unauthorized` | `backend/.env` · `vision/.env` · `pi/.env`의 `DEVICE_API_KEY` 3개가 똑같은지 |
| 대시보드에 **"DB 미연결"** 배지 | XAMPP MySQL이 꺼져 있습니다. 동작은 계속되고 기록만 안 됩니다. 켜면 자동 재연결 |
| `ModuleNotFoundError: No module named 'backend'` | `cd backend` 한 뒤 `uvicorn main:app`을 실행하세요 |
| PowerShell 실행 제한 에러 | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| `mysql: command not found` | `C:\xampp\mysql\bin\mysql.exe -u root` 또는 phpMyAdmin SQL 탭 |

### 하드웨어

| 증상 | 해결 |
|---|---|
| 부저에서 **소리가 안 나거나 '틱'만** | `slot_map.py`의 `buzzer_type`을 `passive` ↔ `active` |
| 버튼·터치센서가 **반응 없음** | `pull_up`을 반대로 (푸시버튼=`True`, 정전식 터치·PIR=`False`) |
| 파이에서 **"흉내내기 모드"** 라고 나옴 | `sudo apt install -y python3-gpiozero python3-lgpio` 후 venv를 `--system-site-packages`로 다시 만드세요 |
| `python daemon.py --check`가 **"고쳐야 할 것"** 을 표시 | 그 줄만 빠지고 나머지는 동작합니다. 메시지가 무엇이 틀렸는지 한글로 알려 줍니다 |
| 여러 핀 쓰는 부품인데 오류 | `pin` 하나가 아니라 `pins: [5,6,13]` 또는 `pins: {"r":17,…}`로 적으세요 |

| 증상 | 해결 |
|---|---|
| 웹캠 화면이 **검은색**이거나 안 열림 | Zoom·Teams·Discord·카메라 앱이 웹캠을 점유 중인지 확인하고 모두 종료 |

## 11. 팀 간 약속과 키트 업데이트

### 지켜야 할 약속

1. 슬롯 ID(`sensor_01`~`actuator_10`)와 DB 스키마, API 응답 형식은 **바꾸지 않습니다.**
2. 팀 고유 부품 이름과 시나리오 라벨(게임·자세 이름)을 `backend/`와 `vision/` 공통 파일에
   넣지 않습니다. 팀 고유 감지는 `vision/detectors/` 안에만 둡니다.
3. 액추에이터의 `current_state`는 **하드웨어가 보고할 때만** 바뀝니다.
   백엔드가 직접 쓰면 배선이 빠져도 화면은 정상으로 보입니다.
4. 숫자 센서는 반드시 `{"value": 24.5}` 형식으로 보고합니다.
5. 바꾼 뒤에는 9장 자가 점검을 돌리고, **전부 통과한 상태로** 커밋합니다.

### 키트가 업데이트되면 받아오기

```bash
git fetch origin
git merge origin/platform
```

충돌은 `frontend/`, `pi/slot_map.py`, `vision/detectors/<우리팀>.py`에서만 납니다 —
우리가 고친 곳이 거기뿐이기 때문입니다. `backend/`나 `vision/` 공통 파일에서 충돌이 난다면
**고치면 안 되는 곳을 고친 것**이므로 그 변경을 되돌리고 1장의 방법으로 다시 해 보세요.

## 12. 배포 (원격 시연이 필요할 때만)

```
Render (FastAPI 백엔드) ◄──► Vercel (Next.js 대시보드)
        │
    Supabase (PostgreSQL)
```

**백엔드 (Render)** — Root Directory `backend`,
Build `pip install -r requirements.txt`,
Start `uvicorn main:app --host 0.0.0.0 --port $PORT`

| 환경변수 | 안 넣으면 |
|---|---|
| `DEVICE_API_KEY` | 누구나 부저를 켤 수 있습니다 |
| `CORS_ALLOW_ORIGINS` (Vercel 주소) | 대시보드의 API 호출이 전부 차단됩니다 |
| `PLATFORM_TIMEZONE=Asia/Seoul` | **알람이 9시간 밀립니다** |
| `DEVICE_MODE` | 기본 `mock`으로 동작합니다 |

> 워커는 **1개**로 두세요. 타이머가 프로세스 안에서 돌기 때문에 여러 개면 같은 알람이 여러 번 울립니다.

**프론트엔드 (Vercel)** — Root Directory `frontend`,
`NEXT_PUBLIC_API_BASE_URL`을 Render 주소로, `NEXT_PUBLIC_WS_URL`은 **`wss://`** 로
(HTTPS 페이지는 `ws://`를 열 수 없습니다).

> ⚠️ **DB 이전은 설정만 바꾸는 작업이 아닙니다.** `init.sql`과 `db/database.py`에 MySQL 전용
> 문법(`AUTO_INCREMENT`, `ON DUPLICATE KEY UPDATE`, `JSON`)이 있어 PostgreSQL에서는 각각
> `SERIAL`, `ON CONFLICT … DO UPDATE`, `JSONB`로 바꾸고 드라이버도 `pymysql` → `psycopg[binary]`로
> 교체해야 합니다. 시간이 없으면 **로컬 MariaDB로 시연하는 편이 안전합니다.**

| `POST /api/v1/vision/events` | vision | 감지 이벤트 |
| `POST /api/v1/vision/detectors` | vision | 부팅 시 검출기·라벨 신고 |
