## 0단계. 깃허브 `karaoke` 브랜치 클론 및 로컬 셋업 (팀당 1회)

### 0-1. 저장소 클론 (PowerShell)
작업할 폴더에서 깃허브 저장소의 **`karaoke` 브랜치**를 클론합니다:
```powershell
git clone -b karaoke https://github.com/foxjini/agent-vibe-coding-starter-kit2.git agent-vibe-coding-starter-kit2-karaoke
cd agent-vibe-coding-starter-kit2-karaoke
```

### 0-2. Antigravity IDE 열기 & Rules 확인
1. Antigravity IDE에서 클론한 폴더(`agent-vibe-coding-starter-kit2-karaoke`)를 엽니다.
2. 상단 메뉴 `…` → **Customizations** → **Rules**에서 아래 3개만 **Always On**으로 설정되어 있는지 확인합니다:
   - `karpathy-principles` (생각 먼저, 단순함 우선, 외과적 변경)
   - `security-rules` (시크릿 보호)
   - `coding-standards` (코딩 스타일 규약)
   *(나머지 룰은 각 에이전트가 필요 시 자동으로 호출하므로 꺼두어야 토큰을 대폭 절약할 수 있습니다.)*

### 0-3. 백엔드 가상환경(venv) 생성 및 패키지 설치
FastAPI 백엔드 실행을 위한 Python 가상환경을 만들고 의존성을 설치합니다:
```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```
> 💡 **스크립트 실행 오류가 발생할 때 (`PSSecurityException`)**:
> PowerShell을 열고 `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`를 실행한 후 다시 활성화합니다.

### 0-4. 프론트엔드 패키지 설치
Next.js 웹 애플리케이션에 필요한 패키지를 설치합니다:
```powershell
cd frontend
npm install
cd ..
```
*(⚠️ 기존 1차 완성 코드가 모두 포함되어 있으므로 `npx create-next-app`을 실행하지 않습니다.)*

### 0-5. 비전(웹캠 인식) 가상환경(venv) 생성 및 패키지 설치
부스 입장 감지(Person Detection) 및 사용자 인식에 사용되는 비전 환경을 준비합니다. 실습실 대역폭과 Windows 호환성을 고려하여 **PyTorch 없이 5~10초 만에 설치되는 순수 ONNXRuntime & OpenCV 엔진(`vision/yolov8n.onnx`)**이 프로젝트에 사전 탑재되어 있습니다:
```powershell
cd vision
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```
> 💡 **비전 환경 팁**:
> - Windows 환경의 Python 3.14/3.13 C++ DLL 충돌(`WinError 1114`)을 방지하기 위해 `py -3.12`로 가상환경을 생성합니다. (Python 3.12가 단독 설치된 경우 `python -m venv venv`로 생성해도 무방합니다.)
> - `.gitignore`에 `venv/`가 등록되어 있으므로 폴더명은 반드시 `venv`로 유지합니다.

### 0-6. 환경변수 파일(`.env`) 복사 및 키 설정
각 폴더의 `.env.example`을 복사하여 `.env` 파일을 생성합니다:
```powershell
copy backend\.env.example backend\.env
copy frontend\.env.example frontend\.env
copy vision\.env.example vision\.env
copy pi\.env.example pi\.env
```
> 🔒 **보안 및 연동 필수 확인 (`DEVICE_API_KEY`)**:
> `backend/.env`, `vision/.env`, `pi/.env`에 적힌 `DEVICE_API_KEY`는 서로 **동일한 비밀 키**(예: `karaoke_secret_key_1234`)여야 인증이 통과됩니다. 네 파일의 키 값을 일치시켜 주세요.

#### `backend/.env`에서 함께 확인할 항목

| 키 | 로컬 개발 | 전시·배포 | 설명 |
|---|---|---|---|
| `ADMIN_PIN` | `9179` 그대로 | **반드시 다른 값으로 변경** | 도어락·전원 제어와 시나리오 강제 실행을 여는 관리자 비밀번호. 기본값은 저장소에 공개되어 있습니다 |
| `ALLOW_TEST_PIN` | `true` (편리) | **반드시 `false`** | `true`면 예약하지 않은 사람도 만능 PIN `1234`로 부스에 들어옵니다 |
| `REQUIRE_USER_AUTH` | `false` | `false` 유지 | Supabase **Auth**를 실제로 붙이지 않은 상태에서 켜면 대시보드가 전부 401이 됩니다 |
| `DATABASE_URL` | 비워 둠 | Supabase 주소 | 값이 있으면 PostgreSQL로, 없으면 로컬 MariaDB로 붙습니다 |

> 🎨 **프론트엔드 주소 설정**: `frontend/.env`의 `NEXT_PUBLIC_API_BASE_URL`과 `NEXT_PUBLIC_WS_URL`이 백엔드 주소와 일치해야 합니다. `NEXT_PUBLIC_`으로 시작하는 값은 **프론트엔드를 껐다 켜야** 반영됩니다.

### 0-7. 로컬 MariaDB/MySQL 데이터베이스 초기화
1. XAMPP Control Panel을 열고 **Apache**와 **MySQL**을 **Start**합니다.
2. PowerShell에서 `backend/db/init.sql`을 실행하여 노래방 부스, 예약, 디바이스 시드, 애창곡 데이터를 DB에 생성합니다:
```powershell
cd backend
Get-Content db\init.sql | mysql -u root
cd ..
```
*(mysql 명령이 PATH에 없다면 phpMyAdmin 웹 화면 `http://localhost/phpmyadmin`의 **SQL** 탭이나 MySQL Workbench에 `backend/db/init.sql` 내용을 복사하여 실행해도 됩니다.)*

`init.sql`을 실행하면 테이블 **7개**가 만들어집니다:
`devices` · `reservations` · `song_history` · `song_videos` · `control_log` · `sensor_readings` · `vision_events`

> ⚠️ **이미 DB를 만들어 둔 팀은 `init.sql`을 한 번 더 실행하세요.**
> 노래방 영상 등록을 저장하는 `song_videos` 테이블이 나중에 추가되었습니다.
> `CREATE TABLE IF NOT EXISTS`라 기존 데이터는 지워지지 않습니다.

> ☁️ **Supabase(클라우드)로 옮길 때는** `init.sql`이 아니라 `backend/db/init_supabase.sql`을
> Supabase 대시보드의 **SQL Editor**에 붙여넣어 실행합니다. (자세한 절차는 부록G §7)

## 1단계. 1차 완성 시스템 로컬 구동 및 기능 점검

백엔드, 프론트엔드, 비전 클라이언트를 동시에 띄워 1차 완성된 노래방 부스 시스템이 정상 동작하는지 점검합니다. **터미널을 3개 열어 각각 유지**합니다.

```
┌────────────────────────────────┐   WebSocket / REST    ┌────────────────────────────────┐
│   [터미널 1] 백엔드 (8000)       │ ◄──────────────────► │  [터미널 2] 프론트엔드 (3000)   │
│   FastAPI (Mock Provider)      │                       │  Next.js 노래방 부스 웹앱      │
└────────────────────────────────┘                       └────────────────────────────────┘
              ▲
              │ POST /api/v1/vision/events
┌────────────────────────────────┐
│   [터미널 3] 비전 (웹캠)         │
│   OpenCV + YOLOv8 ONNX 추론    │
└────────────────────────────────┘
```

### 1-1. 백엔드 서버 구동 [터미널 1]
```powershell
cd backend
.\venv\Scripts\Activate.ps1
uvicorn main:app --reload --port 8000
```
- **확인**: 브라우저에서 `http://localhost:8000/docs` (Swagger UI) 및 `http://localhost:8000/health` 접속 확인.

### 1-2. 프론트엔드 대시보드 구동 [터미널 2]
```powershell
cd frontend
npm run dev
```
- **확인**: 브라우저에서 `http://localhost:3000` 접속.
  - 상단 연결 배지에 **"● 실시간 연결됨"**이 초록색으로 표시되는지 확인합니다.

### 1-3. 비전 클라이언트 구동 [터미널 3]
⚠️ **웹캠 점유 주의**: Zoom, Teams, Discord, 카메라 앱 등 웹캠을 사용하는 다른 프로그램을 모두 종료한 상태에서 새 터미널을 열고 실행합니다:
```powershell
cd vision
.\venv\Scripts\Activate.ps1
python main.py
```
- **확인**: 웹캠 화면 창이 뜨며, 카메라 앞에 사람이 인식되면 초록색 바운딩 박스가 표시되고 백엔드로 입장 이벤트(`POST /api/v1/vision/events`) 전송 로그가 콘솔에 찍힙니다.

### 1-4. 1차 완성 기능 점검 체크리스트
웹 화면(`http://localhost:3000`)에서 다음 핵심 기능들을 직접 조작해 봅니다:
1. **웹 예약 & 일회성 4자리 PIN 발급**:
   - 내일 날짜와 이용 시간대를 선택하고 예약 신청 ➔ 4자리 인증 PIN 발급 확인.
   - 당일 예약 차단 및 동일 시간대 중복 예약 방지 동작 확인.
2. **키패드 PIN 인증 시퀀스**:
   - 발급받은 4자리 PIN 입력 ➔ 솔레노이드 도어락 해제(`UNLOCKED`), 릴레이 전원(`ON`), 부스 조명(`ON`) 확인.
   - **같은 PIN을 한 번 더 입력** ➔ *"이미 사용한 비밀번호"* 로 거부되는지 확인 (PIN은 1회용입니다).
3. **관리자 인증**:
   - 첫 번째 탭 맨 위 상자에 `backend/.env`의 `ADMIN_PIN`(기본 `9179`) 입력 ➔ *"관리자 모드로 인증되었습니다"* 확인.
   - **인증 전에는 기기 제어 버튼이 비활성**이고, 인증 후에 살아나는지 확인.
   - 키패드에 관리자 PIN 입력 ➔ 도어락 해제 및 조명 점등, 단 **노래방 기기 전원(릴레이)은 `OFF` 유지** 확인.
4. **웹캠 입장 감지 & 자동 환영 안내 (TTS)**:
   - 웹캠(비전) 앞에서 사람 감지 시 웹 대시보드에서 환영 메시지가 수신되고 안내 음성이 자동 송출되는지 확인.
5. **노래방 — 입장 → 선곡 → 재생 → 채점**:
   - 노래방 탭에서 **[🎤 노래방 입장하기]** 클릭 ➔ 마이크 권한 허용 ➔ *"준비 완료! (주변 소음 · 발성 인식 기준)"* 표시 확인.
     *(브라우저는 사용자가 버튼을 눌러야 소리를 낼 수 있어, 권한과 소음 측정을 여기서 먼저 끝냅니다.)*
   - 애창곡 10곡 중 하나 선택 ➔ **유튜브 노래방 영상이 화면에 재생**되는지 확인.
     *영상이 안 나오면* → 노래방 탭 아래 **[노래방 영상 점검]** 패널을 펼치고
     **[10곡 후보 전체 점검]** 을 누릅니다. 어떤 영상이 되는지 30초 안에 가려내고,
     되는 영상은 [이 영상 등록]으로 바로 등록할 수 있습니다(**관리자 인증 필요**).
     등록한 영상은 **서버에 저장되어 모든 기기에 적용**됩니다.
   - 노래를 부르면 음정(Pitch)과 성량(VU)이 실시간 반응하는지 확인.
   - **곡이 끝나면 버튼을 누르지 않아도** 점수 화면이 자동으로 뜨는지 확인.
   - 마이크를 켜지 않고 [노래 완료]를 누르면 **점수를 지어내지 않고** 안내가 뜨는지 확인.
6. **퇴실 시퀀스**:
   - 이용 종료 시 퇴실 음악(`더윈드 - 다시 만나`) 자동 재생 및 전원 차단 확인.

## 2단계. [핵심] 라즈베리파이 5 실기기 연동 (Mock ➔ Hardware)

1차 Mock 환경에서 검증이 끝났으므로, 실제 라즈베리파이 5에 센서와 액추에이터를 배선하고 연동합니다.
상세한 인터페이스 계약은 **[`docs/부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md`](부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md)** 및 **[`docs/부록B-라즈베리파이5-담당자-온보딩-슬라이드.pptx`](부록B-라즈베리파이5-담당자-온보딩-슬라이드.pptx)**를 참고합니다.

### 2-1. PC 백엔드 중계 모드 전환 (백엔드 담당자)
1. 백엔드가 구동 중인 Windows PC의 IP를 확인합니다:
   ```powershell
   ipconfig
   # IPv4 주소 확인 (예: 192.168.0.25)
   ```
2. Windows Defender 방화벽에서 8000번 포트 인바운드를 허용합니다 (관리자 PowerShell):
   ```powershell
   netsh advfirewall firewall add rule name="fastapi-dev" dir=in action=allow protocol=TCP localport=8000
   ```
3. `backend/.env`를 열어 디바이스 모드를 하드웨어로 전환하고 백엔드를 재시작합니다:
   ```ini
   DEVICE_MODE=hardware
   ```

### 2-2. 라즈베리파이 5 하드웨어 배선 (하드웨어 담당자)
⚠️ **반드시 전원이 꺼진 상태에서, 교사 입회 하에 배선합니다.**
- **솔레노이드 도어락**: 릴레이 모듈 1번 채널에 연결 (GPIO 제어로 12V 전원 개폐)
- **노래방 기기 전원 릴레이**: 릴레이 모듈 2번 채널에 연결
- **부스 LED 조명 / 경고등**: 트랜지스터 또는 LED 모듈 GPIO 연결
- **4x4 매트릭스 키패드**: 8개 GPIO 핀 (행 4핀, 열 4핀) 연결
- **PIR 인체감지 센서**: VCC(5V), GND, OUT(GPIO 입력) 연결
- **스피커**: 3.5mm 오디오 잭 또는 USB 스피커 연결

### 2-3. 라즈베리파이 5 데몬 설정 및 실행 (라즈베리파이 터미널)
라즈베리파이 5의 터미널(SSH 또는 모니터)에서 실행합니다:
```bash
# 1) 시스템 APT 패키지 설치 (RP1 lgpio C 컴파일 에러 방지)
sudo apt update && sudo apt install -y python3-gpiozero python3-lgpio

# 2) 가상환경 생성 (시스템 패키지 상속) 및 활성화
cd pi
python3 -m venv --system-site-packages venv
source venv/bin/activate

# 3) 가상환경 내부 패키지 설치
pip install -r requirements.txt

# 4) .env 설정 확인
nano .env
```
`pi/.env` 파일 내용:
```ini
BACKEND_URL=http://192.168.0.25:8000   # 백엔드 PC의 IPv4 주소
DEVICE_API_KEY=karaoke_secret_key_1234 # backend/.env와 반드시 동일
POLL_INTERVAL_SEC=2.0
GPIOZERO_PIN_FACTORY=lgpio
```

하드웨어 배선 후 1분 자가진단을 먼저 실행합니다:
```bash
python test_hardware_gpio.py
```

자가진단이 정상 완료되면 데몬을 실행합니다:
```bash
python main.py  # 또는 모의 데몬: python 02_karaoke_daemon_mock.py
```

### 2-4. 양방향 실기기 동작 검증
1. **웹 ➔ 라즈베리파이 (Desired-State 폴링 제어)**:
   - 웹 대시보드에서 도어락 해제 버튼 클릭 또는 4자리 PIN 인증 성공 시, 라즈베리파이에 연결된 솔레노이드 도어락이 실제로 "찰칵" 열리고 릴레이가 켜지는지 확인합니다.
2. **라즈베리파이 ➔ 백엔드 (센서/키패드 이벤트 보고)**:
   - 라즈베리파이의 실물 4x4 키패드로 4자리 PIN을 입력했을 때, 백엔드 인증을 거쳐 도어락이 열리고 웹 대시보드 상태가 실시간 동기화되는지 확인합니다.
   - PIR 센서 앞을 지날 때 입장 감지 이벤트가 백엔드로 전송되는지 확인합니다.

## 4단계. 클라우드 배포 (Supabase, Render, Vercel)

로컬 연동이 완료된 후 상시 서비스를 위한 클라우드 배포를 진행합니다.

1. **Supabase (PostgreSQL 데이터베이스)**:
   - Supabase 프로젝트 생성 후, `.agents/skills/db-migration/SKILL.md`를 참고하여 PostgreSQL 호환 DDL 스크립트를 SQL Editor에서 실행합니다.
2. **Render (FastAPI 백엔드)**:
   - GitHub 저장소 연동 후 Web Service 생성.
   - Root Directory: `backend`
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - 환경변수: `DATABASE_URL`, `DEVICE_API_KEY`, `DEVICE_MODE=hardware` 등록.
3. **Vercel (Next.js 프론트엔드)**:
   - Root Directory: `frontend`
   - 환경변수: `NEXT_PUBLIC_API_BASE_URL`에 배포된 Render 백엔드 URL 등록.
4. **라즈베리파이 `pi/.env` 갱신**:
   - `BACKEND_URL`을 Render 배포 주소(`https://xxxx.onrender.com`)로 변경하여 학교 부스 현장에서 클라우드와 통신하도록 설정합니다.

## 트러블슈팅 & FAQ

| 증상 | 원인 | 해결책 |
|---|---|---|
| 파이에서 `Connection refused` / `Timeout` | Windows 방화벽 차단 또는 IP 오입력 | 백엔드 PC에서 `ipconfig`로 IPv4를 재확인하고, 방화벽 인바운드 8000 포트 허용 규칙을 등록합니다. |
| `401 Unauthorized` 에러 (파이·비전) | API 키 불일치 | `backend/.env`와 `pi/.env`의 `DEVICE_API_KEY` 문자열이 오탈자 없이 완벽히 일치하는지 확인합니다. |
| 기기 제어 버튼이 회색이고 눌러도 401 | **정상 동작입니다.** 기기 제어는 관리자 전용이 되었습니다 | 첫 번째 탭 맨 위 상자에 `backend/.env`의 `ADMIN_PIN`을 입력해 인증하면 버튼이 살아납니다. |
| 예약한 PIN인데 *"이미 사용한 비밀번호"* | **정상 동작입니다.** PIN은 1회용입니다 | 예약을 새로 만들어 새 PIN을 받거나, DB에서 그 예약의 `status`를 `reserved`로 되돌립니다. |
| 노래방 탭에서 [반주 시작]이 눌리지 않음 | 아직 입장하지 않았거나 영상을 불러오는 중 | 먼저 **[🎤 노래방 입장하기]** 를 누릅니다. 버튼이 "영상 불러오는 중"이면 몇 초 기다립니다. |
| 유튜브 영상이 안 나오고 등록 화면이 뜸 | 후보 영상이 모두 임베드 차단·삭제됨 | 등록 화면에 **실패한 영상 ID와 오류 코드**가 함께 표시됩니다. `코드 150`이면 영상 주인이 외부 사이트 재생을 막아 둔 것이니, **[노래방 영상 점검]** 패널에서 되는 영상을 찾아 등록합니다(**관리자 인증 필요**). 등록본은 모든 기기에 적용됩니다. 자세한 내용은 `docs/부록F` §9. |
| 크롬 콘솔에 `postMessage ... target origin` / `compute-pressure` 경고가 뜸 | 유튜브가 제공하는 스크립트가 스스로 찍는 경고 | **오류가 아닙니다.** 우리 코드로 없앨 수 없고 재생 여부와도 무관합니다. 재생 실패 여부는 `[노래방] 재생 실패 …` 로그로 판단합니다. |
| 곡이 끝나도 점수가 안 뜸 | 종료 감지 실패 (드묾) | [노래 완료 & 점수 채점] 버튼으로 직접 채점할 수 있습니다. |
| 노래 탭만 비어 있음 | DB가 안 떠 있음 | XAMPP에서 MySQL이 **Running**인지 확인합니다. 다른 탭은 값이 없어도 화면이 그려집니다. |
| 예약·노래 화면이 서버와 연결되지 않음 | `frontend/.env`의 주소가 다르거나 반영 안 됨 | `NEXT_PUBLIC_API_BASE_URL`을 확인하고 **프론트엔드를 껐다 켭니다** (`NEXT_PUBLIC_`은 재시작해야 반영). |
| 브라우저 콘솔에 CORS 오류 | `backend/.env`의 `CORS_ALLOW_ORIGINS`에 현재 프론트 주소가 없음 | 쓰는 주소를 추가하고 **백엔드를 재시작**합니다. |
| `BadPinFactory` / GPIO 초기화 실패 | Raspberry Pi 5(RP1 칩셋) 특성 및 PyPI C 컴파일 오류 | `pip install lgpio` 대신 `sudo apt install -y python3-gpiozero python3-lgpio`를 설치하고 `python3 -m venv --system-site-packages venv` 가상환경을 사용합니다. `pi/.env`의 `GPIOZERO_PIN_FACTORY=lgpio`도 확인합니다. |
| 웹캠 화면이 검은색이거나 충돌 | 다른 앱의 카메라 점유 | Zoom, Teams, 카메라 앱 등 웹캠을 사용하는 모든 백그라운드 프로세스를 종료합니다. |
| Next.js 대시보드 `Hydration failed` | 시간 렌더링 서버-클라이언트 불일치 | 실시간 시간을 렌더링하는 컴포넌트 태그에 `suppressHydrationWarning` 속성을 적용합니다. |
