PowerShell에서 아래 명령어를 실행하여 1차가 완성된 `wakeup` 브랜치를 클론합니다:

```powershell
cd iot-vision-control-system
```

**확인**: 폴더 내에 `AGENTS.md`, `backend/`, `frontend/`, `vision/`, `pi/`, `run_system.ps1` 등이 존재하면 성공입니다.

### 0-2. Antigravity IDE로 열기
Antigravity IDE를 실행하고 `iot-vision-control-system` 폴더를 워크스페이스로 엽니다.

### 0-3. Antigravity Rules 설정 확인
상단 "…" 메뉴 → **Customizations** 패널(또는 Rules 탭)에서 아래 **3개 규칙만 "Always On"**으로 설정되어 있는지 확인합니다:
- `karpathy-principles` (생각 먼저·단순함 우선·외과적 변경)
- `security-rules` (시크릿 보호)
- `coding-standards` (코드 품질 표준)

> ⚠️ 나머지 규칙(`hardware-rules`, `vision-rules`, `api-rules`, `db-rules` 등)은 Always On으로 켜지 마세요. 필요할 때 각 Agent가 자동으로 읽어오므로 토큰을 크게 아낄 수 있습니다.

## 2단계. 로컬 DB 설정 및 1차 시스템 베이스라인 동작 검증

1차로 완성된 기능(알람 예약 → 비프음 알람 → **가위바위보 기상 미션**으로 알람 해제 → 약 25초 후 2차 수면 방지 팝업)을 직접 실행해서 눈으로 확인합니다.

### 2-1. MariaDB 데이터베이스 초기화
1. **XAMPP Control Panel**에서 **MySQL(MariaDB)을 'Start'** 합니다.
2. PowerShell에서 `init.sql`을 실행해 DB(`smart_control`)와 테이블 5개, 시드 데이터를 생성합니다:
```powershell
cd backend
mysql -u root --default-character-set=utf8mb4 -e "source db/init.sql"
cd ..
```

> ⚠️ **`--default-character-set=utf8mb4`를 빼지 마세요.** MySQL 명령창은 기본이 `latin1`이라,
> 빼고 실행하면 시드 데이터의 한글 이름이 `ì•ŒëžŒ ì¶œë ¥...`처럼 **깨진 채로 저장**됩니다.
> 에러는 안 나서 한참 뒤 대시보드에서야 알아차리게 됩니다.

*(mysql 명령이 환경변수에 없다면 phpMyAdmin 웹 화면 `http://localhost/phpmyadmin`의 **SQL 탭**에 `backend/db/init.sql` 내용을 붙여넣고 실행해도 됩니다. phpMyAdmin은 UTF-8로 처리하므로 안전합니다.)*

> 💡 **DB를 깜빡 안 켜도 시스템은 멈추지 않습니다.** 알람·미션·대시보드는 그대로 동작하고,
> 대신 기록(제어 이력·센서 이력·비전 이벤트)이 저장되지 않습니다. 이때 대시보드 상단에
> **"DB 미연결 (기록 저장 안 됨)"** 배지가 뜨고, `http://localhost:8000/health`의
> `database.connected` 값으로도 확인할 수 있습니다. XAMPP에서 MySQL을 켜면
> **백엔드를 다시 시작하지 않아도** 자동으로 다시 연결됩니다.

### 2-2. 1차 시스템 통합 실행
시스템 실행 방법은 **[방법 A: 자동 스크립트]**와 **[방법 B: 개별 멀티 터미널]** 중 선택할 수 있습니다.

#### [방법 A: 간편 실행] PowerShell 스크립트 이용
프로젝트 루트에서 제공되는 통합 구동 스크립트를 실행합니다:
```powershell
.\run_system.ps1
```
*(백엔드, 프론트엔드, 비전, 가상 하드웨어 Mock GUI 창이 각각 새 창으로 자동 실행됩니다.)*

#### [방법 B: 멀티 터미널 개별 실행] (디버깅 시 권장)
4개의 터미널을 열어 각각 실행합니다:
- **터미널 1 (백엔드 API/WS)**:
  ```powershell
  cd backend; .\venv\Scripts\Activate.ps1; uvicorn main:app --reload --host 0.0.0.0 --port 8000
  ```
  *(※ `--host 0.0.0.0`을 지정해야 동일 Wi-Fi 망의 라즈베리파이 5나 모바일 기기 등 외부 시스템에서 접근할 수 있습니다.)*

- **터미널 2 (대시보드 웹)**:
  ```powershell
  cd frontend; npm run dev
  ```
- **터미널 3 (웹캠 비전 클라이언트)**:
  ```powershell
  cd vision; .\venv\Scripts\Activate.ps1; python main.py
  ```
- **터미널 4 (하드웨어 데몬)**:
  ```powershell
  cd pi; python daemon.py
  ```
  *(배선을 먼저 확인만 하려면 `python daemon.py --check` — GPIO를 건드리지 않고 배치표·연결만 점검합니다.)*

### 2-3. 1차 동작 시나리오 검증 체크
1. **대시보드 접속**: 브라우저에서 `http://localhost:3000` 접속 → 상단 배지가 **"● 실시간 연결됨"**으로 초록색 점등되는지 확인.
2. **알람 테스트 예약**: 대시보드의 **"5초 후 테스트"** 버튼 클릭.
3. **알람 울림 확인**: 5초 뒤 피에조 부저 Mock(PC 사운드 비프음)이 울리며 대시보드에 경보 화면 발생.
4. **기상 미션 수행**: 알람이 울리면 대시보드와 웹캠 화면에 **AI가 낸 손(가위/바위/보)** 이 표시됩니다. 카메라 앞에서 **AI를 이기는 손**을 내면 한 판 승리이며, 기본 **2승**을 하면 알람이 해제됩니다.
   - 오답이거나 15초를 넘기면 **새 라운드로 재시도**합니다.
   - 웹캠 PC에 MediaPipe가 없으면 손동작 대신 **지정 사물/사람 감지**(사람·물병·컵·책·휴대폰)로도 라운드를 통과할 수 있습니다.
5. **2차 수면 방지 팝업 확인**: 알람 종료 약 25초 후, 대시보드와 Mock GUI 화면에 **"2차 수면 방지 기상 확인" 팝업**이 발생.
6. **기상 확인 완료**: 팝업의 "기상 확인" 버튼을 클릭하여 최종 기상 완료 상태로 전환되는지 확인.

> 🧪 **잘 안 될 때 자가 점검**: 백엔드 폴더에서 아래 두 스크립트를 실행하면 어디가 막혔는지 바로 알 수 있습니다.
> ```powershell
> cd backend; .\venv\Scripts\Activate.ps1
> python smoke_test.py        # 서버·DB·제어·폴링·에러 규격 32개 항목 점검
> python conformance_test.py  # 키트 약속(부품을 바꿔도 코드를 안 고침) 69개 항목
> ```
> 미션 판정 규칙만 따로 점검하려면 (판정이 프론트엔드로 옮겨졌습니다):
> ```powershell
> cd frontend; node --experimental-strip-types scenarios/wakeupEngine.test.ts
> ```
> 미션 난이도(필요 승수, 제한 시간)와 팝업 대기 시간은 `frontend/.env.local`의
> `NEXT_PUBLIC_MISSION_*`, `NEXT_PUBLIC_WAKEUP_*` 값으로 조절합니다.
> (미션 판정은 프론트엔드가 하므로 설정도 프론트엔드에 있습니다 — docs/부록F 9장)

## 3단계. 2차 개발 ① — 라즈베리파이 5 실기기 연동 (Mock → Hardware)

PC의 가상 사운드/GUI Mock을 **실제 라즈베리파이 5와 피에조 부저/터치 센서**로 교체하는 단계입니다.
상세한 통신 규약은 **[`docs/부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md`](부록A-백엔드-라즈베리파이5-연동-인터페이스-가이드.md)** 및 **[`docs/부록C-라즈베리파이5-담당자-온보딩-슬라이드.pptx`](부록C-라즈베리파이5-담당자-온보딩-슬라이드.pptx)**를 참고합니다.

### 3-1. 라즈베리파이 5 환경 설정 (라즈베리파이 터미널)
라즈베리파이 5는 RP1 칩 제어를 위해 `lgpio` 라이브러리가 필수입니다.
`gpiozero`/`lgpio`는 **pip로 설치하면 C 빌드 오류가 나기 쉬우므로**, OS 기본 패키지를 쓰고
가상환경에서 그것을 그대로 사용하도록 `--system-site-packages` 옵션을 붙입니다:
```bash
sudo apt update && sudo apt install -y python3-gpiozero python3-lgpio

cd pi
python3 -m venv --system-site-packages venv
source venv/bin/activate
pip install -r requirements.txt
```

### 3-2. 백엔드 IP 연동 및 환경변수 수정
1. **Windows PC 백엔드 실행 옵션 확인**:
   라즈베리파이와 같은 외부 기기에서 백엔드에 접근하려면 uvicorn이 모든 네트워크 인터페이스에 바인딩되어야 합니다.
   ```powershell
   # backend 폴더에서 반드시 --host 0.0.0.0 옵션 포함하여 실행
   uvicorn main:app --reload --host 0.0.0.0 --port 8000
   ```
   > ⚠️ **Windows 방화벽 주의**: Windows 보안 경고 창이 뜨면 **"개인 네트워크" 액세스를 허용**해야 합니다. 연결이 계속 거부되면 PowerShell(관리자)에서 8000번 포트 허용 규칙을 추가하세요:
   > `New-NetFirewallRule -DisplayName "FastAPI 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow`

2. Windows PC의 IP 주소를 확인합니다:
   ```powershell
   ipconfig
   # 예: 무선 LAN / 이더넷 어댑터의 IPv4 주소가 192.168.0.25 라면
   ```
3. 라즈베리파이의 `pi/.env` 파일을 수정합니다:
   ```env
   # 주의: localhost 대신 위에서 확인한 Windows PC의 사설 IP를 입력합니다.
   BACKEND_URL=http://192.168.0.25:8000
   # 1-1에서 팀이 새로 만든 키를 그대로 붙여넣습니다 (backend/.env와 반드시 동일)
   DEVICE_API_KEY=우리팀이_만든_키
   DEVICE_MODE=hardware

   # 부품에 맞춰 반드시 확인할 두 가지 (틀리면 소리가 안 나거나 버튼이 안 먹습니다)
   BUZZER_TYPE=active      # 능동 부저=active / 수동 피에조=passive
   BUTTON_PULL_UP=true     # 푸시버튼(GND 연결)=true / 정전식 터치센서=false
   ```
   > 🔎 **BUZZER_TYPE이 왜 중요한가요?** 능동(액티브) 부저는 전원만 주면 스스로 소리를 내지만,
   > 수동(패시브) 피에조는 주파수를 만들어 줘야(PWM) 소리가 납니다. 설정이 반대면
   > **소리가 아예 안 나거나 '틱' 소리만** 납니다. 부품 구분이 어려우면 3-3의 배선 테스트로
   > 두 설정을 각각 시도해 보세요.
4. Windows PC 백엔드의 `backend/.env`를 실기기 모드로 변경합니다:
   ```env
   DEVICE_MODE=hardware
   ```

### 3-3. 하드웨어 배선 및 데몬 구동
1. **전원을 끈 상태**에서 피에조 부저(GPIO 18 권장) 및 버튼/터치센서(GPIO 24 권장)를 연결합니다.
2. 교사 입회 하에 전원을 켠 뒤, **GPIO를 건드리기 전에** 설정부터 점검합니다:
   ```bash
   python daemon.py --check     # 배치표·백엔드 주소·핀 충돌·오타를 보여주고 종료
   python test_slot_daemon.py   # GPIO도 백엔드도 없이 39개 항목 자가 점검
   ```
   *(배치표에 오타가 있으면 그 줄만 빼고 나머지는 동작하며, 무엇이 왜 틀렸는지 한글로 알려 줍니다.)*
3. 부품이 정상이면 데몬을 실행합니다:
   ```bash
   python daemon.py
   ```
   *(소리가 안 나면 `pi/slot_map.py`에서 부저 슬롯의 `buzzer_type`을 `passive` ↔ `active`로,
   버튼이 안 먹으면 `pull_up`을 반대로 바꾸세요. 핀 번호도 이 파일 한 곳에 있습니다.)*
4. **확인**: 대시보드에서 알람 발생 시 실제 피에조 부저에서 소리가 나고, 대시보드의 부저 카드가
   **"명령 전송됨" → "알람 울림(RINGING)"** 으로 바뀌는지 확인합니다.
   > ⚠️ **"하드웨어 반영 대기"가 계속 뜬다면** 백엔드는 명령을 보냈지만 파이가 반영 보고를 못 한 상태입니다.
   > 파이 데몬이 켜져 있는지, `BACKEND_URL`과 `DEVICE_API_KEY`가 맞는지 확인하세요.
   > (이 표시는 배선이 빠졌는데도 화면만 정상으로 보이는 상황을 막아 줍니다.)

## 4단계. 2차 개발 ② — 스마트 기상 시스템 기능 고도화

1차 구축된 시스템에 다양한 기상 미션과 2차 수면 방지 강화 기능을 추가합니다.
이 과정은 **[`docs/03-2차개발-생성형AI-핸드오버-가이드.md`](03-2차개발-생성형AI-핸드오버-가이드.md)**의 프롬프트 키트를 복사하여 AI 어시스턴트(ChatGPT, Claude, Gemini, Antigravity)와 함께 진행합니다.

### 4-0. 이미 들어 있는 기능 (먼저 확인하고 시작하세요)
아래 기능들은 1차 시스템에 **이미 구현되어 있습니다.** 다시 만들어 달라고 요청하지 말고,
`frontend/.env.local` 값만 바꿔 난이도를 조절하거나 이 위에 새 기능을 얹으세요.

| 기능 | 동작 | 조절 방법 (`frontend/.env.local`) |
|---|---|---|
| 가위바위보 미션 | AI가 낸 손을 이기면 1승, 기본 2승으로 알람 해제. 오답·시간 초과 시 새 라운드 재시도 | `NEXT_PUBLIC_MISSION_REQUIRED_WINS`(승수), `NEXT_PUBLIC_MISSION_ROUND_TIMEOUT_SECONDS`(제한 시간) |
| 사물인식 미션 | 지정 사물을 연속 감지하면 라운드 통과 | `NEXT_PUBLIC_MISSION_OBJECT_REQUIRED_HITS`(연속 횟수) · **감지 대상은 대시보드 `/kit` → 영상인식 설정에서** |
| 패턴 미션 | 매번 새로 보여 주는 점 순서를 화면 패드에 똑같이 이어 그리면 1승. 틀리거나 시간 초과면 새 패턴으로 재시도 (PRD F-04) | `NEXT_PUBLIC_PATTERN_LENGTH`(점 개수), `NEXT_PUBLIC_PATTERN_STEP_SECONDS`(보여 주는 속도), `NEXT_PUBLIC_PATTERN_KEEP_VISIBLE`(쉬운 모드) |
| 미션 방식 선택 | `rps`(손동작만) / `object`(사물만) / `auto`(둘 다 인정, 기본값) / `pattern`(패턴만, 카메라 불필요) | `NEXT_PUBLIC_MISSION_MODE` |
| 2차 수면 방지 | 미션 성공 후 대기 → 확인 팝업 → 미응답 시 재알람 + 미션 재시작 | `NEXT_PUBLIC_WAKEUP_POPUP_DELAY_SECONDS`, `NEXT_PUBLIC_WAKEUP_CONFIRM_TIMEOUT_SECONDS` |

### 4-1. 권장 고도화 기능 아이디어
1. **기상 미션 다양화**:
   - 만세 스트레칭 자세 인식(MediaPipe Pose) 미션 추가
   - `auto` 모드에 패턴 미션을 섞어 라운드마다 다른 미션 내기
   - 미션 난이도를 요일·시간대에 따라 자동으로 바꾸기
2. **2차 수면 방지 로직 강화**:
   - 화면 클릭 대신 실제 방 안의 물리적 터치패드/버튼을 눌러야 팝업 해제
   - PIR 인체감지 모션 센서로 2차 수면 여부 감지
   - 2차 수면 실패 시 텔레그램/디스코드로 비상 알림 전송 (04번 문서 아이디어 ③)
3. **사용자 경험(UX) 개선**:
   - 요일별/시간대별 다중 알람 스케줄러 기능
   - 기상 성공 기록 및 통계 로그 대시보드 차트 시각화

### 4-2. AI 요청 시 3대 원칙
1. **맥락 먼저 전달**: 항상 `docs/03-2차개발-생성형AI-핸드오버-가이드.md` 1장의 기본 시스템 프롬프트를 먼저 제공합니다.
2. **외과적 변경 요청**: 파일 전체를 다시 작성하게 하지 말고, 수정할 함수나 컴포넌트만 지정해서 수정을 요청합니다.
3. **역할 지정**: "너는 이 프로젝트의 `vision-agent`다" 또는 `backend-agent`, `frontend-agent`와 같이 역할을 명시합니다.

## 5단계. 클라우드 배포 (Supabase, Render, Vercel)

로컬 개발 및 실기기 연동이 완료되면 클라우드 환경으로 배포하여 외부에서도 접속 가능한 시스템으로 완성합니다.

```
┌────────────────────────┐      ┌────────────────────────┐
│  Render (FastAPI 백엔드)│ ◄──► │ Vercel (Next.js 웹 앱) │
└────────────────────────┘      └────────────────────────┘
            │
            ▼
┌────────────────────────┐
│ Supabase (PostgreSQL)  │
└────────────────────────┘
```

1. **데이터베이스 마이그레이션 (MySQL → Supabase)**:
   - Supabase 프로젝트 생성 후 SQL Editor에서 PostgreSQL 문법에 맞게 스키마 마이그레이션 실행
   - `.agents/skills/db-migration/SKILL.md` 참고
   - ⚠️ `backend/db/init.sql`과 `db/database.py`에는 MySQL 전용 문법
     (`AUTO_INCREMENT`, `ON DUPLICATE KEY UPDATE`, `JSON` 타입)이 들어 있습니다.
     PostgreSQL에서는 각각 `SERIAL`/`GENERATED AS IDENTITY`, `ON CONFLICT ... DO UPDATE`, `JSONB`로 바꿔야 하며
     드라이버도 `pymysql` → `psycopg[binary]`로 교체해야 합니다. **설정만 바꾸면 되는 작업이 아닙니다.**
2. **백엔드 배포 (Render)**:
   - Render에서 Web Service 생성 후 GitHub 레포지터리 연결
   - Root Directory를 `backend`로 지정, Build Command: `pip install -r requirements.txt`, Start Command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - 환경변수 등록:

     | 환경변수 | 값 | 안 넣으면 생기는 일 |
     |---|---|---|
     | `DEVICE_API_KEY` | 팀이 만든 키 | 인증 없이 누구나 부저를 켤 수 있음 |
     | `CORS_ALLOW_ORIGINS` | Vercel 주소 | 대시보드에서 API 호출이 모두 차단됨 |
     | `ALARM_TIMEZONE` | `Asia/Seoul` | **클라우드 서버는 UTC라서 알람이 9시간 밀림** |
     | `DEVICE_MODE` | `mock` 또는 `hardware` | 기본값 `mock`으로 동작 |
     | `DATABASE_URL` 등 | Supabase 접속 정보 | 기록이 저장되지 않음(동작은 계속됨) |

   - 워커는 **1개(기본값)로 두세요.** 알람 예약 타이머가 프로세스 안에서 돌기 때문에
     워커를 여러 개로 늘리면 같은 알람이 여러 번 울릴 수 있습니다.
3. **프론트엔드 배포 (Vercel)**:
   - Vercel에 GitHub 레포지터리 연결, Root Directory를 `frontend`로 지정
   - 환경변수 `NEXT_PUBLIC_API_BASE_URL`을 Render 백엔드 도메인으로 설정

| `ModuleNotFoundError: No module named 'backend'` | `backend/main.py` 최상단에 `sys.path` 코드가 들어있으므로 `cd backend` 경로로 이동한 뒤 `uvicorn main:app`을 실행합니다. |
| `pip freeze` 후 인코딩 오류 (`charset=utf-16le`) | PowerShell에서 파일 저장 시 `pip freeze \| Out-File -Encoding utf8 requirements.txt` 명령을 사용합니다. |
| 웹캠 화면이 검은색이거나 열리지 않음 | Zoom, Teams, Discord, 브라우저 화상통화, Windows 카메라 앱 등이 웹캠을 점유하고 있는지 확인하고 작업 관리자에서 모두 종료합니다. |
| `401 Unauthorized` (디바이스 통신 실패) | `backend/.env`, `vision/.env`, `pi/.env` 3개 파일의 `DEVICE_API_KEY` 값이 정확히 일치하는지 확인합니다. |
| Next.js 대시보드 `Hydration failed` 경고 | 실시간 시간 표시 태그에 `suppressHydrationWarning` 속성을 추가하거나 `ConnectionBadge` 컴포넌트를 사용합니다. |
| 라즈베리파이 5 `lgpio` 모듈 오류 | 라즈베리파이 5에서는 `pip install lgpio gpiozero`가 반드시 가상환경에 설치되어 있어야 합니다. |
| PowerShell 스크립트 실행 제한 에러 | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` 실행 후 다시 시도합니다. |
| `mysql: command not found` | XAMPP 설치 경로 `C:\xampp\mysql\bin\mysql.exe -u root`를 사용하거나 phpMyAdmin 웹 UI의 SQL 탭을 이용합니다. |
| **어디가 고장인지 모르겠음 (가장 먼저 해볼 것)** | `cd backend; .\venv\Scripts\Activate.ps1; python smoke_test.py` 를 실행하면 서버·DB·제어·폴링·에러 형식까지 32개 항목을 한 번에 점검하고 실패한 곳만 알려 줍니다. 미션 판정 규칙만 확인하려면 `cd frontend; node --experimental-strip-types scenarios/wakeupEngine.test.ts`. |
| 대시보드에 **"DB 미연결 (기록 저장 안 됨)"** 배지가 뜸 | XAMPP에서 MySQL이 꺼져 있는 상태입니다. 알람·미션은 그대로 동작하지만 기록이 저장되지 않습니다. MySQL을 켜면 백엔드 재시작 없이 자동으로 다시 연결됩니다. |
| 부저에서 **소리가 전혀 안 나거나 '틱' 소리만** 남 | 부저 종류와 설정이 반대입니다. `pi/slot_map.py`에서 그 슬롯의 `buzzer_type`을 `passive` ↔ `active`로 바꾼 뒤 데몬을 다시 실행하세요. |
| 버튼/터치센서를 눌러도 **반응이 없음** | 극성이 반대입니다. `pi/slot_map.py`에서 푸시버튼(GND 연결)은 `"pull_up": True`, 정전식 터치센서·PIR은 `False`로 바꾸세요. |
| 대시보드에 **부품이 하나도 안 보임** | 파이에서 `python daemon.py`를 실행해야 슬롯이 등록됩니다. `python daemon.py --check`로 배치표와 백엔드 주소를 먼저 확인하세요. |
| 부저 카드가 계속 **"하드웨어 반영 대기"** | 백엔드는 명령했는데 파이의 반영 보고가 안 온 상태입니다. 파이 데몬 실행 여부, `BACKEND_URL`(PC의 실제 IP), `DEVICE_API_KEY` 일치를 확인하세요. |
| 배포 후 알람이 **엉뚱한 시각(9시간 차이)** 에 울림 | 클라우드 서버가 UTC로 동작하기 때문입니다. Render 환경변수에 `ALARM_TIMEZONE=Asia/Seoul`을 추가하세요. 윈도우에서 시간대 오류가 나면 `pip install tzdata`도 필요합니다. |
| 가위바위보 손동작이 **인식되지 않음** | ① 웹캠 창을 켤 때 검출기 목록에 `[O] hands_rps`가 떴는지 확인(`[X]`면 그 옆에 이유가 적혀 있습니다), ② 웹캠 창에서 `D` 키로 그 검출기를 껐는지 확인, ③ 대시보드 `/kit` → 영상인식 설정의 **검출기** 목록에서 체크가 켜져 있는지 확인, ④ `vision/hand_landmarker.task` 파일이 있는지 확인, ⑤ MediaPipe가 설치되지 않은 PC라면 손동작 대신 **사물 미션**으로 통과하면 됩니다. |
| 미션이 너무 어렵거나 너무 쉬움 | `frontend/.env.local`의 `NEXT_PUBLIC_MISSION_REQUIRED_WINS`(필요 승수), `NEXT_PUBLIC_MISSION_ROUND_TIMEOUT_SECONDS`(라운드 제한 시간)를 조절하고 대시보드를 새로고침하세요. 인식 신뢰도 기준은 `/kit` → 영상인식 설정에서 바꿉니다. |
| 카메라가 **엉뚱한 것을 감지**하거나 원하는 것을 못 찾음 | 대시보드 `/kit` → **영상인식 설정**에서 감지 대상을 고르고 최소 신뢰도를 올리세요. 코드를 고칠 필요가 없고, 비전 클라이언트가 몇 초 안에 반영합니다. |
| 알람 예약이 **서버 재시작 후에도 남아 있음** | 정상입니다. 예약은 자동화 규칙(`rules` 테이블)으로 저장되어 브라우저를 닫아도 유지됩니다. 지우려면 대시보드 알람 카드의 휴지통 버튼을 누르세요. |
