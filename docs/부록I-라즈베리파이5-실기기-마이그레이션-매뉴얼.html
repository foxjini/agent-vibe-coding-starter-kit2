1

라즈베리파이 5 준비

Raspberry Pi Imager로 Raspberry Pi OS (64-bit, Bookworm 이상)를 SD카드에 굽습니다. 굽기 전 톱니바퀴(⚙️) 설정에서 아래 세 가지를 미리 넣어 두면 모니터 없이 바로 접속할 수 있습니다.

  • 사용자 이름과 비밀번호
  • Wi-Fi 설정 — 백엔드가 돌아가는 PC와 같은 공유기여야 합니다
  • SSH 사용 체크
PC의 PowerShell에서 파이에 접속
PS> ssh 사용자이름@raspberrypi.local
# 접속이 안 되면 공유기 관리 화면에서 파이의 IP를 찾아
PS> ssh 사용자이름@192.168.0.42
이 매뉴얼의 위치 통신 규격(어떤 주소로 무엇을 주고받는지)은 docs/부록A에 있습니다. 이 문서는 그 규격을 실제 기기에 올리는 절차만 다룹니다.
2

코드 받기와 파이썬 환경

라즈베리파이 5는 GPIO를 다루는 칩이 RP1으로 바뀌어서, pip install lgpio를 하면 C 컴파일 오류가 납니다. 그래서 APT로 먼저 설치하고, 가상환경이 그것을 물려받도록 만듭니다.

라즈베리파이 터미널
# 1) 저장소 받기
$ git clone -b karaoke https://github.com/foxjini/agent-vibe-coding-starter-kit2.git
$ cd agent-vibe-coding-starter-kit2/pi

# 2) GPIO 라이브러리는 APT로 (RP1 컴파일 오류 회피)
$ sudo apt update && sudo apt install -y python3-gpiozero python3-lgpio

# 3) 가상환경 — --system-site-packages 가 핵심
$ python3 -m venv --system-site-packages venv
$ source venv/bin/activate

# 4) 나머지 의존성
(venv) $ pip install -r requirements.txt
--system-site-packages 를 빼먹으면 가상환경이 APT로 깐 gpiozero를 못 봅니다. 나중에 ModuleNotFoundError: No module named 'gpiozero'가 뜨면 십중팔구 이것입니다. rm -rf venv 후 3번부터 다시 하세요.

pi 폴더에 무엇이 들어 있나

booth_pins.pyGPIO 핀 배치 정의. 배선을 바꾸면 이 파일만 고칩니다
test_hardware_gpio.py배선 1분 자가진단
01_ping_backend.py백엔드와 통신되는지 확인
02_karaoke_daemon_mock.py실기기 없이 통신 계약만 확인 (화면 출력)
main.py본 실행 — 폴링 + GPIO 제어 + 키패드 + PIR
3

배선

⚡ 배선 전 안전 수칙 ① 파이의 전원을 완전히 뽑은 상태에서 배선합니다.
② 220V는 반드시 교사 입회 하에, 그리고 4단계 자가진단이 정상으로 나온 뒤에 연결합니다.
③ 솔레노이드 도어락은 12V 별도 전원을 씁니다. 파이의 5V 핀에서 직접 끌어오면 파이가 재부팅됩니다.

핀 배치

BCM 번호는 코드가 쓰는 번호, 물리 핀 번호는 실제로 꽂는 자리입니다. 값은 pi/booth_pins.py에 있습니다.

부품device_idBCM물리 핀
솔레노이드 도어락door_lock_11711
기기 전원 릴레이 220Vrelay_12713
부스 조명 LEDled_12215
PIR 인체감지pir_12418
키패드 행 (row) 4개keypad_15 · 6 · 13 · 1929 · 31 · 33 · 35
키패드 열 (col) 4개keypad_126 · 16 · 20 · 2137 · 36 · 38 · 40
GPIO 27은 LED가 아니라 220V 전원 릴레이입니다 예전 문서에 다른 프로젝트의 예시 표가 남아 있어 led_1 = GPIO27로 적혀 있었습니다. 위 표가 맞습니다. 헷갈리면 pi/booth_pins.py를 여세요 — 코드가 실제로 쓰는 값은 그 파일 하나뿐입니다.

40핀 헤더에서 찾기

이 프로젝트가 쓰는 핀 GND (접지) 왼쪽 = 홀수 핀, 오른쪽 = 짝수 핀

USB 포트를 아래쪽으로 두고 보드를 세웠을 때, 1번 핀은 왼쪽 위입니다. 릴레이 모듈과 키패드의 GND는 파이의 GND 아무 핀(6·9·14·20·25·30·34·39번)에나 연결하면 됩니다.

4

배선 자가진단

백엔드를 연결하기 전에, 부품이 실제로 움직이는지부터 1분 만에 확인합니다. 이 단계가 통과해야 220V를 연결합니다.

python test_hardware_gpio.py
(venv) $ python test_hardware_gpio.py

✅ [패키지 확인] gpiozero 및 lgpio 모듈이 정상적으로 로드되었습니다.
[*] GPIOZERO_PIN_FACTORY = lgpio
[*] RELAY_ACTIVE_HIGH     = True
[!] 220V 기기는 이 자가진단이 정상으로 나온 뒤에 연결하세요.

[1/5] 솔레노이드 도어락 릴레이 테스트 (GPIO 17)...
  🚪 철컥! 도어락 해제 (1.5초간 유지)...
  ✅ 솔레노이드 도어락 테스트 완료
[2/5] 반주기/앰프 기기 전원 릴레이 테스트 (GPIO 27)...   ✅
[3/5] 부스 실내 조명 LED 테스트 (GPIO 22)...            ✅
[4/5] PIR 인체감지 센서 읽기 테스트 (GPIO 24)...         ✅
[5/5] 4x4 매트릭스 키패드 핀 배선 점검...                 ✅
동작이 반대로 나온다면 — 릴레이 극성 시중 릴레이 보드 상당수는 LOW일 때 켜지는(Low Level Trigger) 방식입니다. 그런 보드는 스크립트가 시작하는 순간 도어락과 220V가 붙어 버립니다. "해제"라고 하는데 잠기고 "잠금"이라는데 열린다면 pi/.env에 아래를 넣으세요. RELAY_ACTIVE_HIGH=false

설정 파일 pi/.env

라즈베리파이 터미널
(venv) $ cp .env.example .env
(venv) $ nano .env
항목넣을 값
BACKEND_URL백엔드 PC의 IPv4 주소. localhost는 파이 자신을 가리키므로 쓸 수 없습니다. 예: http://192.168.0.25:8000
DEVICE_API_KEYbackend/.env의 값과 글자 하나까지 같아야 합니다. 다르면 401
POLL_INTERVAL_SEC백엔드에 물어보는 주기(초). 기본 3.0, 2~5 사이가 적당합니다
RELAY_ACTIVE_HIGH릴레이 극성. 4단계에서 동작이 반대였으면 false
SPEAKER_MODEbrowser(기본) — 부스 웹 화면이 소리를 냅니다. pi로 바꾸면 파이 스피커가 직접 읽어 줍니다(sudo apt install -y espeak-ng 필요)
GPIOZERO_PIN_FACTORYlgpio 고정 (라즈베리파이 5 RP1)
백엔드 담당 친구와 맞출 3가지 이 세 가지만 채팅으로 맞추면, 이후로는 서로 코드를 안 봐도 각자 개발할 수 있습니다.
① DEVICE_API_KEY 같은 문자열  ② devices 테이블의 id 목록  ③ 백엔드 PC의 IP

백엔드 쪽에서 해 줘야 하는 것

  • backend/.env를 DEVICE_MODE=hardware로 바꾸고 백엔드 재시작
  • Windows 방화벽에서 8000번 포트 열기 — 관리자 PowerShell에서
    netsh advfirewall firewall add rule name="fastapi-dev" dir=in action=allow protocol=TCP localport=8000

실기기 데몬 실행

여기가 본 실행입니다. main.py는 네 가지 일을 합니다.

  1. 백엔드에 목표 상태 물어보기 GET .../desired-state
  2. 도어락·릴레이·조명 실제로 움직이기 (gpiozero)
  3. "시킨 대로 했습니다" 보고하기 POST .../state
  4. 키패드로 누른 비밀번호와 PIR 감지 올려보내기

키패드 조작

  • 숫자 4자리를 누르면 자동으로 인증 요청이 나갑니다
  • * — 잘못 눌렀을 때 지우기
  • 8초 동안 아무것도 안 누르면 입력이 자동으로 초기화됩니다
꼭 알아 둘 것 — desired 와 current 가 다른 것은 고장이 아닙니다 대시보드에는 지시(desired)와 확정(current) 두 값이 있습니다. 확정 값은 오직 이 데몬의 보고로만 바뀝니다. 그래서 main.py가 꺼져 있으면 지시만 바뀌고 확정은 그대로 남습니다.
이건 일부러 그렇게 만든 것입니다 — 그래야 배선이 빠졌거나 데몬이 죽은 것을 화면에서 알아챌 수 있습니다. 데몬을 다시 켜면 첫 폴링에서 자동으로 맞춰집니다.

전시장 준비

부팅하면 자동으로 실행되게

전시장에서 매번 SSH로 들어가 실행할 수는 없습니다. systemd 서비스로 등록해 두면 전원만 꽂아도 뜨고, 혹시 죽어도 5초 뒤 되살아납니다.

sudo nano /etc/systemd/system/karaoke-booth.service
[Unit]
Description=School Karaoke Booth Pi Daemon
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=여러분의_사용자이름
WorkingDirectory=/home/사용자이름/agent-vibe-coding-starter-kit2/pi
ExecStart=/home/사용자이름/agent-vibe-coding-starter-kit2/pi/venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
등록과 확인
$ sudo systemctl daemon-reload
$ sudo systemctl enable --now karaoke-booth
$ systemctl status karaoke-booth      # 잘 떴는지
$ journalctl -u karaoke-booth -f      # 실행 화면 보기
전시장 Wi-Fi가 학교와 다르다면 파이의 Wi-Fi를 전시장 망으로 바꾸고, pi/.env의 BACKEND_URL도 그 망에서의 백엔드 주소로 고쳐야 합니다. 클라우드(Render)에 올렸다면 그 URL을 넣으면 되고, 그때도 파이 쪽 코드는 한 줄도 고칠 필요가 없습니다.
