부록 J · 프론트엔드 담당

화면 분리와 UI/UX 개선 작업서

지금 하나뿐인 화면을 관람객 폰 · 부스 대형 화면 · 선생님 노트북 세 개로 나누고, 각 기기에 맞게 다듬는 2차 작업 안내서입니다. 순서대로 따라가면 됩니다.

먼저 알아 둘 것 — 이건 디자인 취향 문제가 아닙니다

지금은 관람객이 보는 화면에 도어락 해제 · 220V 전원 차단 · 이용 강제 종료 버튼이 그대로 놓여 있습니다. 전시가 "관람객 직접 체험 + 실기기 반출"로 정해졌으니, 남이 노래하는 중에 전원이 꺼지거나 부스 문이 열릴 수 있습니다. 화면 분리는 이걸 막는 작업입니다.

1. 세 개로 나누는 이유 보는 사람도, 기기도 다르다

한 화면에 다 있으면 편해 보이지만, 실제로는 서로 다른 세 사람이 서로 다른 기기로 봅니다. 폰에서 쓰기 좋은 화면과 3m 떨어져 보는 대형 화면은 글자 크기부터 달라야 합니다.

2. 지금 탭 5개를 어디로 보내나

현재 탭옮길 곳비고
가상 부스 관제 & 키패드 시뮬레이터/admin전부. 관람객에게 절대 노출 금지

노래 퀴즈 미니게임/대기열에서 기다릴 때 하기 좋다
없어지는 기능 하나 — 미리 알아 두세요 지금은 예약 목록에서 PIN을 누르면 시뮬레이터 탭으로 자동 이동해 인증까지 됩니다(handleSelectPinForSimulator). 화면이 나뉘면 /에서 /admin의 키패드로 넘어갈 수 없습니다.
→ 대신 /에서는 발급된 PIN을 크게 보여 주고, "부스 앞 키패드에 입력하세요"라고 안내하면 됩니다. 실제 사용 흐름과도 이쪽이 맞습니다.

3. 작업 순서 1번을 건너뛰면 같은 코드가 3벌이 됩니다

지금 app/page.tsx 397줄 안에 데이터 로딩·WebSocket·핸들러가 전부 들어 있습니다. 라우트부터 만들고 복사하면 그 397줄이 세 번 복제됩니다. 공통 로직을 먼저 빼내세요.

작업 1

공통 로직을 훅으로 빼내기

반나절

app/page.tsx에서 화면에 안 보이는 부분(데이터 가져오기 + WebSocket)만 새 파일로 옮깁니다. 화면(JSX)은 건드리지 않습니다.

frontend/hooks/useBoothData.ts (새 파일) 
"use client";
import { useState, useEffect, useCallback } from "react";
import { apiUrl } from "@/utils/apiConfig";
import { useKaraokeSocket } from "@/hooks/useKaraokeSocket";
import { Device, Reservation, Song, WebSocketMessage } from "@/types";

/** 세 화면이 똑같이 필요로 하는 것: 기기 상태 · 예약 · 노래 · 실시간 연결 */
export function useBoothData() {
  const [devices, setDevices] = useState<Device[]>([]);
  const [reservations, setReservations] = useState<Reservation[]>([]);
  const [allSongs, setAllSongs] = useState<Song[]>([]);
  const [favoriteSongs, setFavoriteSongs] = useState<Song[]>([]);
  const [lastEventMsg, setLastEventMsg] = useState("부스 시스템이 정상 대기 중입니다.");

  // ↓ page.tsx 의 fetchDevices / fetchReservations / fetchSongs 를 그대로 옮겨 온다
  // ↓ handleWsMessage 와 useKaraokeSocket 호출도 그대로 옮겨 온다

  const { isConnected } = useKaraokeSocket(handleWsMessage);

  return { devices, reservations, allSongs, favoriteSongs,
           lastEventMsg, isConnected, fetchDevices, fetchReservations, fetchSongs };
}

그리고 app/page.tsx 맨 위에서 이렇게 씁니다. 화면은 그대로인데 줄 수가 확 줄어듭니다.

const { devices, reservations, allSongs, favoriteSongs, isConnected, fetchDevices } = useBoothData();
여기서 한 번 확인화면이 이전과 똑같이 동작하는지 먼저 확인하고 다음으로 넘어가세요. 이 단계는 보이는 것이 하나도 바뀌지 않아야 성공입니다.
작업 2

/admin 만들기 — 위험한 것부터 격리

반나절

Next.js App Router는 폴더 이름이 곧 주소입니다. app/admin/page.tsx를 만들면 그 순간 /admin이 생깁니다.

frontend/app/admin/page.tsx (새 파일) 
"use client";
import { useSyncExternalStore } from "react";
import { AdminGate } from "@/components/booth/AdminGate";
import { VirtualBoothSimulator } from "@/components/booth/VirtualBoothSimulator";
import { useBoothData } from "@/hooks/useBoothData";
import { subscribeAdminSession, getAdminSnapshot,
         getAdminServerSnapshot } from "@/utils/adminSession";

export default function AdminPage() {
  const { devices, reservations, fetchDevices } = useBoothData();
  const adminAuthed = useSyncExternalStore(
    subscribeAdminSession, getAdminSnapshot, getAdminServerSnapshot);

  // 인증 전에는 기기 제어 화면 자체를 그리지 않는다
  if (!adminAuthed) return <AdminGate isAuthed={adminAuthed} />;

  return (
    <main>
      <VirtualBoothSimulator devices={devices} /* …기존 props 그대로 */ />
    </main>
  );
}
인증 전에는 그리지 않습니다disabled로 버튼만 막으면 화면에는 계속 보입니다. 아예 return해 버려야 관람객이 무엇이 있는지도 모릅니다.
작업 3

/booth 만들기 — 노래방 전용

반나절

app/booth/page.tsx를 만들고 KaraokeRoomSection을 옮깁니다. 이 화면은 부스 대형 화면에 계속 띄워 두는 화면이라 탭 메뉴도, 상단 헤더도 필요 없습니다.

"use client";
import { KaraokeRoomSection } from "@/components/booth/KaraokeRoomSection";
import { useBoothData } from "@/hooks/useBoothData";

export default function BoothPage() {
  const { devices, fetchSongs } = useBoothData();
  return (
    <main className="min-h-screen bg-slate-950">
      <KaraokeRoomSection devices={devices} onSongCompleted={fetchSongs} />
    </main>
  );
}
작업 4

/ 정리 — 관람객에게 필요한 것만

반나절

남은 app/page.tsx에서 시뮬레이터와 노래방을 걷어내고, 탭 전환도 없앱니다. 폰 화면에서는 탭보다 세로로 쭉 이어지는 편이 낫습니다.

  • ReservationSection — 예약 신청 (신청 기능만)
  • SongHistorySection — 내 노래 기록
  • MiniGameSection — 노래 퀴즈

맨 위에는 부스가 지금 쓰는 중인지 한 줄로 보여 주면 관람객이 줄 설지 판단할 수 있습니다.

작업 5

화면 사이 이동

1~2시간

<a href> 대신 next/link를 쓰세요. 페이지 전체를 새로 받지 않아 훨씬 빠릅니다.

import Link from "next/link";

<Link href="/admin">관리자</Link>
  • / 하단에 /admin 링크를 작게 — 관람객이 눌러도 인증 화면에서 막힙니다
  • /booth에는 링크를 두지 않습니다 — 부스 화면은 노래방만 떠 있어야 합니다
  • app/layout.tsx는 건드리지 마세요. 여기에 헤더를 넣으면 /booth에도 따라붙습니다

기기별로 다듬기

2~3일

4. 화면별 UI/UX 원칙

같은 디자인을 세 곳에 쓰면 안 됩니다. 보는 거리와 손가락 크기가 다릅니다.

/ 관람객 폰 — 한 손으로, 서서, 급하게

  • 터치 영역은 최소 44×44px. 글자만 작게 두고 주변을 넓히는 방식(padding)으로 키우세요
  • 세로 한 컬럼. 폰에서 가로 스크롤이 생기면 그 화면은 실패입니다
  • 입력은 최소로. 예약 폼에서 타이핑이 필요한 칸을 세어 보고, 선택지로 바꿀 수 있는 건 버튼으로
  • 발급된 PIN은 화면에서 가장 큰 글자로. 관람객이 이걸 보고 부스 키패드로 갑니다
  • 숫자 입력 칸에는 inputMode="numeric" — 폰에서 숫자 키패드가 바로 뜹니다

/booth 부스 대형 화면 — 2~3m 떨어져서 본다

  • 본문 글자를 지금의 1.5~2배로. 노트북에서 적당해 보이는 크기는 3m 밖에서 안 읽힙니다. 실제로 화면을 띄워 두고 뒤로 물러나서 확인하세요
  • 마우스 커서를 숨깁니다 — cursor: none. 키오스크 화면에 화살표가 떠 있으면 어설퍼 보입니다
  • 전체화면 — 브라우저에서 F11, 또는 시작 버튼에 requestFullscreen()
  • 어트랙트 화면(부록G §2-⑥) — 아무도 안 쓸 때 곡 목록과 최고 점수를 돌려 보여 주면 사람이 모입니다
  • 점수 화면은 멀리서도 읽히게 — 숫자 하나만 크게, 설명은 작게

/admin 선생님 노트북 — 한눈에 파악, 실수 방지

  • 정보 밀도를 높여도 됩니다. 여기는 표가 어울리는 유일한 화면입니다
  • 위험한 버튼은 한 번 더 묻기 — 전원 차단·강제 종료는 confirm()이라도 거치게
  • 상태는 색과 모양을 같이 씁니다. 색만으로 구분하면 색각 이상인 사람이 읽을 수 없습니다 (예: 🔴 + "차단됨")
  • 지금 누가 이용 중인지, 몇 분 남았는지를 맨 위에

세 화면 공통

  • 키보드 포커스가 보여야 합니다. outline: none만 쓰고 대체 스타일을 안 주는 건 접근성 위반입니다
  • 백엔드가 꺼져 있을 때 화면이 하얗게 되지 않는지 — 지금 코드는 빈 목록으로 버티게 되어 있습니다. 새로 만드는 화면도 그렇게 하세요
  • 로딩 중과 빈 상태를 구분해서 보여 주세요. "불러오는 중"과 "아직 예약이 없습니다"는 다른 화면입니다

5. 자주 막히는 곳

증상원인과 조치
useState is not defined
비슷한 오류		새로 만든 page.tsx 맨 첫 줄에 "use client";가 빠졌습니다. 훅을 쓰는 파일에는 반드시 필요합니다
/admin이 404폴더 이름이 주소가 됩니다. app/admin/page.tsx가 맞는지, 파일 이름이 page.tsx인지 확인하세요
버튼을 눌러도 401관리자 인증이 만료됐습니다. adminFetch()를 쓰고 있는지, fetch()를 쓰고 있진 않은지 확인하세요
Tailwind 색이 안 먹힘클래스 이름을 문자열로 조립하면({`bg-${color}-500`}) 빌드가 그 클래스를 못 찾아 지워 버립니다. 완성된 클래스 이름을 통째로 쓰세요
실시간 표시가 안 바뀜WebSocket이 끊겼습니다. 상단 연결 배지를 확인하고, .env의 NEXT_PUBLIC_WS_URL을 보세요. NEXT_PUBLIC_ 값은 서버를 껐다 켜야 반영됩니다
폰에서 가로로 스크롤어딘가 고정 폭(min-width)이 있습니다. 표는 overflow-x-auto로 감싼 안쪽에서만 넓어야 합니다
