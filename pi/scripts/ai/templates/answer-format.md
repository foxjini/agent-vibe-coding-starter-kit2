# 답변 형식 (반드시 지켜 줘)

나는 네가 준 코드를 VS Code에서 **파일 전체를 지우고 그대로 붙여 넣는** 방식으로 반영한다. 파이썬이라 들여쓰기 한 칸도 중요하다. 그래서:

1. **먼저 계획만** 말해 줘. 코드는 아직 쓰지 말 것.
   - 바꿀 파일과 새로 만들 파일 목록, 파일마다 무엇을 왜 바꾸는지 한두 줄
   - 배선이 바뀌면 배선표(부품의 핀 → 물리 핀 번호와 BCM 번호)와 주의할 점
   - 마지막 줄에 "진행할까요?"라고 묻고 멈출 것. 내가 "진행"이라고 하면 코드를 준다
2. 코드는 **한 번에 파일 하나씩**, 이 모양으로 준다. 파일이 더 있으면 내가 "다음"이라고 할 때 다음 파일을 준다.
   ### 파일: pi/파일이름.py (수정 또는 새 파일)
   ```python
   (파일의 첫 줄부터 마지막 줄까지 전부)
   ```
3. **절대 생략하지 말 것.** `...`, `# 기존 코드 동일`, `# 나머지는 그대로`, `# (생략)` 같은 줄을 쓰면 안 된다.
   바꾸지 않은 줄도 한 글자도 빠짐없이 그대로 다시 써 줘. 바꾸는 곳 밖의 코드와 주석은 고치지 말 것.
   들여쓰기는 스페이스 4칸, 탭은 쓰지 말 것.
4. **400줄이 넘는 큰 파일**(예: `main.py`)은 되도록 조금만 고치고, 새 기능은 작은 새 파일로 만들 수 있으면 그렇게 설계해 줘.
   그래도 큰 파일을 고쳐야 하면 파일 전체를 `(1/2)`, `(2/2)`처럼 나눠서 주고, 나눈 조각마다 끝에
   `# ===== 여기까지 (1/2) — 다음 조각에 이어짐 =====`, 마지막 조각 끝에는 `# ===== 파일 끝 (2/2) =====`을 붙여 줘.
   조각은 함수나 클래스가 완전히 끝난 자리에서만 나눌 것. 나는 조각을 순서대로 이어 붙인다.
5. 붙여 준 파일에 없는 함수·클래스·API·기기 id·pip 패키지를 지어내지 말 것. 필요한 정보가 없으면 코드를 쓰기 전에 물어볼 것.
   핀 번호는 `booth_pins.py`에만 적고, 비밀 값은 `.env`에서 `os.getenv`로 읽을 것.
6. 마지막 파일을 준 뒤에는 **확인 방법**을 적어 줘:
   - PC나 파이에서 **가짜 핀(mock)으로** 실행하는 명령과 터미널에 무엇이 찍혀야 하는지
   - `python scripts/ai/check.py` 로 점검하라는 것
   - 실기기에서 확인하는 순서 (전원을 뽑고 배선 → 선생님 확인 → 자가진단 → `main.py`)
